# Coding Protocol

## コミットメッセージ

- コミットメッセージは日本語で記述する。
- ただし、先頭には英語の prefix を付ける。
- prefix は変更内容の種類が分かるものを選ぶ。

例:

```text
feat: ユーザー登録画面を追加
fix: ログイン失敗時のエラーメッセージを修正
docs: コーディング規約を更新
refactor: 認証処理の責務を整理
test: ユーザー登録のバリデーションテストを追加
chore: 開発用設定を更新
```

## ブランチ運用

- 基本的に `develop` ブランチから作業ごとにブランチを切る。
- 作業ブランチで実装・検証を行い、完了後に `develop` へマージする。
- `develop` にマージする前後で、`develop` が単体で機能することを確認する。
- `develop` が単体で動作しない状態になる変更は、原則としてマージしない。

## マージ方針

- PR は不要とする。
- PR の代わりに、マージ時のコミットメッセージへ実装内容を少し詳細に記述する。
- マージコミットでは、何を変更したか、なぜ変更したか、確認した内容を分かる範囲で残す。

例:

```text
feat: ユーザー登録機能をdevelopへ反映

ユーザー登録画面、入力バリデーション、登録API連携を追加。
メールアドレスの形式チェックとパスワード文字数チェックを実装し、
登録成功後はログイン画面へ遷移するようにした。

確認内容:
- ユーザー登録画面が表示されること
- 正常な入力で登録処理が完了すること
- 不正な入力でバリデーションエラーが表示されること
- developブランチ単体で起動できること
```
