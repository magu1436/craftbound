# 1. FoodProducerの目的

FoodProducerは、農耕、畜産・酪農および料理を通じて、ワールドにおける食料の生産、品質管理、保存、加工および供給を担うロールである。

本仕様では、用語を次のように区別する。

- **材料**：料理または保存食の材料として使用する品質対象アイテム
- **料理**：食材を加工して作成し、満腹度、隠し満腹度またはバフを持つ完成品
- **保存食**：長期保存と携帯を重視する完成食料
- **食料**：材料、料理および保存食の総称

FoodProducerの専門性は、他プレイヤーの基本行動を全面的に禁止することではなく、生産効率、収量、品質、保存性、専用レシピおよび専用設備の差によって表現する。

例外として、家畜の繁殖は牧畜ブロックの管理範囲内でのみ成立する。

# 2. 担当範囲

## 2.1 栽培対象

FoodProducerの農耕スキルが適用される植物は次とする。

- 小麦
- ニンジン
- ジャガイモ
- ビートルート
- カボチャ
- スイカ
- サトウキビ
- カカオ
- スイートベリー
- グロウベリー

対象植物について、FoodProducerは栽培、成長管理、収穫、再植え付け、増産、品質管理および備蓄を担当する。

ネザーウォートはFoodProducerの対象外とし、Alchemistが担当する。FoodProducerの成長時間、収量、品質および肥沃度補正は適用しない。

新規作物は、上記バニラ作物の実装とプレイテストが完了するまで追加しない。

## 2.2 飼育対象

FoodProducerの畜産・酪農スキルが適用される動物は次とする。

- ウシ
- ブタ
- ヒツジ
- ニワトリ
- ウサギ
- ムーシュルーム

対象動物について、FoodProducerは給餌、成長管理、繁殖、個体数管理、生産物の取得および食料生産を目的とした屠畜を担当する。

野生個体の発見、捕獲、誘導および運搬には専用補正を設定しない。

## 2.3 生産物

### 食料・材料

- 農作物
- 生の牛肉
- 生の豚肉
- 生の羊肉
- 生の鶏肉
- 生の兎肉
- 牛乳
- 卵
- キノコシチュー
- 料理および保存食に使用する中間素材

### 非食料素材

- 羊毛
- 革
- 羽根
- ウサギの皮
- ウサギの足

非食料素材は、FoodProducerが取得と一次保管までを担当し、その後の加工や利用を対応するロールへ移譲する。

## 2.4 他ロールとの依存関係

| 相手ロール | FoodProducerが必要とするもの | FoodProducerから渡すもの |
|---|---|---|
| Explorer | 初回の栽培素材、野生動物、拠点で継続生産できない食材、希少食材 | 探索用食料 |
| Adventurer | 農業用肥料の材料となる骨・骨粉 | 戦闘用食料 |
| Blacksmith | 鉄以上のクワ、範囲耕耘・植え付け・収穫・施肥に対応する農具。料理詳細確定後は調理道具 | 食料、革など |
| Architect | 品質劣化を抑える保存容器、品質別に管理できる専用保管庫 | 食料、羊毛など |
| Alchemist | 現時点で必須供給なし | ウサギの足、食料 |

牧畜ブロックはFoodProducer内で完結する設備とし、他ロールの専用部品や設備を要求しない。

## 2.5 共通スキルシステムとの境界

次はFoodProducer単独では決定せず、Pufferfish's Skillsを含むロール共通仕様から受け取る。

- FoodProducerロールの取得方法
- 最大レベル
- レベルごとの必要経験値
- スキルポイントの付与方法
- 各ノードの必要ポイント
- スキル振り直し
- 死亡時・ディメンション移動時・ワールド再参加時の維持
- 他ロールと成長資源を共有する方法

FoodProducer側では、1つの共通経験値、共通レベルおよび共通スキルポイントを、農耕・畜産・料理の3分岐に配分できる構造を要求する。

# 3. 品質システム

## 3.1 品質対象

品質を設定する対象は次とする。

- 料理に使用する材料
- 料理に使用する中間素材
- 直接食べられる食料
- 料理
- 保存食

道具、容器、燃料、肥料、堆肥、革、羊毛、羽根などの非食料アイテムには品質を設定しない。

品質を持つ材料が非食料アイテムのクラフトに使われる場合、そのクラフト結果には品質を継承せず、品質による性能差も発生させない。

ニンジンやジャガイモなど、食料と植え付け素材を兼ねるアイテムは品質を持つ。ただし、植え付け時には品質を参照せず、新しい作物へ品質を継承しない。

## 3.2 品質段階

| 内部値 | 表示名 | 利用 |
|---|---|---|
| 3 | 高品質 | 食用・加工・給餌可能 |
| 2 | 標準品質 | 食用・加工・給餌可能 |
| 1 | 低品質 | 食用・加工・給餌可能 |
| 0 | 腐敗 | 食用・加工・給餌不可。堆肥化のみ可能 |

入手時に「最低品質」とする場合は低品質を意味し、腐敗状態ではない。

腐敗は原則として時間経過によってのみ発生する。

## 3.3 入手時の初期品質

初期品質の判定優先順位は次とする。

1. アイテム種別による固定規則
2. プレイヤーが直接行った収穫・屠畜・採取の確率表
3. 自動処理または処理主体不明の場合のスキルなし確率表
4. 既存アイテムなど、取得経路を判定できない場合の標準品質

### 固定規則

| 対象 | 初期品質 |
|---|---|
| 卵、牛乳など、直接食べず主に材料として使う畜産物 | 高品質固定 |
| ムーシュルームから直接得るキノコシチューなど、そのまま食べられるMob由来食料 | 低品質固定 |
| チェスト報酬、クエスト報酬などの報酬品 | 低品質固定 |
| 品質対象だが取得経路を判定できない既存アイテム | 標準品質 |

卵や牛乳の「高品質固定」は入手時の初期品質を意味する。入手後は材料分類の品質維持時間に従って低下する。

チェスト報酬用のランダム品質表は将来追加候補とし、初期実装では低品質固定とする。

### 直接行動による判定

- 作物収穫は、収穫者の品質栽培ランクに対応する確率表を使用する。
- 屠畜で得る肉は、最終攻撃者の食肉処理ランクを品質判定ランクとして使用する。
- その他の採取物は、対応する品質スキルがある場合はそのランク、ない場合はスキルなし確率表を使用する。
- 自動収穫、自動屠畜、水流、ピストン、村人、Createなど、プレイヤーの直接行動でない処理はスキルなし確率表を使用する。

初期品質確率表は共通で次を使用する。

| 参照ランク | 高品質 | 標準品質 | 低品質 |
|---|---:|---:|---:|
| スキルなし | 5% | 35% | 60% |
| I | 10% | 40% | 50% |
| II | 15% | 45% | 40% |
| III | 25% | 50% | 25% |
| IV | 35% | 50% | 15% |
| V | 50% | 45% | 5% |

## 3.4 加工時の品質継承

品質を持つ完成品を作成する加工では、使用した品質対象材料のうち最も低い品質を基準完成品質とする。

```text
基準完成品質
=
品質を持つ使用材料の最低品質
```

容器、燃料、道具など、品質を持たない入力は判定に含めない。

腐敗した材料を1つでも含む場合は、加工または調理を開始できない。

完成品質を上昇させられるのは、次の条件をすべて満たす場合だけとする。

- プレイヤー本人が手動で処理する
- FoodProducerの対応する料理スキルを取得している
- Blacksmith製の対応調理道具または加工設備を使用する
- 品質上昇抽選に成功する

品質上昇は1回の処理につき最大1段階とし、使用材料の最高品質を超えない。

料理以外の具体的な加工方法、道具、確率およびレシピは料理仕様確定時に追加する。

## 3.5 品質による食事性能

品質は次に影響する。

- 満腹度
- 隠し満腹度（saturation）
- バフ持続時間

初期プレイテスト値は次とする。

| 品質 | 満腹度倍率 | 隠し満腹度倍率 | バフ時間倍率 |
|---|---:|---:|---:|
| 高品質 | 1.25倍 | 1.25倍 | 1.5倍 |
| 標準品質 | 1.0倍 | 1.0倍 | 1.0倍 |
| 低品質 | 0.75倍 | 0.75倍 | 0.67倍 |
| 腐敗 | 使用不可 | 使用不可 | 発動なし |

満腹度は計算後に整数へ丸め、食べられるアイテムは最低1を保証する。

隠し満腹度は、最終的な回復量が上表の倍率になるように計算し、満腹度倍率との重複適用で意図せず二重に増減させない。

Dietの栄養値へ品質倍率を適用するかは、料理仕様確定時に決定する。

## 3.6 品質低下データ

各スタックは少なくとも次を保持する。

- 現在品質
- 現在品質における基礎残り時間
- 最後に時間計算を行った時刻
- 最後に適用していた保存倍率

保存倍率を`M`、読み込み中に経過した実時間を`E`とした場合、基礎残り時間の消費量は`E ÷ M`とする。

```text
新しい基礎残り時間
=
変更前の基礎残り時間 - 経過実時間 ÷ 変更前の保存倍率
```

基礎残り時間が0以下になると品質を1段階低下させる。複数段階分の時間が経過している場合は順に反映する。

保存設備は品質を回復させず、基礎残り時間そのものを増加させない。保存倍率は消費速度だけを低下させる。

## 3.7 スタック統合

同一アイテムかつ同一品質のアイテムだけを通常スタックへ統合できる。

統合後の基礎残り時間には、統合前のうち短い方を採用する。

```text
標準品質・残り10分
＋
標準品質・残り30分
→
標準品質・残り10分
```

異なる品質、異なる効果情報または互換性のないデータを持つアイテムは統合しない。

## 3.8 品質維持時間

| 分類 | 高品質→標準品質 | 標準品質→低品質 | 低品質→腐敗 | 高品質→腐敗 |
|---|---:|---:|---:|---:|
| 料理 | 20分 | 20分 | 20分 | 60分 |
| 材料 | 120分 | 120分 | 120分 | 6時間 |
| 保存食 | 240分 | 240分 | 240分 | 12時間 |

卵、牛乳などの材料は材料分類を使用する。

時間は対象が読み込まれている間だけ進行する。

# 4. 保存設備

## 4.1 保存倍率

| 保存場所 | 保存倍率 |
|---|---:|
| プレイヤーのインベントリ | 1.0倍 |
| 通常チェスト・樽 | 1.0倍 |
| Architect製専用保管庫 | 2.0倍 |
| Architect製保存容器 | 3.0倍 |

通常チェストと樽には保存補正を与えない。

画面上の品質低下までの残り実時間は、現在の基礎残り時間に現在の保存倍率を乗算して表示する。

## 4.2 保存場所変更時の計算

保存場所を移動するときは、移動前の倍率で経過時間を先に精算し、その後に移動先の倍率を適用する。

```text
移動時の基礎残り時間
=
移動前の基礎残り時間 - 移動前の経過実時間 ÷ 移動前の保存倍率

移動後の表示残り実時間
=
移動時の基礎残り時間 × 移動先の保存倍率
```

例として、基礎残り時間10分の食料を通常容器で3分保存し、その後3倍の保存容器へ移す場合は次となる。

```text
10分 - 3分 ÷ 1.0 = 基礎残り7分
7分 × 3.0 = 表示残り21分
```

出し入れを繰り返しても倍率を累積させず、消費済み時間を回復させない。

## 4.3 専用保管庫

専用保管庫は単一ブロックとし、同一アイテムを品質別に内部管理する。

初期容量は次とする。

| 項目 | 初期値 |
|---|---:|
| 登録可能なアイテム種類 | 27種類 |
| 1種類あたりの最大数 | 品質合計256個 |
| 最大理論保管数 | 6,912個 |
| 初期取り出し順 | 品質低下までの残り時間が短い順 |

専用保管庫は次に対応する。

- 品質を指定した取り出し
- 古いものからの取り出し
- 品質別在庫表示
- 品質と残り時間を維持した搬入・搬出
- ホッパーおよびCreateからの一般的なアイテム搬入・搬出

初期実装ではCreate専用フィルターや装置別の個別連携を要求しない。一般的なアイテム入出力インターフェースを提供する。

## 4.4 時間経過

- 読み込み済みチャンク内の容器は品質時間を進行させる。
- 未読み込みチャンクでは停止し、再読み込み時に未読み込み期間を加算しない。
- サーバー停止中の実時間を加算しない。
- プレイヤーのインベントリはオンライン中のみ進行する。
- 地面に落ちたItem Entityでは品質時間を停止するが、バニラの5分消滅は通常どおり適用する。

通常コンテナの更新方式、更新周期および1tickあたりの処理上限はCodexが負荷を考慮して決定し、負荷試験後に調整する。v1.1の初期目安は約10秒周期、1tick最大32コンテナとする。

# 5. 農耕

## 5.1 基本ループ

```text
畑を用意する
→ 堆肥と農業用肥料を用意する
→ 肥沃度を回復する
→ 作物を植える
→ 成長を待つ
→ 収穫する
→ 保存・料理材料・餌・再植え付け・堆肥へ分配する
```

## 5.2 農具

FoodProducerは、低耐久の木製クワと石製クワを製作できる。

| クワ | 初期耐久値 | 範囲機能 |
|---|---:|---|
| 木製クワ | 30 | なし |
| 石製クワ | 65 | なし |

鉄以上のクワ、範囲形状、範囲サイズ、耐久、修理および強化はBlacksmith側で定義する。

Blacksmith製クワには次の機能を要求する。

- 範囲耕耘
- 範囲植え付け
- 範囲収穫
- 範囲施肥
- クワ側から作業範囲と形状を取得できること

## 5.3 肥沃度

耕地の最大肥沃度は100とする。

通常作物は植え付け時に肥沃度20を消費する。最大状態では5回植え付けられる。

肥培管理II取得者が植えた場合は消費量を16とする。

肥沃度が必要量未満の場合は植え付けできず、種または作物を消費しない。

収穫時には肥沃度を追加消費しない。

## 5.4 肥沃度の対象作物

肥沃度は、原則として耕地へ植える作物だけに適用する。

| 作物 | 肥沃度処理 |
|---|---|
| 小麦、ニンジン、ジャガイモ、ビートルート | 植え付け時に消費 |
| カボチャ、スイカ | 茎の植え付け時に消費。実の生成時は追加消費なし |
| サトウキビ、カカオ、スイートベリー、グロウベリー | 肥沃度対象外 |

肥沃度対象外の作物にも、生育管理、収量管理および品質栽培の補正は適用する。

## 5.5 堆肥

バニラのコンポスターを使用する。

- 通常の植物、作物および種子はバニラの投入成功率を維持する。
- 腐敗した材料、料理および保存食は投入成功率100%とする。
- コンポスター完成時は、骨粉ではなく堆肥1個を取得する。
- 自動投入・自動回収は許可するが、FoodProducer経験値とスキル補正を付与しない。

肥培管理IIIを持つプレイヤーが完成した堆肥を手動回収した場合、50%の確率で堆肥を1個追加する。

## 5.6 農業用肥料

初期レシピは次とする。

```text
骨粉 ×1
＋
堆肥 ×1
→
農業用肥料 ×1
```

農業用肥料1個の基礎回復量は40とする。肥培管理I取得者が使用した場合は50回復する。

最大肥沃度を超える回復分は切り捨てる。

肥沃度が最大の土壌には使用できず、肥料を消費しない。

骨粉を作物へ直接使用する即時成長効果は無効化する。

## 5.7 範囲施肥

範囲植え付け機能を持つBlacksmith製クワをオフハンドに持ち、メインハンドに農業用肥料を持って耕地を右クリックすると範囲施肥を行う。

- 範囲と形状は使用クワの範囲植え付けと同じとする。
- 右クリックした耕地を基準位置とする。
- 肥沃度が最大未満の耕地だけを対象とする。
- 対象1マスにつき農業用肥料1個を消費する。
- 所持数が不足する場合は、処理可能な数まで適用して終了する。
- 最大肥沃度の耕地や対象外ブロックには肥料を消費しない。
- 使用者の肥培管理ランクを各対象マスへ適用する。
- 処理順は中心から近い順とし、同距離の場合は常に同じ内部順序を使用する。
- クワの耐久消費は範囲植え付けと同じ規則を使用する。

## 5.8 植え付けと成長

植え付け時に次を行う。

1. 対象ブロックへ作物を植えられることを確認する。
2. 肥沃度対象作物の場合は必要肥沃度を確認して消費する。
3. 植え付けたプレイヤーの生育管理ランクを参照する。
4. 成熟までの時間を決定して作物へ保存する。

植え付け後にプレイヤーのスキルが変化しても、保存済み成長時間は変更しない。

初期成長時間は次とする。

| 分類 | 対象例 | 基礎時間 |
|---|---|---:|
| 短期作物 | スイートベリー、グロウベリー | 40分 |
| 標準作物 | 小麦、ニンジン、ジャガイモ、ビートルート、サトウキビ | 60分 |
| 長期作物 | カボチャ、スイカ、カカオ | 90分 |

| 生育管理 | 短縮率 |
|---|---:|
| I | 8% |
| II | 16% |
| III | 24% |
| IV | 32% |
| V | 40% |

スキルなし、自動植え付け、村人または装置による植え付けでは短縮を適用しない。

## 5.9 範囲植え付け

範囲植え付け機能を持つクワをオフハンドに持ち、メインハンドに植える種または作物を持った状態で植え付ける。

次を満たす位置だけを処理する。

- 対象作物を植えられる
- 既に作物が植えられていない
- 肥沃度対象の場合は必要量を持つ
- 必要な種または作物を所持している

対象ごとに通常の肥沃度消費と成長時間決定を行う。

## 5.10 収穫

成熟した担当作物をプレイヤーが収穫した場合、収穫者のスキルを参照する。

```text
通常の収穫
→ 道具などの収穫補正
→ 収量管理による追加抽選
→ 各収穫物の品質判定
```

収量管理の初期値は次とする。

| 収量管理 | 主要生産物を1個追加する確率 |
|---|---:|
| I | 10% |
| II | 20% |
| III | 30% |
| IV | 40% |
| V | 50% |

追加分に道具の補正を再適用しない。追加分にも通常の品質判定を行う。

範囲収穫は最終成長段階の作物だけを対象とする。

水流、ピストン、村人、Createなどによる収穫では追加収穫を行わず、スキルなし品質表を使用し、経験値を付与しない。

# 6. 畜産・酪農

## 6.1 基本ループ

```text
飼育場所を用意する
→ 牧畜ブロックを設置する
→ 対象動物を設定する
→ 餌を補充する
→ 家畜を管理する
→ プレイヤーが手動繁殖する
→ 個体数を管理する
→ 生産物を取得する
```

## 6.2 牧畜管理スキルとレシピ解放

畜産・酪農分岐の最初に`牧畜管理`を置く。

牧畜管理を取得すると牧畜ブロックのクラフトレシピを解放する。解放後は材料がある限り個数制限なくクラフトできる。

完成した牧畜ブロックは譲渡でき、スキルを持たないプレイヤーも設置・利用できる。

牧畜ブロックの初期レシピは次とする。

```text
木材 ×4
鉄インゴット ×2
チェスト ×1
干草の俵 ×1
レッドストーン ×1
→ 牧畜ブロック ×1
```

初期実装では9素材の不定形レシピとする。材料と入手難度はプレイテスト後に調整できる。

## 6.3 共有運用

牧畜ブロックには所有者を設定しない。

すべてのプレイヤーに次を許可する。

- UIを開く
- 対象動物を設定・変更する
- 餌を搬入・搬出する
- 状態を確認する
- 管理範囲内で手動繁殖する
- ブロックを破壊・回収する

飼料管理ランクおよび飼育容量ランクの性能更新は、牧畜管理を取得したプレイヤーだけが実行できる。

専用の保護、所有権またはアクセス権は設けない。

## 6.4 管理範囲

水平方向は1チャンク相当の16×16ブロック、高さ方向は33ブロックとする。

偶数幅のため牧畜ブロックを完全な中央には配置できない。範囲は設置座標を基準に固定し、次とする。

- X方向：設置座標から`-7～+8`
- Z方向：設置座標から`-7～+8`
- Y方向：設置座標から`-16～+16`

境界を含む`16×16×33`ブロックを管理する。

同じ動物が複数の牧畜ブロックの条件を満たす場合、動物から最も近い1個だけが管理する。同距離の場合は、Codexが常に一意に決まる内部順序を使用する。

## 6.5 対象動物の設定

1個の牧畜ブロックは1種類の動物だけを管理する。

設置直後は未設定とする。UIから次のいずれかを選択する。

- ウシ
- ブタ
- ヒツジ
- ニワトリ
- ウサギ
- ムーシュルーム

対象変更規則は次とする。

- 誰でも変更できる。
- 変更にアイテム、経験値または通貨を消費しない。
- 餌スロットにアイテムが入っている間は変更できない。
- 未設定へ戻せる。
- 変更前の動物にはダメージ、消滅または移動を発生させない。
- 変更後は旧対象への管理効果を停止し、新対象へ適用する。
- 未設定中は餌消費、給餌、成長管理および繁殖判定を行わない。

## 6.6 餌スロット

餌スロットは1枠、最大64個とする。同時に1種類のアイテムだけを保持する。

| 対象動物 | 使用可能な餌 |
|---|---|
| ウシ、ヒツジ、ムーシュルーム | 小麦 |
| ブタ | ニンジン、ジャガイモ、ビートルート |
| ニワトリ | バニラで繁殖に使える種 |
| ウサギ | ニンジン、金のニンジン、タンポポ |

設定中の動物に使用できないアイテムは搬入できない。

手動操作に加え、ホッパーとCreateによる一般的な搬入・搬出を許可する。接続面などの技術詳細はCodexへ任せる。

## 6.7 給餌・容量・成長

牧畜ブロック1個の基礎管理可能数は8体とする。成体と子どもの両方を数える。

| 飼育容量 | 管理可能数 |
|---|---:|
| スキルなし | 8体 |
| I | 12体 |
| II | 16体 |
| III | 20体 |

餌消費の初期値は次とする。

- 成体：20分ごとに1個
- 子ども：10分ごとに1個

| 飼料管理 | 餌を消費しない確率 |
|---|---:|
| スキルなし | 0% |
| I | 10% |
| II | 20% |
| III | 30% |

判定は動物ごとに行う。

子どもの基礎成長時間は60分とし、必要な餌を受け取れている間だけ進行する。

餌不足または容量超過で動物を死亡・消滅させない。

管理可能数を超えた動物には次を適用する。

- 牧畜ブロックから給餌しない
- 子どもの成長を停止する
- 繁殖対象にしない
- 牧畜ブロックに依存する継続生産を停止する

容量内へ戻った場合は通常処理を再開する。

## 6.8 手動繁殖

繁殖は自動化しない。プレイヤーが対応する餌を成体へ直接与える。

繁殖を成立させる条件は次とする。

- 同種の繁殖可能な成体が2体以上いる
- 繁殖クールダウン中ではない
- 2体が同じ牧畜ブロックに管理されている
- 子ども1体を追加しても管理可能数を超えない

管理可能数に空きがない場合は繁殖状態へ移行せず、餌を消費しない。

通常個体を1体生成した後、繁殖を成立させたプレイヤーの繁殖管理ランクで追加個体抽選を1回行う。

| 繁殖管理 | 追加個体率 |
|---|---:|
| スキルなし | 0% |
| I | 10% |
| II | 20% |
| III | 30% |
| IV | 40% |
| V | 50% |

追加個体で容量を超える場合は生成しない。

複数プレイヤーが関与した場合は、繁殖を成立させる最後の餌を与えたプレイヤーのランクを参照する。

繁殖クールダウンは20分とする。

牧畜ブロックの管理範囲外では繁殖状態へ移行せず、餌を消費しない。

## 6.9 屠畜

FoodProducerが成体の対象動物の最終攻撃者となった場合、食料だけに追加ドロップ抽選を行う。

| 食肉処理 | 対象肉を1個追加する確率 |
|---|---:|
| I | 20% |
| II | 40% |
| III | 60% |
| IV | 80% |
| V | 100% |

処理順は次とする。

```text
通常ドロップ
→ ドロップ増加などの処理
→ FoodProducer追加食料抽選
→ 肉の品質判定
```

追加分へドロップ増加を再適用しない。

革、羊毛、羽根、ウサギの皮およびウサギの足には追加抽選を適用しない。

プレイヤーが放った矢など、攻撃元を特定できる間接攻撃はそのプレイヤーを最終攻撃者として扱う。

自動屠畜では追加食料抽選を行わず、肉の品質はスキルなし表を使用する。

## 6.10 その他の畜産物

牛乳、卵、羊毛、キノコシチューなどの取得方法と数量はバニラを維持する。

- 卵と牛乳は入手時に高品質とし、材料分類の品質時間を使用する。
- キノコシチューは入手時に低品質とし、料理分類の品質時間を使用する。
- 羊毛などの非食料素材には品質を設定しない。
- 初期版では生産間隔や数量へのスキル補正を追加しない。

## 6.11 設置・性能更新・破壊

設置時に、設置者の飼料管理ランクと飼育容量ランクを牧畜ブロックへ記録する。スキルなしプレイヤーが設置した場合は両方を0として記録する。

牧畜管理取得者が性能更新を行った場合は、現在値と更新者のランクの高い方を保存する。

```text
更新後ランク
=
max（保存中ランク, 更新者ランク）
```

低いランクで上書きしない。

破壊時は次とする。

- 牧畜ブロック本体をドロップする。
- 内部の餌をすべてドロップする。
- 対象動物設定を失う。
- 保存中のスキルランクを失う。
- 動物自体には影響しない。
- 再設置時に設置者の現在ランクを新規記録する。

## 6.12 牧畜ブロックと経験値

牧畜ブロックによる自動処理からFoodProducer経験値を一切発生させない。

経験値を発生させない処理には次を含む。

- ブロックのクラフト、設置、破壊
- 対象動物や設定の変更
- 餌の自動消費
- 飼料管理による消費軽減
- 管理数の監視
- 子どもの成長
- ホッパーやCreateによる搬入・搬出
- 時間経過による管理処理

プレイヤーが動物へ直接餌を与えて繁殖を成立させた行為と、プレイヤー自身による屠畜は、牧畜ブロックの自動処理ではないため経験値対象とする。

# 7. スキルツリー

FoodProducerツリーは1つのタブ内で3方向へ分岐する。

```text
                    農耕
                     ↑
                     │
畜産・酪農 ← FoodProducer基点 → 料理
```

## 7.1 農耕分岐

```text
農地診断
├─ 生育管理 I～V
│  ├─ 収量管理 I～V
│  └─ 品質栽培 I～V
└─ 肥培管理 I～III
```

### 農地診断

次を確認できる。

- 現在肥沃度
- 最大肥沃度
- 植え付け可否
- 作物の成長状態
- 成熟までの残り時間

### 生育管理 I～V

植え付け時に確定する成長時間を短縮する。

### 収量管理 I～V

成熟作物を収穫した際の主要生産物追加率を上げる。

### 品質栽培 I～V

収穫時の品質確率を改善する。

### 肥培管理 I～III

| ランク | 効果 |
|---|---|
| I | 農業用肥料の回復量を40から50へ増加 |
| II | 植え付け時の肥沃度消費を20から16へ減少 |
| III | 完成した堆肥の手動回収時、50%の確率で1個追加 |

## 7.2 畜産・酪農分岐

```text
牧畜管理
├─ 飼料管理 I～III
│  └─ 飼育容量 I～III
├─ 繁殖管理 I～V
└─ 食肉処理 I～V
```

### 牧畜管理

牧畜ブロックのレシピを解放し、性能更新を可能にする。

### 飼料管理 I～III

牧畜ブロックの餌を消費しない確率を上げる。

### 飼育容量 I～III

牧畜ブロックの管理可能数を増やす。

### 繁殖管理 I～V

手動繁殖成立時の追加個体率を上げる。

### 食肉処理 I～V

屠畜時の追加食料率を上げ、肉の品質判定ランクとしても使用する。

## 7.3 料理分岐

料理分岐の詳細、レシピ、中間素材、道具、加工設備、効果およびDiet栄養値は最終版直前に決定する。

現時点で固定する共通条件は次だけとする。

- 完成品の基準品質は、品質を持つ材料の最低品質とする。
- 品質上昇は1回につき最大1段階とする。
- 使用材料の最高品質を超えない。
- 腐敗材料を含む場合は開始できない。
- 品質上昇は、料理スキルを持つFoodProducerがBlacksmith製道具で手動調理した場合だけ発生する。
- FoodProducerが作成した料理でも、消費者のロールは制限しない。

# 8. 経験値

FoodProducerは共通経験値を使用する。

料理以外の初期経験値は次とする。

| 行動 | 経験値 |
|---|---:|
| 成熟作物を1株手動収穫 | 1 |
| 農業用肥料で耕地1マスを実際に回復 | 2 |
| 完成した堆肥を1個手動回収 | 1 |
| 家畜へ直接餌を与えて繁殖成立 | 5 |
| 対象動物をプレイヤーが屠畜 | 2 |
| 牛乳、採卵、羊毛取得 | 0 |
| 牧畜ブロックに関する処理 | 0 |

範囲施肥は、実際に回復して肥料を消費した耕地ごとに経験値を付与する。最大肥沃度、対象外ブロックまたは肥料不足で処理しなかった位置には付与しない。

自動処理、村人、水流、ピストン、ホッパー、Createおよび処理主体を特定できない作業には経験値を付与しない。

料理・加工の経験値は料理仕様確定時に追加する。

---

# 9. 自動化とCreate

自動化自体は原則として禁止しない。

Createは、バニラで生産可能なアイテムや食料の大量・自動生産を担当する。Createの出力を強制的に低品質へ固定するのではなく、FoodProducerスキルなしの処理として扱う。

自動処理には次を適用しない。

- FoodProducerの成長時間短縮
- 追加収穫
- スキル品質表
- 屠畜時の追加食料
- 料理品質上昇
- 加工時間短縮
- 中間素材出力量増加
- FoodProducer経験値

FoodProducerスキルで解放する追加レシピはCreateで自動化できない。

Create、ホッパーなどがFoodProducer関連設備へ接続する場合は、品質、基礎残り時間および効果情報を失わずに搬入・搬出する。

装置別の接続面、フィルター、ベルト、ファンネル、シュートなどの詳細は、必要になった時点で技術実装側が決定する。

# 11. 実装条件と設定方針

## 11.1 開発環境

| 項目 | 内容 |
|---|---|
| Minecraft | 1.20.1 |
| Modローダー | Minecraft Forge |
| Java | 64ビット版JDK 17 |
| マッピング | Mojang公式マッピング（official） |

実装順序、Javaクラス構成、保存データ方式、イベントの選択、同期方式およびテスト単位はCodexへ任せる。ただし、本仕様のゲーム上の結果を変更してはならない。

## 11.2 Diet連携

Dietは任意依存とする。Dietが未導入でもFoodProducer機能とMOD本体が起動できるようにする。

Diet連携が有効になる条件は次の両方を満たす場合とする。

- Dietが導入されている
- サーバー設定でDiet連携が有効になっている

Diet連携の有効・無効切り替えだけは、最小構成での外部設定禁止の例外とする。

Dietが無効な場合でも、品質、満腹度、隠し満腹度、バフ、農耕、保存および畜産は動作する。

栄養カテゴリ、栄養値および品質との関係は料理仕様確定時に追加する。

## 11.3 データ化

次は調整可能なデータとして、Javaコードへ過度に固定しないことを推奨する。

- 品質確率表
- 成長時間
- 肥沃度消費・回復量
- 収量率
- 牧畜容量
- 餌消費間隔
- 追加個体率
- 品質維持時間
- 保存倍率
- 経験値
- レシピ

具体的にJSON、データパック、Forge ConfigまたはJava定数のどれを使用するかはCodexが実装規模に応じて決定する。

## 11.4 初期テスト方針

- 最初にソロプレイで各ゲームループを確認する。
- バニラ作物を先に実装し、新規作物は後回しにする。
- 料理の詳細実装は本書の未確定章を完成させた後に行う。
- マルチプレイ固有の同期、同時操作、権限競合および負荷は最終テスト段階で確認する。
- 数値は本書の初期値で実装し、プレイテスト後に調整する。
