# 鉄のピッケル試作仕様

## 1. 本書の目的

本書は、鍛冶システムで最初に実装する縦方向の試作として、バニラの鉄のピッケルを製作するための具体仕様を定義する。

共通ルールは[鍛冶師システム仕様](./blacksmith.md)、素材初期値は[鍛冶素材仕様](./materials.md)、JSONの配置と評価関数の境界は[鍛冶システムJSON・評価関数仕様](./data-formats.md)、画面操作は[鍛冶システムUI仕様](./ui.md)、検証項目は[鍛冶システムテスト仕様](./test-cases.md)に従う。

本書の数値は初期実装値であり、プレイテスト後はJSONを変更して調整する。コード変更を必要とする数値調整は行わない。

---

## 2. 完成までの流れ

```text
鉄インゴット3個
    ↓
るつぼで加熱
    ↓
ピッケルヘッド用鋳型へ鋳造
    ↓
冷却
    ↓
鍛造
    ↓
品質付き鉄製ピッケルヘッド

任意のバニラ板材1個
    ↓
細工ナイフで細工台からパーツを選択して非金属加工
    ↓
品質付きピッケルの柄

鉄製ピッケルヘッド + ピッケルの柄
    ↓
バニラの作業台で組み立て
    ↓
品質付き鉄のピッケル
```

---

## 3. パーツと材料

鉄のピッケルは、以下の2パーツから構成する。

- 鉄製ピッケルヘッド
- ピッケルの柄

鉄製ピッケルヘッド1個には、鉄インゴット3個を使用する。鉄の原石と鉄鉱石は直接投入できず、鉄インゴットへ加工してからるつぼへ投入する。

るつぼには鉄インゴットと鉄の金属塊を合計16個分まで投入できる。ピッケルヘッドの鋳造では3個分だけを消費し、余った鉄は同じ加熱経過時間を保持してるつぼへ残す。

ピッケルの柄1個には、任意のバニラ板材1個を使用する。MVPでは木材の種類による性能差を設けず、非金属加工で得た柄の品質だけを評価する。パーツ種別IDは素材に依存しない `pickaxe_handle` とする。

ピッケルヘッド用鋳型は、レンガ5個と鉄塊3個から空鋳型を作り、空鋳型を石切台で加工して入手する。完成したピッケルヘッド用鋳型は繰り返し使用でき、別の鋳型へ再変換できない。

## 4. 鉄の加熱

### 4.1 加熱条件

鉄の加熱条件は以下のとおり。

| 経過時間 | 状態と結果 |
|---:|---|
| 0秒以上10秒未満 | 鋳造不能。流し込むと一部を失って金属塊になる |
| 10秒以上15秒未満 | 鋳造可能。適正時間との差に応じて品質が低下する |
| 15秒以上18秒以下 | 適正時間。加熱評価 `100` を得る |
| 18秒超24秒未満 | 鋳造可能。適正時間との差に応じて品質が低下する |
| 24秒以上28秒未満 | 鋳造可能だが品質が低下する。全消失が近いため警告を表示する |
| 28秒以上 | 回収不能な廃棄物となり、鉄は全消失する |

秒数、適正帯、残り時間はプレイヤーへ数値で表示しない。24秒以上では、色、音、パーティクルなど、低コストで実現できる方法によって危険を通知する。

るつぼを溶鉱炉から取り出した時点で加熱経過時間を固定する。所持中とインベントリ内では加熱も冷却も進行させず、溶鉱炉へ戻した場合は固定した時間から加熱を再開する。鋳型へ流し込んだ時点で加熱評価を確定する。

### 4.2 加熱評価

加熱評価は、JSONに定義した経過時間と評価値の組を線形補間して求める。

| 経過時間 | 加熱評価 |
|---:|---:|
| 10秒 | 40 |
| 15秒 | 100 |
| 18秒 | 100 |
| 24秒 | 40 |
| 28秒 | 0 |

10秒未満ではパーツを生成しないため、加熱評価を使用しない。28秒以上では全消失を先に判定し、評価 `0` のパーツは生成しない。

鋳造が早すぎた場合、鉄インゴット3個分のうち `ceil(3 / 2) = 2` 個分を失い、残り1個分を「鉄の金属塊・小」1個として回収する。金属塊・小はインゴット1個分に相当する。

加熱評価は独立した加熱評価関数で計算する。溶鉱炉、るつぼ、鋳造台は補間式を直接実装せず、加熱経過時間と金属JSONを評価関数へ渡す。

## 5. 鋳造と冷却

鉄をピッケルヘッド用鋳型へ流し込み、鍛造前の粗加工パーツを生成する。鉄製ピッケルヘッドの表面凝固時間は2秒（40ゲームティック）、安全冷却時間は5秒（100ゲームティック）とする。

鋳造時に以下を検証する。

- るつぼの内容が鉄であること
- 鉄インゴット3個分の量があること
- 10秒以上加熱されていること
- 28秒未満であること
- ピッケルヘッド用鋳型が設置されていること

冷却時間は、溶解した鉄を鋳型へ流し込んだ時点から、粗加工パーツを鋳型から取り出すまで計測する。安全冷却時間へ達する前でも取り出して鍛造台へ移動できる。

鋳型から取り出した時点で冷却時間と破損回数上限を固定する。インベントリ、鍛造台、鍛造ミニゲーム中は冷却を進行させない。時間を置いてから鍛造しても、取り出し時に確定した破損回数上限は変化しない。

冷却時間そのものは品質へ影響させない。5秒を超えて冷却しても、品質や破損回数上限へ追加効果を与えない。

鋳造直後から2秒までは蒸気パーティクルを多く表示する。2秒へ達した時点で一度だけ蒸気音を再生し、それ以降は蒸気パーティクルを減らす。安全冷却時間の5秒へ達した時点では、音、通知、専用エフェクトを発生させない。

### 5.1 冷却による破損回数上限

鋳型から粗加工パーツを取り出した時点で、鋳型内の冷却時間から有効な破損回数上限を計算する。

```text
冷却率 = clamp(取り出し時の冷却ティック / 100, 0, 1)
有効破損回数 = max(1, floor(10 × 冷却率))
```

代表的な値は以下のとおり。

| 冷却時間 | 有効破損回数 |
|---:|---:|
| 0秒 | 1回目 |
| 1秒 | 2回目 |
| 2秒 | 4回目 |
| 3秒 | 6回目 |
| 4秒 | 8回目 |
| 5秒以上 | 10回目 |

打撃後の累計打撃回数が、取り出し時に確定した有効破損回数以上になった場合は、粗加工パーツを金属塊へ変化させる。鍛造中に上限を再計算しない。

有効破損回数の計算は、独立した冷却破損上限関数で行う。鋳造台は取り出し時にこの関数を呼び出し、結果を粗加工パーツへ保存する。鍛造台とGUIは計算式を直接実装しない。

## 6. 鉄製ピッケルヘッドの鍛造

### 6.1 鍛造条件

打撃強度ゲージの範囲は `0` から `100` とする。

ゲージは `0 → 100 → 0` の三角波で移動し、1往復を3秒（60ゲームティック）、片道を1.5秒とする。開始時は `0` から上昇し、プレイヤーは左クリックで打撃する。ゲージの内部値は連続値とし、表示目盛りへ丸めずに打撃強度として記録する。

目盛り間隔は精密目盛の取得段階に応じて以下のとおりとする。

| 取得状態 | 目盛り間隔 |
|---|---:|
| 精密目盛未取得 | 25 |
| 精密目盛I | 20 |
| 精密目盛II | 10 |
| 精密目盛III | 5 |
| 精密目盛IV | 2 |

目盛りは表示上の補助であり、ゲージ速度、適正強度、採点式を変更しない。

- 適正強度: `55` から `65`
- 適正打撃回数: 6回
- 安全冷却後に破損する打撃回数: 10回目

安全冷却後は、10回目の打撃を行った時点で鍛造失敗とし、完成操作を待たずに粗加工パーツを金属塊へ変化させる。冷却不足の場合は、冷却破損上限関数が返した、より低い回数で破損する。適正強度、適正回数、破損回数はプレイヤーへ数値で表示しない。

鍛造によって金属塊化した場合も同じ損失規則を適用し、鉄インゴット3個分のうち2個分を失って、1個分を「鉄の金属塊・小」1個として回収する。

### 6.2 打撃強度評価

各打撃について、適正範囲からの距離を求める。適正範囲内の距離は `0` とする。

```text
1打の評価 = clamp(100 - 適正範囲からの距離 × 5, 0, 100)
強度評価 = 全打撃評価の算術平均
```

打撃を一度も行わずに完成した場合、強度評価は `0` とする。

### 6.3 打撃回数評価

```text
回数評価 = clamp(100 - abs(実打撃回数 - 6) × 20, 0, 100)
```

### 6.4 鍛造評価

```text
鍛造評価 = round(強度評価 × 0.8 + 回数評価 × 0.2)
```

10回目の打撃によって破損した場合は、鍛造評価を計算しない。

打撃強度評価、打撃回数評価、鍛造評価は、独立した鍛造評価関数で計算する。鍛造台とGUIは計算式を直接実装せず、打撃履歴と金属パーツJSONを評価関数へ渡す。

## 7. 金属パーツ品質

鉄製ピッケルヘッドの品質は、加熱評価と鍛造評価から計算する。

```text
金属パーツ品質 = round(加熱評価 × 0.4 + 鍛造評価 × 0.6)
```

結果は `0` から `100` の範囲へ収める。

金属パーツ品質は、加熱評価関数や鍛造評価関数とは別の金属パーツ品質関数で計算する。重みを変更しても、加熱、鋳造、鍛造の処理を変更する必要がない構造とする。

## 8. ピッケルの柄

### 8.1 材料と加工道具

ピッケルの柄には、任意のバニラ板材1個を使用する。入力判定には個別アイテムIDではなく、バニラ板材を表すアイテムタグを使用する。

加工特性は木材プロファイル `craftbound:wood` を参照し、細工ナイフ、1通過あたり除去量 `0.5`、耐久1消費あたり累積除去量 `8` を使用する。

理想形状は木材用の形状として定義せず、パーツ種別 `pickaxe_handle` の形状として定義する。将来、骨や他の非金属素材からピッケルの柄を加工できるようにする場合も、同じ理想形状を参照する。

加工には `craftbound:carving_knife`（細工ナイフ）を使用する。最大耐久値は `128` とする。セル残存量を合計8セル相当削るごとに耐久値を1消費し、8セル未満の累積除去量は細工台へ保存する。

### 8.2 グリッド解像度

基本のグリッド解像度は `16×16` とする。スキルによって、以下の解像度を順次利用可能にする。

- 精密成形未取得: `16×16`
- 精密成形I: `24×24`
- 精密成形II: `32×32`

現時点でゲーム内の最大解像度は `32×32` とする。`pickaxe_handle` の理想形状は、この最大解像度で定義する。将来、ゲーム内の最大解像度を変更した場合は、理想形状の基準解像度も同じ値へ変更する。

削る範囲は円形ブラシとし、精密成形の取得段階ごとの半径は以下のとおりとする。

| 取得状態 | グリッド解像度 | ブラシ半径 |
|---|---:|---:|
| 精密成形未取得 | `16×16` | 1.5セル |
| 精密成形I | `24×24` | 1.0セル |
| 精密成形II | `32×32` | 0.5セル |

半径0.5セルは単一セル相当の操作とする。木材は1回の通過で対象セルの残存量を `0.5` 減らし、同じ位置を2回通過すると完全に削れる。ドラッグ経路は通過セル単位で補間し、描画フレーム数やカーソル速度によって削り跡や除去量が変化しないようにする。

ドラッグ経路はsupercover line方式で補間し、連続する通信区間の端点セルを重複処理しない。半径0.5セルではカーソルを含むセルだけを削り、それ以上の半径ではセル中心との距離で対象を決める。

`16×16` または `24×24` で加工した結果は、正規化領域の重なり面積による加重平均で `32×32` へ展開し、`32×32` の理想形状と比較する。`pickaxe_handle` の理想形状は、下位解像度へ変換してから `32×32` へ戻した場合に元の形状と一致しないように設計する。これにより、下位解像度では必ず離散化による誤差が残る。

`pickaxe_handle` の理想形状は、`32×32` のグリッド内で以下の制約を満たすように定義する。

- 全高は26～28セル
- 上端のヘッド接続部は幅約8セル
- 中央の軸は幅4～5セル
- 下端の握り部は幅6～7セル
- 輪郭に1セル単位のテーパーまたは段差を含める

具体的な32行のバイナリマスクは、[理想形状定義](./data-formats.md#7-理想形状定義)に示すJSONを初期値とする。1セル単位の輪郭差を持つため、下位解像度では完全再現できない。

### 8.3 形状評価

ピッケルの柄の品質には、加工結果と `pickaxe_handle` の理想形状のIoUを使用する。

```text
共通領域 = Σ min(加工結果のセル残存量, 理想形状のセル残存量)
合計領域 = Σ max(加工結果のセル残存量, 理想形状のセル残存量)
形状評価 = round(共通領域 / 合計領域 × 100)
```

結果は `0` から `100` の範囲へ収める。合計領域が `0` の場合は形状評価を `0` とする。

理想形状として残すべき領域の50%以上を削り落とした場合は、完成操作を待たずに素材を消失させる。

理想形状として残すべき領域の残存率が60%以下になった場合は、警告音とGUI枠の色変化を発生させる。専用の亀裂表示は、共通オーバーレイだけで実装できる場合に限ってMVPへ含める。

形状評価は独立した非金属形状評価関数で計算する。細工台とGUIはIoUを直接計算せず、加工グリッドと非金属パーツJSONを評価関数へ渡す。

ピッケルの柄の品質には形状評価をそのまま使用する。

## 9. 組み立てと完成品品質

鉄製ピッケルヘッドとピッケルの柄を、バニラの作業台で独自レシピタイプ `craftbound:quality_assembly` の固定レシピに従って組み立てる。

```text
鉄のピッケル品質 = round((鉄製ピッケルヘッド品質 + ピッケルの柄品質) / 2)
```

完成品品質の計算には共通の完成品品質関数を使用する。鉄のピッケル用レシピ内で平均を直接計算しない。

採掘速度と最大耐久値には、共通仕様で定義した品質補正を適用する。

## 10. 中断と再開

溶鉱炉にはGUIを設けない。るつぼが挿入され、真下に有効な熱源が存在し、対象チャンクがロードされている間は、プレイヤーがその場を離れても加熱を継続する。チャンクアンロード中とサーバー停止中は進行しない。

るつぼを取り出した場合は加熱経過時間を保存して停止し、溶鉱炉へ戻した場合だけ再開する。

鍛造GUIを閉じた場合は、打撃履歴、ゲージ位置、ゲージの移動方向を保存して一時停止する。再度開いた場合は同じ状態から再開する。

非金属加工GUIを閉じた場合は、加工グリッド、選択した `pickaxe_handle`、投入した板材を保存して一時停止する。再度開いた場合は同じ状態から再開する。

細工ナイフが壊れた場合も加工を一時停止し、新しい細工ナイフで同じ細工台から再開する。GUI closeは一時停止のみとし、空手取り出し・細工台破壊では現在gridを品質評価して完成品を確定する。

各工程の開始時に、使用する評価関数IDと加熱、冷却、鍛造、非金属加工の各設定値を加工状態へ保存する。データパック再読み込み後も進行中の加工には保存済みの値を使い、新しい値へ途中変更しない。

完成品またはパーツの品質は、プレイヤーが完成ボタンを押した場合だけ確定する。

## 11. 受け入れ条件

- 鉄インゴット3個をるつぼへ投入できる
- るつぼが鉄を16個分まで保持し、3個分の鋳造後も余剰分を保持できる
- るつぼを取り出すと加熱が停止し、再投入すると保存した時間から再開する
- 加熱時間によって、金属塊、品質付き粗加工パーツ、全消失の結果へ分岐する
- 加熱評価をJSONの評価点から線形補間できる
- 打撃強度と打撃回数から鍛造評価を計算できる
- 10回目の打撃で金属塊へ変化する
- 金属塊化した場合に鉄2個分を失い、インゴット1個分の「鉄の金属塊・小」を1個回収できる
- 加熱評価40%、鍛造評価60%で鉄製ピッケルヘッド品質を計算できる
- 5秒未満で鋳型から取り出した場合に、冷却時間に応じて破損回数上限が低下する
- 5秒以上冷却した場合に、10回目の打撃で破損する
- 5秒を超える冷却による追加効果がない
- 2秒で蒸気音と蒸気量が変化し、5秒では安全冷却完了を示す通知が発生しない
- 鋳型から取り出した後は、時間が経過しても破損回数上限が変化しない
- 任意のバニラ板材1個から `pickaxe_handle` を加工できる
- 精密成形によって `16×16`、`24×24`、`32×32` のグリッドを利用できる
- 精密成形の取得段階によって円形ブラシの半径が1.5、1.0、0.5セルへ変化する
- ドラッグ経路がセル単位で補間され、カーソル速度や描画フレーム数で結果が変化しない
- 細工ナイフが8セル相当の除去ごとに耐久値を1消費する
- 理想形状がゲーム内の最大解像度 `32×32` で定義される
- `pickaxe_handle` の32行の実マスクをJSONから読み込める
- 下位解像度では理想形状を完全再現できない
- IoUによってピッケルの柄の品質を計算できる
- 理想形状を50%以上削り落とした場合に素材が消失する
- 細工ナイフの破損やGUI close後に細工台の加工途中状態から再開でき、取り出し・作業台破壊では完成品が確定する
- 2パーツの品質平均から鉄のピッケル品質を計算できる
- `craftbound:quality_assembly` レシピから品質付き鉄のピッケルを生成できる
- 同じプレイヤーが全工程を担当した場合、鋳造3、鍛造6、柄加工3、組み立て2の合計14鍛冶経験値を得る
- すべての評価を独立した評価関数経由で計算できる
