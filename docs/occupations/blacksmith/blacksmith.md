# 鍛冶師システム仕様

## 1. 本書の目的

本書は、Craftboundにおける鍛冶師関連システムのゲーム仕様と実装方針を定義する。

鍛冶師関連の実装では、本書を判断基準として使用する。`docs/overview.md` と記述が競合する場合は、鍛冶師システムについては本書を優先する。

本書では、調整によって変更する数値と、変更してはならないシステム上の責務を分けて扱う。適正時間、品質補正値、ミニゲームの判定値などはデータとして調整可能にし、コードへ直接埋め込まない。

個別仕様とデータ形式は、以下の文書で定義する。

- [鉄のピッケル試作仕様](./iron-pickaxe.md)
- [鍛冶システムJSON・評価関数仕様](./data-formats.md)

---

## 2. 鍛冶師の役割

鍛冶師は、入手済みの素材を加工し、武器、防具、ツールを製作する生産職である。

担当する工程は以下のとおり。

- 金属の溶解、鋳造、鍛造
- 木材、布、宝石などの非金属素材の加工
- 加工済みパーツを使用した完成品の組み立て
- 装備、武器、ピッケル、斧、クワなどの製作

鉱石、木材、ボス素材などの採集は鍛冶師の役割に含めない。素材は主に冒険家、探検家、その他の採集担当から供給される。

独自の修理システムと、製作後の独自強化システムはMVPに含めない。バニラの金床やクラフトによる修理と、既存のエンチャントシステムは利用可能なまま残す。

## 3. 設計方針

### 3.1 手作業による高品質化

通常のクラフトレシピは削除しない。ただし、通常レシピから作られた対象アイテムは固定の低品質品とする。

高品質品を作るには、金属加工または非金属加工によってパーツを製作し、定義済みのレシピで組み立てる必要がある。

### 3.2 固定された完成品とレシピ

初期実装では、素材とパーツを自由に組み合わせて新しい装備を生成する方式を採用しない。

完成品、必要なパーツ、使用可能な素材はレシピごとに定義する。組み立てにはバニラの作業台を使用し、専用の組立作業台は追加しない。

### 3.3 発見を重視したミニゲーム

適正加熱時間、適切な打撃強度、適切な打撃回数、非金属パーツの理想形状などの正解値はプレイヤーへ直接公開しない。プレイヤー同士の試行錯誤と情報交換によって、より良い加工方法が開拓されることを狙う。

ただし、素材の全消失や再加工が必要になる状態が近い場合は、視覚、音、エフェクト、GUI表示などによる警告を必須とする。正解値そのものを示さず、危険が近いことだけを伝える。

### 3.4 サーバー側を正とする

加工状態、素材消費、ミニゲーム結果、品質計算、完成品の生成はサーバー側で検証、確定する。クライアントから送信された操作結果を、そのまま完成結果として信用しない。

## 4. MVPの範囲

### 4.1 含めるもの

- るつぼ
- 溶鉱炉
- 鋳型と鋳造用作業台
- 鍛造台
- ハンマー
- 鍛造ミニゲーム
- 非金属加工用作業台
- 非金属加工用アイテム
- 二次元グリッドを使用する非金属加工ミニゲーム
- 金属パーツ、非金属パーツ、その他の中間素材
- 固定レシピによる完成品の組み立て
- 品質の保存、表示、計算、完成品への性能反映
- バニラの武器、防具、ツールに対応する加工パーツとレシピ
- 対象MODの装備、素材、ドロップに対する連携機能

MVPで連携対象とするMODは以下のとおり。

- L_Ender's Cataclysm
- Twilight Forest
- Alex's Caves
- Roaring

### 4.2 含めないもの

- 独自の修理システム
- 製作後に品質を上げる再鍛造または強化システム
- ランダムエンチャントの付与
- パーツと素材の自由な組み合わせによる動的な装備生成
- 素材の採集システム
- 専用の組立作業台

## 5. 制作フロー

```text
採集済み素材
    ├─ 金属素材
    │    ↓
    │  るつぼへ投入
    │    ↓
    │  溶鉱炉で加熱
    │    ↓
    │  鋳型へ流し込み、冷却
    │    ↓
    │  鍛造ミニゲーム
    │    ↓
    │  金属パーツ
    │
    └─ 非金属素材
         ↓
       加工パーツを選択
         ↓
       削りミニゲーム
         ↓
       非金属パーツ

金属パーツ + 非金属パーツ + レシピ固有素材
    ↓
バニラの作業台で組み立て
    ↓
品質付き完成品
```

完成品によっては、金属パーツまたは非金属パーツの一方だけを使用してもよい。必要なパーツ構成は完成品レシピで定義する。

## 6. 品質システム

### 6.1 内部値と表示

品質は `0` から `100` までの整数で保持する。計算結果が範囲外になった場合は、この範囲へ丸める。

プレイヤーには品質値を直接表示せず、以下の段階へ変換して表示する。

| 内部品質 | 表示 |
|---:|---|
| 0～19 | 粗悪 |
| 20～39 | 低品質 |
| 40～59 | 標準 |
| 60～79 | 高品質 |
| 80～100 | 最高品質 |

段階名と閾値はJSONから変更可能にする。

将来、スキル効果などによって品質の内部値を表示できる余地を残す。

### 6.2 中間パーツの品質

加工によって生成された中間パーツは、それぞれ品質を持つ。

金属パーツの品質には、少なくとも以下を反映する。

- 加熱時間と適正時間との差
- 鋳造可能な状態であったか
- 鍛造時の打撃強度と適正強度との差
- 打撃回数と適正回数との差

非金属パーツの品質には、少なくとも以下を反映する。

- 加工後の形状と理想形状の一致度
- 削りすぎた量
- 使用した加工用アイテム

各工程の点数を中間パーツ品質へ変換する処理は、品質計算APIを経由する。計算式を各ブロックやGUIへ分散させない。

スキル値は品質計算式へ直接加算しない。スキルによって操作しやすくなった結果、より良い加工結果を出せることはあるが、同じ加工結果からはスキル値にかかわらず同じ品質を算出する。

### 6.3 完成品の品質

初期実装では、完成品に使用した品質付きパーツの算術平均を完成品品質とする。

```text
完成品品質 = 品質付きパーツの品質合計 / 品質付きパーツ数
```

端数の処理方法は品質計算API内で統一する。完成品レシピに品質を持たない材料が含まれる場合、その材料は平均計算の対象外とする。

平均計算は暫定仕様であり、主要パーツへの重み付けなどへ変更できるようにする。クラフト処理から平均値を直接計算せず、必ず完成品品質計算APIを呼び出す。

### 6.4 通常レシピの品質

バニラまたは他MODが提供する通常レシピは原則として残す。通常レシピから生成された品質対象アイテムには、固定品質 `30` を付与する。

品質データを持たない既存アイテムを読み込んだ場合も、品質 `30` として扱う。この固定値はJSONから変更可能にする。

### 6.5 品質による性能補正

品質によって補正する能力はアイテム種別ごとに定義する。

| 種別 | 主な補正対象 |
|---|---|
| 武器 | 攻撃力、最大耐久値 |
| 防具 | 防御力、防具強度、最大耐久値 |
| 採掘・伐採ツール | 採掘速度、最大耐久値 |
| クワなどの作業用ツール | 最大耐久値、必要に応じて作業性能 |

採掘速度と最大耐久値には、以下の補正式を使用する。

```text
採掘速度倍率 = 0.7 + 品質 × 0.006
最大耐久値倍率 = 0.7 + 品質 × 0.006
```

品質 `0` でバニラ性能の70%、品質 `50` で100%、品質 `100` で130%となる。最大耐久値など整数を必要とする値は、最終計算時に丸める。

攻撃力、防御力、防具強度、作業性能の具体的な補正式は別途決定する。補正値はJSONから変更可能にする。品質によるランダムエンチャントはMVPでは行わない。

既存のエンチャントは品質補正と併用できるものとする。

## 7. 金属加工システム

### 7.1 るつぼ

るつぼは、金属素材を入れて溶鉱炉で加熱するための容器である。

るつぼは少なくとも以下の状態を保持する。

- 投入された金属の種類
- 投入量
- 加熱経過時間
- 現在の加工状態
- 加熱工程で発生した品質評価

異なる金属を同時に投入できるか、合金を扱うかはMVPの未決定事項とする。合金を実装しない場合は、異なる金属を同じるつぼへ投入できないようにする。

### 7.2 溶鉱炉と加熱

溶鉱炉はGUIを持たない。プレイヤーがるつぼを持って右クリックすると溶鉱炉へ挿入し、るつぼを持っていない状態で右クリックすると取り出す。

溶鉱炉は、真下に有効な熱源がある場合だけ加熱する。MVPで有効な熱源は以下のとおり。

- 溶岩
- 炎
- 魂の炎

有効な熱源はデータから追加可能にする。MVPでは熱源による加熱速度の差を設けない。熱源が失われた場合は、その時点で加熱を停止する。

るつぼ用の外部アイテム入出力機能は公開しない。ホッパー、Create、他MODの搬送機器によるるつぼの挿入と取り出しは許可せず、必ずプレイヤーの右クリック操作を要求する。常時加熱は、開発およびテスト用設定でのみ利用可能にする。

金属ごとに以下の時間をデータとして定義する。

- 鋳造可能になる最小時間
- 品質が最大になる適正時間または適正時間帯
- 適正時間から外れた場合の品質低下
- 全消失となる上限時間

プレイヤーは任意のタイミングでるつぼを取り出せる。取り出し自体では結果を確定せず、鋳型へ流し込んだ時点の加熱状態によって結果を決定する。

加熱状態と結果は以下のとおり。

| 状態 | 鋳造結果 |
|---|---|
| 早すぎて鋳造不能 | 金属塊を生成する。投入量の一部は消失する |
| 鋳造可能だが適正時間外 | 対象パーツを生成できるが品質が低下する |
| 適正時間内 | 加熱工程で高い品質評価を得る |
| 遅すぎる | 回収不能な廃棄物となり、投入金属は全消失する |

金属塊は再びるつぼへ投入できる。金属塊に変化した場合は、使用した金属量の `1/2` を切り上げた量を失う。残りの量を金属塊として回収する。

```text
損失量 = ceil(使用量 / 2)
金属塊の量 = 使用量 - 損失量
```

損失割合と端数処理はデータから調整可能にする。

全消失が近い状態では警告を表示する。警告は正確な残り時間や適正時間を公開しなくてもよい。

### 7.3 鋳型と鋳造

鋳型は、溶解した金属から作るパーツの種類を決定する。

基本フローは以下のとおり。

1. 鋳造用作業台へ鋳型を設置する
2. 加熱したるつぼから金属を流し込む
3. 加熱状態と必要量を検証する
4. 一定時間冷却する
5. 鍛造前の粗加工パーツを生成する

パーツごとに、使用する鋳型、使用可能な金属、必要量、冷却時間をレシピとして定義する。

通常装備には汎用鋳型を利用できる。ボス素材装備などには、探索やダンジョン報酬から入手する専用鋳型を要求できる。

### 7.4 鍛造台と鍛造ミニゲーム

プレイヤーは粗加工パーツを鍛造台へ置き、ハンマーを持って右クリックすることで鍛造ミニゲームを開始する。

ミニゲームの基本仕様は以下のとおり。

1. GUI下部に、一定時間ごとに増減する打撃強度ゲージを表示する
2. プレイヤーは任意のタイミングで打撃操作を行う
3. 打撃時点のゲージ値を、その打撃の強度として記録する
4. プレイヤーは必要だと判断する回数だけ打撃する
5. プレイヤーが「完成」ボタンを押すと採点する
6. 採点結果から金属パーツの品質を決定する

金属パーツごとに適切な打撃強度と打撃回数をJSONで定義する。同じ金属でも、パーツの形状や用途によって条件を変更できる設計とする。

品質は、各打撃の強度と適正強度との差、および実際の打撃回数と適正回数との差が小さいほど高くなる。

打撃回数が破損上限を超えた場合は、完成操作を待たずに加工失敗とし、金属塊へ変化させる。破損上限へ近づいた場合は、正確な上限回数を公開せず、ひび、音、エフェクト、GUI表示などで危険を通知する。

適正強度、適正回数、破損上限はプレイヤーへ数値として公開しない。

## 8. 非金属加工システム

### 8.1 対象素材

初期対象には、木材、布、宝石などを含める。素材の追加時にミニゲーム自体を増やす必要がないよう、素材特性と加工レシピをデータとして定義する。

素材ごとに設定できる主な特性は以下のとおり。

- 硬さ
- 一回の操作で削れる量
- 操作位置から削れる範囲
- 入力位置に対する誤差
- 使用可能な加工用アイテム

### 8.2 加工フロー

1. 非金属加工用作業台へ素材を置く
2. 作成するパーツを選択する
3. 対応する加工用アイテムを持って右クリックする
4. GUI上で加工ミニゲームを開始する
5. 左クリックを押しながら、削りたい位置をドラッグする
6. 操作位置を中心に素材を削る
7. プレイヤーが完成操作を行う
8. 理想形状との一致度から品質を計算する

パーツを選択してから加工を開始し、加工途中で別のパーツへ変更することはできない。

### 8.3 二次元グリッド

素材の形状はGUI上の二次元グリッドとして保持する。各セルは、素材の残存量を表す数値を持つ。

```text
0.0 = 完全に削られている
1.0 = 完全に残っている
```

加工操作では、カーソル位置を中心としたセルの残存量を減少させる。実際に減少する量と範囲には、素材特性、加工用アイテム、およびスキルによって利用可能な操作精度を反映する。

グリッド解像度は固定値としてコードへ埋め込まず、複数段階から選択できる構造とする。スキルによって、より細かいグリッド解像度と、より狭い削り幅を利用可能にする。

理想形状は、ゲーム内で利用可能な最大グリッド解像度で定義する。下位解像度で加工した結果は最大解像度へ展開し、最大解像度の理想形状と比較する。

下位解像度では理想形状を完全再現できないように形状を設計し、スキルによって解像度を上げるほど形状へ近づけるようにする。スキル値を品質へ直接加点せず、操作可能な解像度の違いによって加工精度へ差を生じさせる。

採点はセル数そのものではなく面積比を基準にし、最大解像度が変更されても同じ評価関数を利用できるようにする。

### 8.4 理想形状と採点

理想形状は、素材や完成アイテムごとではなく、`pickaxe_handle` などのパーツ種別ごとに定義する。同じパーツ種別を異なる素材から加工する場合は、同じ理想形状を再利用する。

加工レシピは、製作するパーツ種別に対応する理想形状を参照する。理想形状は採点にのみ使用し、加工中のGUIへ正解ガイドとして表示しない。

品質計算では少なくとも以下を評価する。

- 残すべき領域が残っている割合
- 削るべき領域を削れた割合
- 削りすぎによって失われた領域

削りすぎが破損閾値を超えた場合は、パーツを生成せず素材を消失させる。破損が近い場合はGUI上の状態変化などで警告する。

素材ごとに異なるミニゲームは実装しない。同じ操作規則を使い、素材特性によって加工感と難易度を変える。

## 9. 完成品の組み立て

加工済みパーツは、バニラの作業台で固定レシピに従って組み立てる。

組み立てレシピは少なくとも以下を定義する。

- 完成品ID
- 必要な金属パーツ
- 必要な非金属パーツ
- 品質を持たない追加材料
- 完成品品質計算に使用するパーツ

レシピが要求するパーツの種類が一致していれば、異なる品質のパーツを同時に使用できる。完成品には品質計算APIが返した品質と、それに対応する性能補正を保存する。

通常レシピと鍛冶用レシピが同じ完成品を生成する場合でも、通常レシピ品は固定低品質、鍛冶用レシピ品はパーツから計算した品質となる。

## 11. スキル連携

鍛冶関連の行動は `Pufferfish's Skills` の対応スキルと連携する。

スキルは、品質を直接上昇させる数値補正や、製作可能なアイテムを制限する条件として使用しない。スキル未取得者でも、すべての加工工程とレシピへ挑戦できるものとする。

スキルによる成長は、プレイヤーが加工操作をより精密に行えるようにする。候補となる効果は以下のとおり。

- 打撃強度ゲージの目盛りを細分化し、現在の強度を読み取りやすくする
- 打撃強度ゲージ上へ補助線を追加し、狙った強度で打撃しやすくする
- 非金属加工で選択できる削り幅を細分化する
- 非金属加工で、より細かいグリッド解像度を選択可能にする

打撃強度、打撃回数、形状一致度などの採点基準はスキルによって変更しない。品質計算時にスキル値を参照せず、ミニゲームから得られた加工結果だけを評価する。

スキルによる操作支援は各ミニゲーム内へ直接記述せず、スキル連携用の窓口から利用可能な操作精度を取得する。スキル効果の追加や変更によって、品質計算APIや加工レシピを変更する必要がない構造とする。

## 12. 他職業とのつながり

鍛冶師は素材の採集を担当せず、他職業から素材を受け取って加工する。

| 供給元・利用者 | 鍛冶師との関係 |
|---|---|
| 冒険家 | ボス素材や戦闘報酬を供給し、製作された武器と防具を使用する |
| 探検家 | 希少鉱石、地域素材、専用鋳型を供給し、製作された探索用装備を使用する |
| 農家 | 鍛冶師からクワなどの農業用ツールを購入、利用する |

この供給関係により、素材の獲得、加工、販売、装備更新のプレイヤー間経済を形成する。

## 13. 他MODとの連携

### 13.1 連携方式

他MOD対応は、鍛冶システム本体へ個別処理を混在させず、対象MODごとの連携機能として実装する。

対象MODが導入されている場合だけ、以下を登録する。

- 対象素材
- 中間パーツ
- 専用鋳型
- 加工レシピ
- 組み立てレシピ
- 品質による完成品の性能補正
- 必要に応じたルートテーブル変更

対象MODが存在しない環境でも、鍛冶システム本体が読み込みエラーを起こさないようにする。

### 13.2 ボスドロップの置き換え

ボスが対象装備を直接ドロップする場合は、その装備を鍛冶工程で製作できるよう、直接ドロップを対応するボス素材へ置き換える。

置き換えは対象MODごとの連携機能で行い、ボスやMODに依存する判定を共通の鍛冶処理へ持ち込まない。

ボス素材から専用中間パーツを作り、定義済みの固定レシピで元の装備を完成させる。自由な素材合成は行わない。

対象装備、置き換えるドロップ、素材数、専用鋳型の入手方法はMODごとの対応表で管理する。

## 14. データ定義とAPI境界

### 14.1 データ駆動にする項目

具体的な配置、JSON構造、検証規則は、[鍛冶システムJSON・評価関数仕様](./data-formats.md)で定義する。

可能な限り、JSON、データパック、設定ファイルなどから以下を変更可能にする。

特に、金属の加熱条件と鍛造条件は必ずJSONで定義し、ソースコードへ直接記述しない。

- 金属ごとの必要量と加熱時間
- 適正時間からのずれによる品質低下
- 金属塊化と全消失の閾値
- 金属塊化した際の損失割合
- 冷却時間
- 鋳型と生成パーツの対応
- 打撃の適正強度、適正回数、破損上限
- 非金属素材の硬さと削れ方
- 非金属パーツの理想形状
- 品質の表示段階と閾値
- 品質による性能補正
- 通常レシピ品の固定品質
- 完成品の組み立てレシピ
- 他MODの素材、パーツ、完成品の対応
- スキルレベルごとのゲージ目盛り、削り幅、グリッド解像度

不正な定義を読み込んだ場合は、該当定義を無効化し、原因を特定できるログを出力する。

### 14.2 品質計算API

品質に関する計算は、少なくとも以下の責務に分ける。

- 加熱結果から工程品質を計算する
- 鍛造結果から工程品質を計算する
- 非金属形状からパーツ品質を計算する
- 複数工程から中間パーツ品質を計算する
- 複数パーツから完成品品質を計算する
- 内部品質を表示段階へ変換する
- 品質からアイテム性能補正を計算、適用する

各作業台、レシピ、GUI、MOD連携コードは独自に品質式を実装せず、共通APIを呼び出す。

初期実装の平均計算を将来重み付き計算へ変更しても、クラフト処理や各連携機能を修正せずに済む構造とする。

各評価関数は、加工状態とJSON定義を入力として `0` から `100` の評価値を返す、副作用のない独立した処理とする。具体的な関数境界は、[鍛冶システムJSON・評価関数仕様](./data-formats.md)で定義する。

## 15. 保存と同期

以下の情報は、ワールド再読み込みやサーバー再起動後も保持する。

- るつぼの内容と加熱状態
- 鋳造中の素材、鋳型、冷却進捗
- 鍛造中のパーツと打撃履歴
- 非金属加工中の対象パーツと二次元グリッド
- 中間パーツと完成品の品質

鍛造と非金属加工は、GUIを閉じた場合に即時完成させず一時停止する。ログアウト、通信切断、サーバー停止の場合も同様に状態を保存する。

鍛造では、加工対象、打撃履歴、ゲージ位置、ゲージの移動方向を保存する。非金属加工では、加工対象、選択パーツ、二次元グリッド、使用素材を保存する。再度GUIを開いた場合は保存地点から再開し、完成ボタンを押した場合だけ採点と品質確定を行う。

加熱にはGUIがなく、るつぼが溶鉱炉へ挿入され、有効な熱源が存在する間は進行する。ログアウトやサーバーにプレイヤーがいないことを理由に停止しない。

別のプレイヤーも同じ作業台から加工を再開できる。作業台を破壊した場合は、加工途中の状態を保持した作業物をドロップし、再設置または対応作業台で再開できるようにする。作業台の破壊によって加工状態を初期化できないようにする。

同じ入力から複数の出力を得られないよう、状態変更、素材返却、完成品生成はサーバー側で排他的に処理する。

品質値が異なる中間素材のスタック可否は実装前に確定する。

## 16. 実装順序

MVPのリリース対象は全バニラ武器、防具、ツール、および対象MOD連携とする。ただし、実装と検証は以下の順で進める。

1. 品質データ、品質計算API、性能補正の基盤
2. るつぼ、溶鉱炉、加熱状態の保存
3. 鋳型、鋳造、冷却
4. 鍛造台と鍛造ミニゲーム
5. 非金属加工用作業台と削りミニゲーム
6. 鉄のピッケルを使用した一連の制作フロー
7. 通常レシピ品への固定低品質の付与
8. バニラの対象武器、防具、ツールへの展開
9. L_Ender's Cataclysm連携
10. Twilight Forest連携
11. Alex's Caves連携
12. Roaring連携
13. 全体のバランス調整とサーバー負荷検証

最初に一種類の完成品で、素材投入から品質付き完成品の生成までを縦に完成させる。その後、同じ基盤へレシピとデータを追加して対象を広げる。

## 17. MVP受け入れ条件

MVPは少なくとも以下を満たした場合に完成とする。

- 通常レシピから対象アイテムを作成でき、品質 `30` の低品質品になる
- 鉄インゴット3個から鉄製ピッケルヘッドを作成できる
- 鉄の加熱時間と鍛造条件をJSONの変更によって調整できる
- 溶鉱炉がGUIを持たず、右クリックだけでるつぼを出し入れできる
- 有効な熱源が真下にある場合だけ溶鉱炉が加熱する
- 搬送機器からるつぼを挿入または取り出せない
- 金属を加熱、鋳造、鍛造して品質付き金属パーツを作成できる
- 早すぎる鋳造で、素材の一部を失った金属塊が生成される
- 遅すぎる鋳造で、投入金属が全消失する
- 鍛造の強度と回数によって品質が変化する
- 鍛造回数が多すぎる場合に金属塊へ変化する
- 非金属素材を二次元グリッド上で加工し、形状一致度から品質を決定できる
- 非金属素材を削りすぎた場合に素材が消失する
- 固定レシピでパーツを組み立て、パーツ品質の平均を完成品へ設定できる
- 完成品品質に応じて、種別ごとの性能が補正される
- 品質付き完成品へバニラのエンチャントと修理を適用できる
- スキル未取得者でも、すべての加工工程とレシピへ挑戦できる
- スキルによって打撃ゲージ、削り幅、グリッド解像度の操作精度が変化する
- 同じ加工結果からは、スキル値にかかわらず同じ品質が算出される
- 鍛造と非金属加工を中断し、保存地点から再開できる
- 消失リスクが近い場合に、正解値を公開しない警告が表示される
- サーバー再起動後も進行中の加工状態と品質が保持される
- 対象MODごとの連携が、他の連携や鍛冶システム本体から分離されている
- 対象MODが存在しない環境でも、鍛冶システム本体を読み込める
