# 鍛冶師システム仕様

## 1. 本書の目的

本書は、Craftboundにおける鍛冶師関連システムのゲーム仕様と実装方針を定義する。

鍛冶師関連の実装では、本書を判断基準として使用する。`docs/overview.md` と記述が競合する場合は、鍛冶師システムについては本書を優先する。

本書では、調整によって変更する数値と、変更してはならないシステム上の責務を分けて扱う。適正時間、品質補正値、ミニゲームの判定値などはデータとして調整可能にし、コードへ直接埋め込まない。

個別仕様とデータ形式は、以下の文書で定義する。

- [鉄のピッケル試作仕様](./iron-pickaxe.md)
- [鍛冶システムJSON・評価関数仕様](./data-formats.md)
- [鍛冶システムテスト仕様](./test-cases.md)
- [設備・道具・鋳型仕様](./equipment/stations-and-tools.md)
- [バニラ装備構成仕様](./equipment/vanilla.md)

## 2. 鍛冶師の役割

鍛冶師は、入手済みの素材を加工し、武器、防具、ツールを製作する生産職である。

担当する工程は以下のとおり。

- 金属の溶解、鋳造、鍛造
- 木材、布、宝石などの非金属素材の加工
- 加工済みパーツを使用した完成品の組み立て
- 装備、武器、ピッケル、斧、クワなどの製作

鉱石、木材、ボス素材などの採集は鍛冶師の役割に含めない。素材は主に冒険家、探検家、その他の採集担当から供給される。

独自の修理システムと、製作後の独自強化システムはMVPに含めない。バニラの金床やクラフトによる修理と、既存のエンチャントシステムは利用可能なまま残す。

## 3. 設計方針

### 3.1 手作業による高品質化

通常のクラフトレシピは削除しない。ただし、通常レシピから作られた対象アイテムは固定の低品質品とする。

高品質品を作るには、金属加工または非金属加工によってパーツを製作し、定義済みのレシピで組み立てる必要がある。

### 3.2 固定された完成品とレシピ

初期実装では、素材とパーツを自由に組み合わせて新しい装備を生成する方式を採用しない。

完成品、必要なパーツ、使用可能な素材はレシピごとに定義する。組み立てにはバニラの作業台を使用し、専用の組立作業台は追加しない。

### 3.3 発見を重視したミニゲーム

適正加熱時間、適切な打撃強度、適切な打撃回数、非金属パーツの理想形状などの正解値はプレイヤーへ直接公開しない。プレイヤー同士の試行錯誤と情報交換によって、より良い加工方法が開拓されることを狙う。

ただし、素材の全消失や再加工が必要になる状態が近い場合は、視覚、音、エフェクト、GUI表示などによる警告を必須とする。正解値そのものを示さず、危険が近いことだけを伝える。

### 3.4 サーバー側を正とする

加工状態、素材消費、ミニゲーム結果、品質計算、完成品の生成はサーバー側で検証、確定する。クライアントから送信された操作結果を、そのまま完成結果として信用しない。

## 4. MVPの範囲

### 4.1 含めるもの

- るつぼ
- 溶鉱炉
- 鋳型と鋳造用作業台
- 鍛造台
- ハンマー
- 鍛造ミニゲーム
- 非金属加工用作業台
- 非金属加工用アイテム
- 二次元グリッドを使用する非金属加工ミニゲーム
- 金属パーツ、非金属パーツ、その他の中間素材
- 固定レシピによる完成品の組み立て
- 品質の保存、表示、計算、完成品への性能反映
- バニラの武器、防具、ツールに対応する加工パーツとレシピ
- 対象MODの装備、素材、ドロップに対する連携機能

MVPで連携対象とするMODは以下のとおり。

- L_Ender's Cataclysm
- Twilight Forest
- Alex's Caves
- Roaring

### 4.2 含めないもの

- 独自の修理システム
- 製作後に品質を上げる再鍛造または強化システム
- ランダムエンチャントの付与
- パーツと素材の自由な組み合わせによる動的な装備生成
- 素材の採集システム
- 専用の組立作業台

## 5. 制作フロー

```text
採集済み素材
    ├─ 金属素材
    │    ↓
    │  るつぼへ投入
    │    ↓
    │  溶鉱炉で加熱
    │    ↓
    │  鋳型へ流し込み、冷却
    │    ↓
    │  鍛造ミニゲーム
    │    ↓
    │  金属パーツ
    │
    └─ 非金属素材
         ↓
       加工パーツを選択
         ↓
       削りミニゲーム
         ↓
       非金属パーツ

金属パーツ + 非金属パーツ + レシピ固有素材
    ↓
バニラの作業台で組み立て
    ↓
品質付き完成品
```

完成品によっては、金属パーツまたは非金属パーツの一方だけを使用してもよい。必要なパーツ構成は完成品レシピで定義する。

## 6. 品質システム

### 6.1 内部値と表示

品質は `0` から `100` までの整数で保持する。計算結果が範囲外になった場合は、この範囲へ丸める。

プレイヤーには品質値を直接表示せず、以下の段階へ変換して表示する。

| 内部品質 | 表示 |
|---:|---|
| 0～19 | 粗悪 |
| 20～39 | 低品質 |
| 40～59 | 標準 |
| 60～79 | 高品質 |
| 80～100 | 最高品質 |

段階名と閾値はJSONから変更可能にする。

将来、スキル効果などによって品質の内部値を表示できる余地を残す。

### 6.2 中間パーツの品質

加工によって生成された中間パーツは、それぞれ品質を持つ。

金属パーツの品質には、少なくとも以下を反映する。

- 加熱時間と適正時間との差
- 鋳造可能な状態であったか
- 鍛造時の打撃強度と適正強度との差
- 打撃回数と適正回数との差

非金属パーツの品質には、少なくとも以下を反映する。

- 加工後の形状と理想形状の一致度
- 削りすぎた量
- 使用した加工用アイテム

各工程の点数を中間パーツ品質へ変換する処理は、品質計算APIを経由する。計算式を各ブロックやGUIへ分散させない。

スキル値は品質計算式へ直接加算しない。スキルによって操作しやすくなった結果、より良い加工結果を出せることはあるが、同じ加工結果からはスキル値にかかわらず同じ品質を算出する。

### 6.3 完成品の品質

初期実装では、完成品に使用した品質付きパーツの算術平均を完成品品質とする。

```text
完成品品質 = 品質付きパーツの品質合計 / 品質付きパーツ数
```

端数の処理方法は品質計算API内で統一する。完成品レシピに品質を持たない材料が含まれる場合、その材料は平均計算の対象外とする。

平均計算は暫定仕様であり、主要パーツへの重み付けなどへ変更できるようにする。クラフト処理から平均値を直接計算せず、必ず完成品品質計算APIを呼び出す。

### 6.4 通常レシピの品質

バニラまたは他MODが提供する通常レシピは原則として残す。通常レシピから生成された品質対象アイテムには、固定品質 `30` を付与する。

品質データを持たない既存アイテムを読み込んだ場合も、品質 `30` として扱う。この固定値はJSONから変更可能にする。

### 6.5 品質による性能補正

品質によって補正する能力はアイテム種別ごとに定義する。

| 種別 | 主な補正対象 |
|---|---|
| 近接武器 | 攻撃力、最大耐久値 |
| 遠距離武器 | 射撃ダメージ、最大耐久値 |
| 防具 | 防御力、防具強度、最大耐久値 |
| 採掘・伐採ツール | 採掘速度、最大耐久値 |
| クワなどの作業用ツール | 最大耐久値、必要に応じて作業性能 |

攻撃力、射撃ダメージ、防御力、防具強度、採掘・作業速度、最大耐久値には、以下の補正式を使用する。

```text
性能倍率 = 0.7 + 品質 × 0.006
```

品質 `0` でバニラ性能の70%、品質 `50` で100%、品質 `100` で130%となる。攻撃力と採掘・作業速度は、アイテムが持つ基礎値へ倍率を適用してからエンチャントなどの追加補正を適用する。防御力と防具強度は0.5単位、最大耐久値は整数へ丸める。

攻撃速度、ノックバック、ノックバック耐性、エンチャント効果には品質倍率を適用しない。補正値と丸め方はJSONから変更可能にする。品質によるランダムエンチャントはMVPでは行わない。

既存のエンチャントは品質補正と併用できるものとする。

品質の付与または継承によって最大耐久値が変化した場合は、変更前の損傷割合を維持する。

```text
新しい損傷値 = round(新しい最大耐久値 × 変更前の損傷値 / 変更前の最大耐久値)
```

新規製作品の損傷値は `0` とする。補正計算には登録時の基礎耐久値を使用し、品質補正済みの値へ再度倍率を掛けない。計算結果は `0` から `新しい最大耐久値 - 1` の範囲へ収める。

### 6.6 品質の引き継ぎ

品質付きアイテムをバニラの機能で加工する場合は、以下の規則で品質を維持する。

| 操作 | 品質の扱い |
|---|---|
| 金床での修理、名前変更、エンチャント合成 | 左側の対象スロットに置いた装備の品質を維持する |
| 修理素材を使用する金床修理 | 対象装備の品質を維持する |
| 砥石 | 入力装備の品質を維持する |
| 鍛冶台による派生装備への変換 | ベース装備の品質を結果へ引き継ぐ |
| 耐久値の回復、Mending | 品質を変更しない |

品質データを持たないアイテムは品質 `30` として扱う。通常クラフトで品質対象アイテムを別の品質対象アイテムへ変換する場合は、品質継承を明示した専用レシピでない限り、出力を品質 `30` とする。

品質の保存と性能補正の再計算はサーバー側で行う。同じ性能補正を重複適用しないよう、品質由来の属性補正には安定した識別子を使用する。

## 7. 金属加工システム

### 7.1 るつぼ

るつぼは、金属素材を入れて溶鉱炉で加熱するための容器である。

るつぼは少なくとも以下の状態を保持する。

- 投入された金属の種類
- 投入量
- 加熱経過時間
- 現在の加工状態
- 加熱工程で発生した品質評価

MVPのるつぼ容量は16インゴット相当とする。同じ金属であれば、インゴットと再利用可能な金属塊を混在して投入できる。内容物と異なる金属、および容量を超える投入は拒否し、投入アイテムを消費しない。MVPでは合金を扱わない。

鋳造時は、対象パーツが要求する量だけをるつぼから消費する。余剰分は、金属の種類、加熱経過時間、その他の状態を維持したままるつぼへ残す。

るつぼを手に持ち、ブロックを対象にせずスニークしながら右クリックすると、手動投入用GUIを開く。GUIは素材投入用の1スロットと、現在量を示す容量表示を持つ。通常クリックでは1個、シフトクリックでは容量に収まる最大量を投入する。

素材は、一度も加熱していないるつぼからだけ取り出せる。一度でも加熱した後は、投入素材を個別アイテムへ戻せず、鋳型へ流すか、溶鉱炉へ戻して再加熱する必要がある。内容量が `0` になった場合は未加熱状態へ戻す。

るつぼ用GUIはプレイヤーの手動操作だけを受け付ける。アイテムハンドラーなどの外部入出力機能を公開せず、GUIを経由した投入をCreate、ホッパー、他MODから自動化できないようにする。

### 7.2 溶鉱炉と加熱

溶鉱炉はGUIを持たない。プレイヤーがるつぼを持って右クリックすると溶鉱炉へ挿入し、るつぼを持っていない状態で右クリックすると取り出す。

溶鉱炉は、真下に有効な熱源がある場合だけ加熱する。MVPで有効な熱源は以下のとおり。

- 溶岩
- 炎
- 魂の炎

有効な熱源はデータから追加可能にする。MVPでは熱源による加熱速度の差を設けない。熱源が失われた場合は、その時点で加熱を停止する。

るつぼ用の外部アイテム入出力機能は公開しない。ホッパー、Create、他MODの搬送機器によるるつぼの挿入と取り出しは許可せず、必ずプレイヤーの右クリック操作を要求する。常時加熱は、開発およびテスト用設定でのみ利用可能にする。

金属ごとに以下の時間をデータとして定義する。

- 鋳造可能になる最小時間
- 品質が最大になる適正時間または適正時間帯
- 適正時間から外れた場合の品質低下
- 全消失となる上限時間

プレイヤーは任意のタイミングでるつぼを取り出せる。溶鉱炉から取り出した時点で加熱経過時間を固定し、プレイヤーが所持している間やインベントリ内では加熱も冷却も進行させない。同じるつぼを有効な熱源のある溶鉱炉へ戻した場合は、保存された加熱経過時間から加熱を再開する。

取り出し自体では結果を確定しない。鋳型へ流し込んだ時点の加熱経過時間を加熱評価関数へ渡し、加熱結果を確定する。

加熱状態と結果は以下のとおり。

| 状態 | 鋳造結果 |
|---|---|
| 早すぎて鋳造不能 | 金属塊を生成する。投入量の一部は消失する |
| 鋳造可能だが適正時間外 | 対象パーツを生成できるが品質が低下する |
| 適正時間内 | 加熱工程で高い品質評価を得る |
| 遅すぎる | 回収不能な廃棄物となり、投入金属は全消失する |

金属塊は再びるつぼへ投入できる。金属塊に変化した場合は、使用した金属量の `1/2` を切り上げた量を失う。残りの量を金属塊として回収する。

```text
損失量 = ceil(使用量 / 2)
金属塊の量 = 使用量 - 損失量
```

損失割合と端数処理はデータから調整可能にする。

全消失が近い状態では、黒煙パーティクルと不規則な金属音で警告する。警告は正確な残り時間や適正時間を公開しない。

### 7.3 鋳型と鋳造

鋳型は、溶解した金属から作るパーツの種類を決定する。

基本フローは以下のとおり。

1. 鋳型を持って鋳造用作業台を右クリックし、鋳型を設置する
2. 加熱したるつぼを持って右クリックし、加熱状態と必要量を検証する
3. 検証に成功した場合だけ必要量の金属を流し込み、冷却を開始する
4. 任意のタイミングで空の手によって右クリックし、粗加工パーツを取り出す
5. 取り出した時点の冷却時間と破損回数上限を粗加工パーツへ保存する
6. 鋳造物がない状態で、空の手によってスニークしながら右クリックすると鋳型を回収する

冷却中は鋳型の交換と通常操作による回収を禁止する。MVPでは鋳型に耐久値を設定せず、鋳造後も繰り返し使用可能とする。

鋳造用作業台を破壊した場合は、設置済みの鋳型と、加工状態を保持した粗加工パーツをドロップする。冷却中の鋳造物は破壊時点を鋳型からの取り出しとして扱い、その時点の冷却時間と破損回数上限を固定する。ブロック破壊によって素材を複製したり、冷却状態を初期化したりできないようにする。

冷却時間は、溶解金属を鋳型へ流し込んでから、粗加工パーツを鋳型から取り出すまでの時間とする。粗加工パーツは、安全冷却時間へ達する前でも取り出して鍛造できるが、冷却不足の場合は鍛造時の破損回数上限が低くなる。

鋳型から取り出した時点で冷却時間と破損回数上限を固定する。インベントリ、鍛造台、鍛造ミニゲーム中は冷却時間を進行させない。

パーツごとに、使用する鋳型、使用可能な金属、必要量、表面凝固時間、安全冷却時間をJSONで定義する。表面凝固時間は正解時刻を示さない中間状態として扱い、到達時に一度だけ蒸気音を再生する。鋳造直後から表面凝固までは蒸気パーティクルを多くし、以降は量を減らす。

安全冷却時間へ達したことを示す音、通知、専用エフェクトは設けない。安全冷却時間を事実上の正解として公開せず、プレイヤーが試行から判断する余地を残すためである。将来、実装コストが許容できる場合は、赤熱色から元の金属色へ徐々に戻る描画を追加してよい。ただし、色だけから安全冷却完了の正確な瞬間を判別できない変化とする。

鋳型内で安全冷却時間を超えて待っても、品質や破損回数上限へ追加効果を与えない。

通常装備には汎用鋳型を利用できる。ボス素材装備などには、探索やダンジョン報酬から入手する専用鋳型を要求できる。

### 7.4 鍛造台と鍛造ミニゲーム

プレイヤーは粗加工パーツを鍛造台へ置き、ハンマーを持って右クリックすることで鍛造ミニゲームを開始する。

ミニゲームの基本仕様は以下のとおり。

1. GUI下部に、`0` から `100` の間を往復する打撃強度ゲージを表示する
2. プレイヤーは任意のタイミングで左クリックして打撃する
3. 打撃時点のゲージ値を、その打撃の強度として記録する
4. プレイヤーは必要だと判断する回数だけ打撃する
5. プレイヤーが「完成」ボタンを押すと採点する
6. 採点結果から金属パーツの品質を決定する

ゲージは `0 → 100 → 0` の三角波とし、1往復を3秒（60ゲームティック）、片道を1.5秒とする。開始時は `0` から上昇する。内部値は連続値として進行させ、画面上の目盛りへ丸めない。GUIを閉じた場合はゲージ位置と移動方向を保存し、再開時に同じ状態から続行する。

金属パーツごとに適切な打撃強度と打撃回数をJSONで定義する。同じ金属でも、パーツの形状や用途によって条件を変更できる設計とする。

品質は、各打撃の強度と適正強度との差、および実際の打撃回数と適正回数との差が小さいほど高くなる。

粗加工パーツを鋳型から取り出した時点の冷却時間から、有効な破損回数上限を計算して固定する。冷却が不足しているほど上限を低くし、安全冷却時間へ達していた場合はJSONで定義した通常の破損回数上限を使用する。

打撃回数が有効な破損回数上限へ達した場合は、完成操作を待たずに加工失敗とし、金属塊へ変化させる。残りの打撃可能回数が2回以下になった場合は、打撃音を鈍い音へ変化させ、既存のパーティクルで危険を通知する。正確な破損上限や残り回数は公開しない。

専用のひび表示は、共通のオーバーレイと既存の描画経路だけで実現でき、パーツごとのモデルやテクスチャを必要としない場合に限りMVPへ含める。それ以上の専用描画が必要な場合はMVP範囲外とし、音と既存パーティクルだけを必須とする。

適正強度、適正回数、破損上限はプレイヤーへ数値として公開しない。

## 8. 非金属加工システム

### 8.1 対象素材

初期対象には、木材、布、宝石などを含める。素材の追加時にミニゲーム自体を増やす必要がないよう、素材特性と加工レシピをデータとして定義する。

素材ごとに設定できる主な特性は以下のとおり。

- 硬さ
- 一回の操作で削れる量
- 操作位置から削れる範囲
- 入力位置に対する誤差
- 使用可能な加工用アイテム

### 8.2 加工フロー

1. 非金属加工用作業台へ素材を置く
2. 作成するパーツを選択する
3. 対応する加工用アイテムを持って右クリックする
4. GUI上で加工ミニゲームを開始する
5. 左クリックを押しながら、削りたい位置をドラッグする
6. 操作位置を中心に素材を削る
7. プレイヤーが完成操作を行う
8. 理想形状との一致度から品質を計算する

パーツを選択してから加工を開始し、加工途中で別のパーツへ変更することはできない。

彫刻ナイフの耐久値が加工中に尽きた場合は、その時点で加工を一時停止する。素材や加工状態は失わず、新しい彫刻ナイフを用意すると同じ状態から再開できる。

プレイヤーがキャンセルした場合は原材料へ戻さず、加工状態を保持した非金属加工途中アイテムを返却する。非金属加工用作業台を破壊した場合も、投入素材を個別に返却せず、同じ加工途中アイテムをドロップする。加工途中アイテムは対応する作業台へ置くことで再開できる。

### 8.3 二次元グリッド

素材の形状はGUI上の二次元グリッドとして保持する。各セルは、素材の残存量を表す数値を持つ。

```text
0.0 = 完全に削られている
1.0 = 完全に残っている
```

加工操作では、カーソル位置を中心としたセルの残存量を減少させる。実際に減少する量と範囲には、素材特性、加工用アイテム、およびスキルによって利用可能な操作精度を反映する。

削る範囲は円形ブラシとして扱う。ドラッグ中は直前の入力位置から現在位置までに通過したセルを補間し、高速にカーソルを動かしても削り跡に隙間が生じないようにする。削り処理は描画フレーム数ではなく、通過したセルとセル相当の除去量を基準に確定する。

カーソル位置は、加工領域の左上を `(0.0, 0.0)`、右端と下端の境界を `1.0` とする `[0.0, 1.0)` の正規化座標で送信する。サーバーは現在のグリッド解像度へ変換し、supercover line方式で始点から終点までに交差するすべてのセルを列挙する。同じドラッグ操作内で重複したセルは1回だけ処理し、隣接する通信区間で共有する端点セルも重複処理しない。左クリックを離して新しいドラッグ操作を開始した場合は、同じセルを再び処理できる。

ブラシ半径 `0.5` はカーソルを含む1セルだけを処理する。半径が `0.5` より大きい場合は、カーソル位置からセル中心までの距離がブラシ半径以下のセルを処理する。距離は現在のグリッドにおけるセル単位で計算する。

グリッド解像度は固定値としてコードへ埋め込まず、複数段階から選択できる構造とする。スキルによって、より細かいグリッド解像度と、より狭い削り幅を利用可能にする。

理想形状は、ゲーム内で利用可能な最大グリッド解像度で定義する。下位解像度で加工した結果は、各セルが占める正規化領域の重なり面積による加重平均で最大解像度へ展開し、最大解像度の理想形状と比較する。最近傍補間や双線形補間は使用しない。

```text
展開後セルの残存量 = Σ(入力セルの残存量 × 重なり面積) / 展開後セルの面積
```

下位解像度では理想形状を完全再現できないように形状を設計し、スキルによって解像度を上げるほど形状へ近づけるようにする。スキル値を品質へ直接加点せず、操作可能な解像度の違いによって加工精度へ差を生じさせる。

採点はセル数そのものではなく面積比を基準にし、最大解像度が変更されても同じ評価関数を利用できるようにする。

### 8.4 理想形状と採点

理想形状は、素材や完成アイテムごとではなく、`pickaxe_handle` などのパーツ種別ごとに定義する。同じパーツ種別を異なる素材から加工する場合は、同じ理想形状を再利用する。

加工レシピは、製作するパーツ種別に対応する理想形状を参照する。理想形状は採点にのみ使用し、加工中のGUIへ正解ガイドとして表示しない。

品質計算では少なくとも以下を評価する。

- 残すべき領域が残っている割合
- 削るべき領域を削れた割合
- 削りすぎによって失われた領域

削りすぎが破損閾値へ達した場合は、パーツを生成せず素材を消失させる。理想形状として残すべき領域の残存率が警告閾値以下になった場合は、警告音とGUI枠の一時的な色変化で危険を通知する。正確な残存率と破損閾値は公開しない。

専用の亀裂表示は、共通オーバーレイだけで低コストに実装できる場合に限りMVPへ含める。素材ごとの専用テクスチャや描画処理が必要な場合はMVP範囲外とする。

素材ごとに異なるミニゲームは実装しない。同じ操作規則を使い、素材特性によって加工感と難易度を変える。

## 9. 完成品の組み立て

加工済みパーツは、バニラの作業台で固定レシピに従って組み立てる。

品質付き完成品の組み立てには、独自レシピタイプ `craftbound:quality_assembly` を使用する。レシピの配置先とJSON形式は、[鍛冶システムJSON・評価関数仕様](./data-formats.md)で定義する。

組み立てレシピは少なくとも以下を定義する。

- 完成品ID
- 必要な金属パーツ
- 必要な非金属パーツ
- 品質を持たない追加材料
- 完成品品質計算に使用するパーツ

レシピが要求するパーツの種類が一致していれば、異なる品質のパーツを同時に使用できる。完成品には品質計算APIが返した品質と、それに対応する性能補正を保存する。

通常レシピと鍛冶用レシピが同じ完成品を生成する場合でも、通常レシピ品は固定低品質、鍛冶用レシピ品はパーツから計算した品質となる。

## 11. スキル連携

鍛冶関連の行動は `Pufferfish's Skills` の対応スキルと連携する。

スキルは、品質を直接上昇させる数値補正や、製作可能なアイテムを制限する条件として使用しない。スキル未取得者でも、すべての加工工程とレシピへ挑戦できるものとする。

スキルによる成長は、プレイヤーが加工操作をより精密に行えるようにする。候補となる効果は以下のとおり。

- 打撃強度ゲージの目盛りを細分化し、現在の強度を読み取りやすくする
- 打撃強度ゲージ上へ補助線を追加し、狙った強度で打撃しやすくする
- 非金属加工で選択できる削り幅を細分化する
- 非金属加工で、より細かいグリッド解像度を選択可能にする

MVPの打撃強度ゲージは、基本段階で25刻み、中位段階で10刻み、上位段階で5刻みの目盛りを表示する。目盛りは読み取り支援だけに使用し、ゲージの内部値、移動速度、適正強度、採点結果を変更しない。

打撃強度、打撃回数、形状一致度などの採点基準はスキルによって変更しない。品質計算時にスキル値を参照せず、ミニゲームから得られた加工結果だけを評価する。

スキルによる操作支援は各ミニゲーム内へ直接記述せず、スキル連携用の窓口から利用可能な操作精度を取得する。スキル効果の追加や変更によって、品質計算APIや加工レシピを変更する必要がない構造とする。

## 14. データ定義とAPI境界

### 14.1 データ駆動にする項目

具体的な配置、JSON構造、検証規則は、[鍛冶システムJSON・評価関数仕様](./data-formats.md)で定義する。

可能な限り、JSON、データパック、設定ファイルなどから以下を変更可能にする。

特に、金属の加熱条件と鍛造条件は必ずJSONで定義し、ソースコードへ直接記述しない。

- 金属ごとの必要量と加熱時間
- 適正時間からのずれによる品質低下
- 金属塊化と全消失の閾値
- 金属塊化した際の損失割合
- 冷却時間
- 鋳型と生成パーツの対応
- 打撃の適正強度、適正回数、破損上限
- 非金属素材の硬さと削れ方
- 非金属パーツの理想形状
- 品質の表示段階と閾値
- 品質による性能補正
- 通常レシピ品の固定品質
- 完成品の組み立てレシピ
- 他MODの素材、パーツ、完成品の対応
- スキルレベルごとのゲージ目盛り、削り幅、グリッド解像度

不正な定義を読み込んだ場合は、該当定義を無効化し、原因を特定できるログを出力する。

### 14.2 品質計算API

品質に関する計算は、少なくとも以下の責務に分ける。

- 加熱結果から工程品質を計算する
- 鍛造結果から工程品質を計算する
- 非金属形状からパーツ品質を計算する
- 複数工程から中間パーツ品質を計算する
- 複数パーツから完成品品質を計算する
- 内部品質を表示段階へ変換する
- 品質からアイテム性能補正を計算、適用する

各作業台、レシピ、GUI、MOD連携コードは独自に品質式を実装せず、共通APIを呼び出す。

初期実装の平均計算を将来重み付き計算へ変更しても、クラフト処理や各連携機能を修正せずに済む構造とする。

各評価関数は、加工状態とJSON定義を入力として `0` から `100` の評価値を返す、副作用のない独立した処理とする。具体的な関数境界は、[鍛冶システムJSON・評価関数仕様](./data-formats.md)で定義する。

### 14.3 MVPのアイテム・ブロックID

粗加工パーツと加工途中品は、素材、対象パーツ、加工状態をデータとして保持する汎用アイテムとする。個別の加工途中アイテムをパーツごとに登録しない。

## 15. 保存と同期

### 15.1 加工状態の保存

以下の情報は、ワールド再読み込みやサーバー再起動後も保持する。

- るつぼの内容と加熱状態
- 鋳造中の素材、鋳型、冷却進捗
- 表面凝固通知を再生済みかどうか
- 粗加工パーツを取り出した時点の冷却時間と破損回数上限
- 鍛造中のパーツと打撃履歴
- 非金属加工中の対象パーツと二次元グリッド
- 中間パーツと完成品の品質

加工途中アイテムには、工程に応じて少なくとも以下を保存する。

- データ形式のバージョン
- パーツ種別ID
- 素材IDと素材量
- 加熱経過時間と確定済みの加熱評価
- 鋳型から取り出した時点の冷却時間
- 固定済みの破損回数上限
- 打撃履歴
- 非金属加工グリッド
- 完成済みかどうか
- 確定済みの最終品質

加工開始時には、その工程の再開と採点に必要な評価関数ID、閾値、重みなどの定義を加工状態へスナップショットとして保存する。データパックを再読み込みしても、開始済みの加工には保存済みの定義を適用し、新しい定義は再読み込み後に開始した加工から適用する。

鍛造と非金属加工は、GUIを閉じた場合に即時完成させず一時停止する。ログアウト、通信切断、サーバー停止の場合も同様に状態を保存する。

鍛造では、加工対象、打撃履歴、ゲージ位置、ゲージの移動方向を保存する。非金属加工では、加工対象、選択パーツ、二次元グリッド、使用素材を保存する。再度GUIを開いた場合は保存地点から再開し、完成ボタンを押した場合だけ採点と品質確定を行う。

加熱にはGUIがなく、るつぼが溶鉱炉へ挿入され、有効な熱源が存在する間は進行する。ログアウトやサーバーにプレイヤーがいないことを理由に停止しない。

別のプレイヤーも同じ作業台から加工を再開できる。作業台を破壊した場合は、加工途中の状態を保持した作業物をドロップし、再設置または対応作業台で再開できるようにする。作業台の破壊によって加工状態を初期化できないようにする。

同じ入力から複数の出力を得られないよう、状態変更、素材返却、完成品生成はサーバー側で排他的に処理する。

加工途中のパーツと完成パーツは、品質や加工状態にかかわらずスタック不可とする。

再利用可能な金属塊は、小・中・大のサイズに分ける。金属塊化した際に返却するサイズと個数は金属パーツ定義に持たせ、同じ金属かつ同じサイズの金属塊だけをスタック可能とする。異なる金属または異なるサイズの金属塊はスタックしない。各サイズが表す素材量はデータとして定義する。

### 15.2 クライアント通信と不正操作の検証

クライアントは、打撃、完成、キャンセル、ドラッグ経路などの操作要求だけを送信する。打撃強度、削れた量、素材消費、品質、完成結果はサーバー側で計算して確定し、クライアントから送信された計算結果を使用しない。

鍛造の打撃要求にはセッションID、単調増加する連番、クライアントが観測した同期済みサーバーティックを含める。サーバーは現在ティックから最大4ティックまでの範囲に限ってゲージ位置を遡って評価する。範囲外の時刻はサーバー受信時刻で評価し、未来の時刻、重複した連番、順序が逆転した要求は拒否する。

非金属加工のドラッグ要求には、セッションID、連番、左クリックを押してから離すまで同一となるストロークID、正規化した開始座標と終了座標を含める。クライアントは2ゲームティックに1回以下の頻度で経路を送信する。サーバーは座標が加工領域内であること、1要求の補間結果が64セル以下であること、要求頻度が上限内であることを検証してからセルを更新する。

操作要求の受付時には、少なくとも以下を検証する。

- プレイヤーが対象作業台から8ブロック以内にいる
- 対象GUIと加工セッションが有効である
- 必要な加工用アイテムを使用できる状態である
- セッションの操作権を持つプレイヤーからの要求である
- 完成、キャンセル、素材消費が未処理である

1つの作業台を同時に操作できるプレイヤーは1人とする。他のプレイヤーは、現在の操作セッションが閉じられた後に再開できる。完成とキャンセルは冪等に処理し、同じ要求を再送してもアイテム生成や素材返却が複数回発生しないようにする。

操作権は、GUIを正常に開いた時点で取得するリースとして管理する。1人のプレイヤーが同時に保持できる鍛冶加工セッションは1つまでとし、別の作業台を開く場合は以前の操作権を解放する。

GUIを閉じた場合、プレイヤーが死亡した場合、または作業台から8ブロックを超えて離れた場合は即時に操作権を解放する。通信切断時だけ100ゲームティックの再接続猶予を設け、同じプレイヤーが猶予内に復帰した場合は操作権を再取得できる。猶予を超えた場合は他のプレイヤーへ解放する。

クライアントは操作中、20ゲームティックごとにセッションの生存通知を送る。サーバー再起動時は加工状態を維持する一方、保存されていた操作権とリース期限を無効化し、最初にGUIを開いたプレイヤーが新しい操作権を取得する。

## 16. 実装順序

MVPのリリース対象は全バニラ武器、防具、ツール、および対象MOD連携とする。ただし、実装と検証は以下の順で進める。

1. 登録ID、データコンポーネント、品質計算API、性能補正の基盤
2. 共通設備、加工道具、鋳型のレシピ
3. るつぼ、溶鉱炉、加熱状態の保存
4. 鋳型、鋳造、冷却
5. 鍛造台と鍛造ミニゲーム
6. 非金属加工用作業台と削りミニゲーム
7. 鉄のピッケルを使用した一連の制作フロー
8. 通常レシピ品への固定低品質の付与
9. バニラの対象武器、防具、ツールへの展開
10. L_Ender's Cataclysm連携
11. Twilight Forest連携
12. Alex's Caves連携
13. Roaring連携
14. 全体のバランス調整とサーバー負荷検証

最初に一種類の完成品で、素材投入から品質付き完成品の生成までを縦に完成させる。その後、同じ基盤へレシピとデータを追加して対象を広げる。

## 17. MVP受け入れ条件

MVPは少なくとも以下を満たした場合に完成とする。

- 通常レシピから対象アイテムを作成でき、品質 `30` の低品質品になる
- 鉄インゴット3個から鉄製ピッケルヘッドを作成できる
- るつぼが16インゴット相当まで同じ金属を保持し、異なる金属と容量超過を拒否する
- 手持ちるつぼのGUIからだけ素材を投入でき、加熱後は素材を個別回収できない
- 鉄の加熱時間と鍛造条件をJSONの変更によって調整できる
- 溶鉱炉がGUIを持たず、右クリックだけでるつぼを出し入れできる
- 有効な熱源が真下にある場合だけ溶鉱炉が加熱する
- 搬送機器からるつぼを挿入または取り出せない
- 溶鉱炉から取り出したるつぼの加熱時間が停止し、再投入時に同じ時間から再開する
- 金属を加熱、鋳造、鍛造して品質付き金属パーツを作成できる
- 早すぎる鋳造で、素材の一部を失った金属塊が生成される
- 遅すぎる鋳造で、投入金属が全消失する
- 鍛造の強度と回数によって品質が変化する
- 打撃強度ゲージが3秒で `0` から `100` を往復し、スキル段階によって目盛りだけが細分化される
- 鍛造回数が多すぎる場合に金属塊へ変化する
- 安全冷却時間より早く鋳型から取り出した場合に、破損回数上限が低下する
- 安全冷却時間を超えても追加効果が発生しない
- 表面凝固時には蒸気音と蒸気量の変化が発生し、安全冷却完了時には正解を示す通知が発生しない
- 鋳型を右クリックで設置、鋳造、回収でき、鋳造用作業台の破壊後も加工状態が保持される
- 非金属素材を二次元グリッド上で加工し、形状一致度から品質を決定できる
- supercover lineと面積加重展開により、同じ入力から常に同じ加工グリッドを得る
- 非金属素材を削りすぎた場合に素材が消失する
- 彫刻ナイフの破損、キャンセル、作業台の破壊後も加工途中状態から再開できる
- 固定レシピでパーツを組み立て、パーツ品質の平均を完成品へ設定できる
- `craftbound:quality_assembly` レシピで品質付きパーツを組み立てられる
- 完成品品質に応じて、種別ごとの性能が補正される
- 攻撃力、射撃ダメージ、防御力、防具強度、採掘・作業速度、最大耐久値へ共通倍率を適用できる
- 最大耐久値の変更時に損傷割合が維持され、品質補正が重複適用されない
- 品質付き完成品へバニラのエンチャントと修理を適用できる
- 金床、砥石、鍛冶台、Mendingで定義どおり品質が維持される
- スキル未取得者でも、すべての加工工程とレシピへ挑戦できる
- スキルによって打撃ゲージ、削り幅、グリッド解像度の操作精度が変化する
- 同じ加工結果からは、スキル値にかかわらず同じ品質が算出される
- 鍛造と非金属加工を中断し、保存地点から再開できる
- GUI終了、死亡、距離超過、通信切断、サーバー再起動時に定義どおり操作権が解放される
- 消失リスクが近い場合に、正解値を公開しない警告が表示される
- 音と既存パーティクルまたはGUIの色変化だけで、専用亀裂描画なしでもMVPの危険通知が成立する
- サーバー再起動後も進行中の加工状態と品質が保持される
- データパック再読み込み後も、開始済みの加工が開始時の評価定義で再開される
- 型付きデータコンポーネントを永続化、通信同期、旧形式から移行できる
- 不正なセッション、重複要求、範囲外座標、過剰な入力頻度をサーバーが拒否する
- 同じ完成要求を再送しても、完成品や返却素材が複製されない
- [鍛冶システムテスト仕様](./test-cases.md)のMVPケースを満たす
- [設備・道具・鋳型仕様](./equipment/stations-and-tools.md)の全レシピで設備と道具を入手できる
- [バニラ装備構成仕様](./equipment/vanilla.md)の対象完成品に鍛冶製作または品質継承経路が存在する
- 対象MODごとの連携が、他の連携や鍛冶システム本体から分離されている
- 対象MODが存在しない環境でも、鍛冶システム本体を読み込める

- 彫刻ナイフ以外の非金属加工用アイテムの耐久値と具体的な効果
- ピッケルの柄以外で削りすぎと判定する閾値
- バニラ特殊装備を含む各パーツの個別加工難易度
- 対象MODの導入バージョン、対応装備、ボス素材、ドロップ置き換え、専用鋳型
- 専用のひび・亀裂オーバーレイを低コストで共通実装できるか
- スキルレベルと基本・中位・上位の操作支援段階との対応
- 溶鉱炉から取り出した時点で冷却を開始する、より直感的な状態遷移へ変更するか
- 中・大の金属塊が表す素材量
