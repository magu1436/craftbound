# パーツ原型仕様

## 1. 本書の目的

本書は、MVP対象装備の加工条件を一貫して定義するため、金属パーツの鍛造原型と非金属パーツの共通初期値を定義する。対象パーツと素材量は[バニラ装備構成仕様](./vanilla.md)、素材特性は[鍛冶素材仕様](../materials.md)に従う。

本書の式は初期JSONを作るための生成規則であり、ゲーム実行時に評価しない。生成後の各パーツJSONには、冷却時間、適正強度、適正打撃回数、破損回数を具体値として保存する。

---

## 2. 金属パーツ原型

| 原型ID | 対象例 | 適正強度 | 打撃回数補正 |
|---|---|---:|---:|
| `blade` | 剣身、斧頭、ハサミ刃 | `60～70` | `+3` |
| `heavy_tool` | ピッケルヘッド、重量工具 | `55～65` | `+3` |
| `light_tool` | シャベルヘッド、クワ頭 | `45～55` | `+2` |
| `sheet` | 防具本体、馬鎧本体 | `35～50` | `+4` |
| `small_part` | リング、留め具、打ち金、ブラシヘッド | `50～60` | `+2` |

鉄製ピッケルヘッドは `heavy_tool` の基準例とする。

---

## 3. 金属パーツ初期値の生成

素材量はインゴット相当の整数とする。初期値を以下で生成する。

```text
安全冷却時間 = 40 + 素材量 × 20ティック
表面凝固時間 = floor(安全冷却時間 × 0.4)
適正打撃回数 = 素材量 + 原型の打撃回数補正
通常破損回数 = 適正打撃回数 + 4
```

全原型で以下を共通初期値とする。

| 項目 | 値 |
|---|---:|
| 冷却0時の最小破損回数 | `1` |
| 適正強度から1離れた場合の減点 | `5` |
| 適正回数から1回離れた場合の減点 | `20` |
| 強度評価の重み | `0.8` |
| 回数評価の重み | `0.2` |
| 加熱評価の重み | `0.4` |
| 鍛造評価の重み | `0.6` |

素材量3のピッケルヘッドでは、安全冷却100ティック、表面凝固40ティック、適正打撃6回、通常破損10回となり、鉄のピッケル試作仕様と一致する。

値を調整する場合は対象JSONを直接変更する。生成規則から外れる個別値も許可するが、評価関数IDとJSON形式は変更しない。

## 4. バニラ金属パーツの原型割り当て

| パーツ種別 | 原型 |
|---|---|
| `sword_blade`、`axe_head`、`shears_blades` | `blade` |
| `pickaxe_head` | `heavy_tool` |
| `shovel_head`、`hoe_head` | `light_tool` |
| `helmet_body`、`chestplate_body`、`leggings_body`、`boots_body`、`horse_armor_body` | `sheet` |
| `iron_ring`、`crossbow_trigger`、`shield_boss`、`fire_striker`、`brush_head` | `small_part` |

MOD連携パーツは、形状と用途が最も近い原型を指定する。どの原型にも合わない場合だけ連携側で新しい原型を追加する。

---

## 5. 非金属パーツの初期値

すべての非金属パーツは、素材プロファイルから加工道具、1通過の除去量、耐久消費を取得する。パーツ側は以下を持つ。

- 素材と必要量
- 出力パーツID
- パーツ種別と同じ理想形状ID
- 基本グリッド解像度 `16×16`
- 警告開始残存率 `0.6`
- 消失残存率 `0.5`
- 形状評価関数 `craftbound:iou`

理想形状はゲーム内最大解像度 `32×32` で、パーツ種別ごとに1つ定義する。木、石、宝石など素材が異なっても同じパーツ種別では形状を共有する。

MVP対象の形状IDには少なくとも以下を含める。

| 区分 | 形状ID |
|---|---|
| 武器・ツール | `sword_blade`、`sword_handle`、`pickaxe_head`、`pickaxe_handle`、`axe_head`、`axe_handle`、`shovel_head`、`shovel_handle`、`hoe_head`、`hoe_handle` |
| 防具 | `helmet_body`、`chestplate_body`、`leggings_body`、`boots_body`、`horse_armor_body` |
| 遠距離 | `bow_limb`、`bow_string`、`crossbow_stock`、`crossbow_string` |
| その他 | `shield_frame`、`fishing_rod_body`、`fishing_line`、`mace_head`、`mace_handle`、`trident_head`、`trident_handle`、`turtle_helmet_body`、`wolf_armor_body` |

金属加工と非金属加工の両方で使用するパーツ種別も、同じ形状IDを使用する。金属パーツでは形状マスクを採点に使用せず、鋳型IDと鍛造条件の識別に使用する。

---

## 6. データ生成と検証

組み込みデータの生成処理は、素材、パーツ原型、素材量の表から具体的なパーツJSONを生成する。生成後は通常のデータパックJSONと同じ検証を通す。

データパックから追加するパーツは、原型を参照して実行時に値を補完する方式を採用しない。すべての必須値を持つ完全なJSONとして定義する。

---

## 7. 受け入れ条件

- すべてのMVP対象パーツが原型または個別条件を持つ
- 鉄製ピッケルヘッドの生成値が試作仕様と一致する
- 実行時に生成式を評価せず、具体値をJSONから読み込む
- 同じパーツ種別の理想形状を素材ごとに複製しない
- 各非金属パーツが素材プロファイルを参照する
