# Farmer仕様書

## 1. Farmerの目的

Farmerは、農耕・畜産・酪農・料理を通じて、ワールドにおける食料の生産、保存、加工および供給を担うロールである。

本仕様では、用語を以下のように区別する。

- 食材：農作物、肉、卵、牛乳など、料理の材料となるもの
- 料理：食材を加工して作成した完成品
- 食料：食材と料理の総称

### 1.1 食料と栄養の安定供給

`Diet` MODによって栄養の概念が導入されるため、Farmerには単一の食料を大量生産するだけでなく、複数種類の食材を継続的に供給することが求められる。

### 1.2 食料備蓄の管理

食材と料理には品質が設定され、時間経過によって劣化する。

Farmerは、在庫数、品質、品質低下までの時間および需要を確認し、保存、加工、消費、再生産の優先順位を管理する。

### 1.3 料理による付加価値の付与

Farmerは、食材を料理へ加工することで、満腹度や栄養だけでなく、一定時間の支援効果をプレイヤーへ提供する。

料理は、探索、戦闘、採掘、建築など、他ロールの活動を支える。

## 2. 担当範囲

Farmerは、拠点で継続的に栽培できる植物と繁殖できる動物について、生産、管理および食材への加工を担当する。

初回の栽培素材や野生動物の入手について、Farmerに専用の補正は設定しない。Farmer自身が探索や採集を行うことも制限しない。

ロールの専門性は、作業の禁止ではなく、効率、生産量、品質および専用機能の差によって表現する。ただし、動物の手動繁殖など、本仕様で明示的に無効化するバニラ処理は例外とする。

### 2.1 栽培対象

Farmerの農耕スキルが適用される植物は以下とする。

- 小麦
- ニンジン
- ジャガイモ
- ビートルート
- カボチャ
- スイカ
- サトウキビ
- カカオ
- スイートベリー
- グロウベリー

対象植物について、Farmerは以下を担当する。

- 栽培
- 成長管理
- 収穫
- 再植え付け
- 増産
- 備蓄

ネザーウォートはFarmerの対象外とし、栽培、管理、備蓄および利用をAlchemistが担当する。Farmerの成長時間、収量、品質および肥沃度に関する補正は適用しない。

### 2.2 飼育対象

Farmerの畜産・酪農スキルが適用される動物は以下とする。

- ウシ
- ブタ
- ヒツジ
- ニワトリ
- ウサギ
- ムーシュルーム

対象動物について、Farmerは以下を担当する。

- 給餌
- 成長管理
- 繁殖
- 個体数管理
- 生産物の取得
- 食料生産を目的とした屠畜

野生個体の発見、捕獲、誘導および運搬について、Farmerに専用の補正は設定しない。

### 2.3 生産物

#### 食材

- 農作物
- 生の牛肉
- 生の豚肉
- 生の羊肉
- 生の鶏肉
- 生の兎肉
- 牛乳
- 卵
- キノコシチュー

食材について、Farmerは取得、保存、加工および調理を担当する。

#### 非食料素材

- 羊毛
- 革
- 羽根
- ウサギの皮
- ウサギの足

非食料素材について、Farmerは取得と一次保管までを担当し、その後の加工や利用を対応するロールへ移譲する。

### 2.4 他ロールから必要とするもの

| ロール | Farmerが必要とするもの |
|---|---|
| Explorer | 初回の栽培素材、野生動物、拠点で継続生産できない食材、希少食材 |
| Adventurer | 農業用肥料の材料となる骨 |
| Blacksmith | 鉄以上のクワ、範囲作業に対応した農具、ハサミやバケツなどの畜産用道具、調理器具、金属製加工設備 |
| Architect | 品質劣化を抑える保存容器、専用保管庫、飼料保管用の家具 |
| Alchemist | 現時点でFarmerが必須とする供給物はない |

牧畜ブロックはFarmerのスキルで解放し、Farmerが製作、設置および管理する。

### 2.5 Farmerが他ロールへ移譲するもの

- 革を使用した装備や製品：Blacksmithまたは対応する製作ロール
- 羊毛を使用した建材や装飾品：Architect
- ウサギの足を使用した醸造：Alchemist
- その他の非食料素材：用途に対応するロール

Farmerは、すべてのロールに食料を供給する。

## 3. 各分野のゲームループ

Farmerの基本的な循環は以下とする。

```text
作物と家畜を生産する
→ 食材を取得する
→ 品質と用途に応じて分配する
→ 保存または加工する
→ 料理を作る
→ 他のプレイヤーへ供給する
→ 必要な食材を再生産する
```

### 3.1 品質管理

#### 3.1.1 品質段階

食材、中間加工品および料理には、以下の4段階の品質を設定する。

| 内部値 | ユーザー向け表示名 | 利用 |
|---|---|---|
| 品質3 | 高品質 | 食用・加工可能 |
| 品質2 | 標準品質 | 食用・加工可能 |
| 品質1 | 低品質 | 食用・加工可能 |
| 品質0 | 腐敗 | 食用・加工・給餌不可。堆肥化のみ可能 |

品質0は低品質の食材ではなく、品質を失った腐敗状態として扱う。

品質は、食用または料理材料となるアイテムに設定する。革、羊毛、羽根、肥料、堆肥などの非食料アイテムには設定しない。

ニンジンやジャガイモなど、食材と再植え付け用作物を兼ねるアイテムは品質を持つ。ただし、再植え付け時には品質を参照しない。

#### 3.1.2 品質低下

各スタックは、以下の情報を保持する。

- 現在の品質
- 次に品質が低下する時刻

設定された時間が経過すると品質が1段階低下する。

保存設備は品質低下を完全には停止せず、品質低下までの時間を延長する。

#### 3.1.3 スタックの統合

同じ種類かつ同じ品質のアイテムのみ、同一スタックに統合できる。

統合後の品質低下時刻には、統合前のスタックのうち早い時刻を採用する。

```text
標準品質・残り10分
＋
標準品質・残り30分

↓

標準品質・残り10分
```

品質が異なるアイテムは、通常のインベントリでは別スタックとして扱う。

#### 3.1.4 専用保管庫

品質ごとのスタック分割による操作負担を軽減するため、単一ブロックの専用保管庫と専用UIを追加する。

専用保管庫は、同じアイテムを品質別に内部管理し、UIでは合計数と品質ごとの内訳を表示する。

```text
小麦：合計128個
├ 高品質：32個
├ 標準品質：64個
├ 低品質：32個
└ 腐敗：0個
```

専用保管庫には以下の機能を持たせる。

- 品質を指定して取り出す
- 品質低下までの時間が短いものから取り出す
- 品質ごとの在庫数を確認する
- 通常容器より品質低下を遅らせる

専用保管庫や保存容器の製作はArchitectが担当し、在庫と品質の運用はFarmerが担当する。

### 3.2 農耕

農耕の基本ループは以下とする。

```text
畑を用意する
→ 肥沃度を回復する
→ 作物を植える
→ 成長を待つ
→ 収穫する
→ 保存・加工・飼料・再植え付け・堆肥へ分配する
```

#### 3.2.1 農具

Farmerは、低耐久の木製および石製クワを製作できる。

これらのクワは1マスの耕耘にのみ対応し、範囲機能を持たない。

以下はBlacksmithが担当する。

- 鉄以上の高耐久クワ
- 範囲耕耘
- 範囲植え付け
- 範囲収穫
- 農具の修理と改良

#### 3.2.2 肥沃度と農業用肥料

耕地は水分に加えて肥沃度を持つ。

作物の植え付け時に肥沃度を消費し、必要量を満たさない耕地には植え付けできない。

農業用肥料は、Farmerが骨粉と堆肥から製作する。

```text
骨粉
＋
堆肥
→
農業用肥料
```

骨粉を作物へ直接使用した場合の即時成長効果は無効化する。

堆肥には以下を利用できる。

- 不要な作物
- 余剰の種子
- 植物性の副産物
- 腐敗した食材や料理

#### 3.2.3 植え付けと成長

植え付け時に以下を処理する。

1. 対象が植え付け可能なブロックであることを確認する。
2. 必要な肥沃度を確認し、消費する。
3. 植え付けたプレイヤーのFarmerスキルを参照する。
4. 作物の成熟までの時間を決定して保存する。

基本成長時間はバニラより長く設定する。

Farmerスキルを持たないプレイヤーが植えた場合は、最も長い基本成長時間を使用する。

植え付け後にスキルが変化しても、既に保存された成長時間は変更しない。

#### 3.2.4 範囲植え付け

範囲植え付け機能を持つクワをオフハンドに持ち、メインハンドに植える作物を持った状態で植え付けると、クワの性能に応じて範囲植え付けを行う。

以下を満たす位置だけを対象とする。

- 作物を植えられるブロックである
- 作物が既に植えられていない
- 必要な肥沃度を持つ
- 必要な種または作物を所持している

#### 3.2.5 収穫

成熟した担当作物をプレイヤーが収穫した場合、収穫者のFarmerスキルを参照する。

処理順序は以下とする。

```text
通常の収穫処理
→ 道具などの収穫補正
→ Farmerの追加収穫抽選
→ 各収穫物の品質判定
```

追加収穫は主要生産物のみを対象とし、追加分に道具の補正を再適用しない。

品質判定には、収穫者の品質栽培スキルに対応する確率テーブルを使用する。

範囲収穫は、最終成長段階の作物だけを対象とする。

#### 3.2.6 収穫物の分配

収穫物は以下へ分配する。

- 食料として保存
- 料理や中間素材へ加工
- 家畜の餌
- 再植え付け
- 堆肥化

再植え付けでは品質を参照せず、元の品質を新しい作物へ継承しない。

### 3.3 畜産・酪農

畜産・酪農の基本ループは以下とする。

```text
飼育場所を用意する
→ 牧畜ブロックを設置する
→ 餌を補充する
→ 家畜を成長・繁殖させる
→ 個体数を管理する
→ 生産物を取得する
```

#### 3.3.1 牧畜ブロック

牧畜ブロックは、家畜の給餌、成長、繁殖および個体数管理を行う単一ブロックである。

畜産・酪農スキルツリーの最初のスキル「牧畜管理」で解放する。

牧畜ブロックは1チャンクを基本効果範囲とし、以下の情報を持つ。

- 対象動物
- 使用できる餌
- 餌の残量
- 餌の最大収容量
- 管理可能数
- 現在の管理対象数
- 成体数
- 子どもの数
- 繁殖可能数

#### 3.3.2 給餌と成長

動物が餌を必要とした際、効果範囲内の牧畜ブロックから対応する餌を消費する。

餌を受け取れない子どもの成長は停止する。

餌不足または管理可能数の超過によって、動物を死亡または消滅させることはない。

管理可能数を超えた動物には、以下を適用する。

- 牧畜ブロックから給餌されない
- 子どもの成長が停止する
- 繁殖対象にならない
- 継続的な生産活動を行わない

#### 3.3.3 繁殖

家畜の繁殖は、プレイヤーが対応する繁殖用の餌を成体へ直接与えることで行う。

餌を与えられた動物は、原則としてバニラと同様に繁殖状態へ移行する。ただし、繁殖を成立させるには以下の条件を満たす必要がある。

- 同じ種類の繁殖可能な成体が2体以上いる
- 対象動物が繁殖クールダウン中ではない
- 対象動物が同じ牧畜ブロックの管理範囲内にいる
- 子どもを追加しても牧畜ブロックの管理可能数を超えない

管理可能数に空きがない場合、動物は繁殖状態へ移行せず、繁殖用の餌も消費しない。

条件を満たした2体が繁殖状態になった場合、子どもを1体生成する。

牧畜ブロックは繁殖そのものを自動実行せず、繁殖可能数と管理可能数の判定のみを行う。繁殖に必要な餌は、プレイヤーが動物へ直接与えたものを消費する。

繁殖管理スキルを持つプレイヤーが繁殖を成立させた場合、通常個体の生成後に追加個体抽選を行う。

複数のプレイヤーが繁殖操作を行った場合は、最後に繁殖用の餌を与えて繁殖を成立させたプレイヤーのスキルを参照する。

追加個体を生成すると牧畜ブロックの管理可能数を超える場合、追加個体は生成しない。

#### 3.3.4 屠畜時の追加食料

Farmerが担当動物の最終攻撃者となった場合、食料に限って追加ドロップ抽選を行う。

適用条件は以下とする。

- 対象が成体の担当動物である
- 対象が食料をドロップする
- 最終攻撃者がプレイヤーである
- 最終攻撃者が食肉処理スキルを持つ

プレイヤーが放った矢など、攻撃元のプレイヤーを特定できる間接攻撃も対象とする。

対象食料は以下とする。

- 生の牛肉
- 生の豚肉
- 生の羊肉
- 生の鶏肉
- 生の兎肉

処理順序は以下とする。

```text
通常ドロップ
→ ドロップ増加エンチャントなどの処理
→ Farmerの追加食料抽選
```

Farmerの追加分にはドロップ増加効果を再適用しない。革、羊毛、羽根、ウサギの皮、ウサギの足には適用しない。

| 食肉処理スキル | 効果 |
|---|---|
| I | 20%の確率で1個追加 |
| II | 40%の確率で1個追加 |
| III | 60%の確率で1個追加 |
| IV | 80%の確率で1個追加 |
| V | 1個確定で追加 |

#### 3.3.5 その他の生産物

牛乳、卵、羊毛、キノコシチューなど、動物を倒さずに取得する生産物は、現段階ではバニラの取得方法を維持する。

これらの数量、品質または生産間隔に対する追加補正は、必要になった時点で個別に定義する。

### 3.4 料理

料理の基本ループは以下とする。

```text
食材を選ぶ
→ 必要に応じて加工する
→ レシピと道具を選ぶ
→ 料理を作る
→ 完成品質を決定する
→ 保存・配布する
```

#### 3.4.1 レシピの利用範囲

すべてのプレイヤーは、バニラに存在する料理レシピを利用できる。

Farmerスキルを持たない場合は、以下の制限を受ける。

- 完成品質は使用食材の最低品質をそのまま引き継ぐ
- 完成品質を上昇させる判定を行わない
- MODで追加する中間加工を利用できない
- MODで追加する料理やバフ料理を作成できない

Farmerは料理スキルによって、追加加工、追加レシピ、品質補正およびバフ料理を解放する。

#### 3.4.2 調理道具

Farmerはレシピの選択、食材の加工、調理操作および完成品質の管理を担当する。

包丁、鍋、フライパン、粉砕器、圧搾器などの調理道具や金属製加工設備はBlacksmithが担当する。

複数ブロック構造を前提とする調理施設は採用しない。

#### 3.4.3 完成品質

複数の食材を使用する料理の基準品質は、使用食材のうち最も低い品質とする。

品質調理スキルによって、完成品質を一定確率で1段階上昇させる。判定には、品質調理スキルのランクに対応する確率テーブルを使用する。

品質の違いは、同一レシピ・同一完成アイテムが保持する品質情報として表現する。品質段階ごとに別のレシピや別アイテムを追加しない。

完成品質は、使用した主要食材の最高品質を超えない。

腐敗した食材を含む場合は調理を開始できない。

#### 3.4.4 追加加工とバフ

想定する加工方法は以下とする。

- 切る
- 挽く
- 混ぜる
- 焼く
- 煮る
- 燻製する
- 発酵させる

加工技術スキルによって、加工方法の解放に加えて、加工時間の短縮と中間素材の生産量増加を段階的に行う。

具体的な中間素材、レシピ、必要な道具、加工時間、生産量、バフの種類、強さおよび持続時間は、第7章の方針に基づいて個別に定義する。

料理は、ポーションよりも長時間持続する日常的な支援効果を中心とする。

## 4. Farmer専用能力

ゲームループ内で定義したFarmerの専用能力を、以下に集約する。

### 4.1 初期能力

- 低耐久の木製・石製クワの製作
- 骨粉と堆肥を使用した農業用肥料の製作
- 食材と料理の品質情報の確認
- バニラ料理の作成

バニラ料理の作成自体は全プレイヤーが可能であり、Farmerの専門性は品質補正と追加加工にある。

### 4.2 農耕能力

- 耕地の肥沃度と作物の状態を確認する
- 植え付け時の成長時間を短縮する
- 収穫時に主要生産物を追加する
- 高品質な収穫物の出現率を上げる
- 肥料と堆肥の利用効率を上げる

### 4.3 畜産・酪農能力

- 牧畜ブロックを製作・設定・運用する
- 餌の消費効率を上げる
- 牧畜ブロックの管理可能数を増やす
- 繁殖時の追加個体率を上げる
- 最終攻撃者となった際の食料ドロップを増やす

### 4.4 料理能力

- MOD追加の中間加工を解放する
- MOD追加レシピを解放する
- 完成品質を補正する
- バフ料理を作成する
- 加工時間や中間素材の生産効率を改善する

### 4.5 道具・設備によって利用する機能

以下はFarmer自身の能力ではなく、他ロールから供給される道具または設備の機能である。

- 範囲耕耘・範囲植え付け・範囲収穫：Blacksmith製農具
- 高度な食材加工：Blacksmith製調理道具・加工設備
- 品質劣化の抑制と品質別在庫管理：Architect製保存容器・専用保管庫

### 4.6 Farmerの有無による違い

#### Farmerがいない場合

- 作物栽培は可能だが、成長時間が長い
- 収穫量と収穫品質に補正がない
- 農業用肥料の利用効率を改善できない
- 手動繁殖が無効なため、家畜を継続的に繁殖できない
- 屠畜時の追加食料がない
- バニラ料理は作成できる
- MOD追加加工、追加料理、品質補正およびバフ料理を利用できない

#### Farmerがいる場合

- 同じ農地と資源から、より多く高品質な作物を得られる
- 牧畜ブロックによって家畜を継続的に管理・繁殖できる
- 屠畜時に追加食料を得られる
- 高品質な料理とバフ料理を供給できる
- 食料の生産、保存および消費を一体的に管理できる

## 5. スキルツリー

Farmerは、1つの共通経験値、共通レベルおよび共通スキルポイントを持つ。

スキルツリーは1つのタブ内で、以下の3方向へ分岐する。

```text
                 農耕
                  ↑
                  │
畜産・酪農 ← Farmer基点 → 料理
```

- 分野別経験値や分野別レベルは設けない
- Farmerに関係する作業は、すべて共通のFarmer経験値を付与する
- 共通スキルポイントを3分野の任意のノードへ使用できる
- ノードの取得条件は、原則として前提ノードと必要ポイントとする
- Farmerツリー全体の最大化には大きなコストを要求する
- Farmerへ多く投資するほど、他のスキルツリーへ使用できる成長資源が減少する

### 5.1 経験値の基本方針

経験値は、生産に貢献する処理に対して付与する。

主な対象は以下とする。

- 成熟した作物の収穫
- 農業用肥料の使用
- 堆肥化による資源循環
- 対象動物の屠畜
- 食材の加工
- 料理の完成

未成熟作物の破壊や、設置と破壊の反復など、生産に寄与しない操作には付与しない。

自動処理による経験値の付与条件と、マルチプレイ時の経験値帰属は別章で定義する。

### 5.2 農耕分岐

```text
農地診断
├─ 生育管理 I～V
│  ├─ 収量管理 I～V
│  └─ 品質栽培 I～V
└─ 肥培管理 I～III
```

#### 農地診断

以下を確認できる。

- 現在の肥沃度
- 最大肥沃度
- 植え付け可否
- 作物の成長状態
- 成熟までの残り時間

#### 生育管理 I～V

植え付け時に決定される成長時間を短縮する。

#### 収量管理 I～V

成熟した作物を収穫した際の追加収穫率または追加数を増やす。

#### 品質栽培 I～V

収穫時の品質確率テーブルを改善し、高品質と標準品質の出現率を上げる。

収穫時に腐敗状態を生成することはなく、腐敗は時間経過によってのみ発生する。

#### 肥培管理 I～III

以下を段階的に改善する。

- 肥料による肥沃度回復量
- 植え付け時の肥沃度消費
- 堆肥の生産効率
- 肥沃度消費を軽減する確率

肥沃度消費を完全には無効化しない。

### 5.3 畜産・酪農分岐

```text
牧畜管理
├─ 飼料管理 I～III
│  └─ 飼育容量 I～III
├─ 繁殖管理 I～V
└─ 食肉処理 I～V
```

#### 牧畜管理

畜産・酪農分岐の最初の必須スキルとする。

取得すると以下を解放する。

- 牧畜ブロックの製作
- 設置と設定
- 自動給餌
- 成長管理
- 繁殖
- 個体数管理
- 牧畜ブロックの専用UI

手動繁殖は全プレイヤーで無効であるため、牧畜管理を持つFarmerがいなければ家畜を継続的に繁殖できない。

#### 飼料管理 I～III

牧畜ブロックの餌消費を改善する。

- 餌の消費間隔を延長する
- 一定確率で餌を消費しない
- 1個の餌で対応できる動物数を増やす

餌を完全には不要にしない。

#### 飼育容量 I～III

牧畜ブロックの管理可能数を増やす。

#### 繁殖管理 I～V

牧畜ブロックによる繁殖時の追加個体率を上げる。

#### 食肉処理 I～V

最終攻撃者となった場合の追加食料率を、20%、40%、60%、80%、100%の順に上げる。

### 5.4 料理分岐

```text
基礎加工
├─ 品質調理 I～V
└─ 加工技術 I～III
   └─ レシピ研究 I～V
      └─ 効果料理 I～V
```

#### 基礎加工

MODで追加する中間素材、加工方法および調理設備の利用を解放する。

#### 品質調理 I～V

完成品質を1段階上昇させる確率を増やす。

品質上昇は確率テーブルによる完成時判定として処理し、品質段階ごとのレシピや完成アイテムは追加しない。

#### 加工技術 I～III

以下を段階的に解放または改善する。

- 加工方法
- 加工時間の短縮
- 1回の加工で得られる中間素材の量
- 加工時の品質維持

加工時間と出力量には、7.2の初期推奨値を使用する。

#### レシピ研究 I～V

対応段階の中間素材、一般料理および保存食を解放する。

レシピ研究は、食料の加工、栄養供給および保存を担当する。

#### 効果料理 I～V

対応段階のロール別バフ料理を解放する。

対象系統は以下とする。

- Blacksmith向け
- Explorer向け
- Adventurer向け
- Alchemist向け
- Architect向け

効果料理のランクNを取得するには、レシピ研究のランクNを必要とする。

```text
レシピ研究III
→ 一般料理III・保存食IIIを解放
→ 効果料理IIIを取得可能
→ 各ロール向けバフ料理IIIを解放
```

レシピ研究は「作成可能な食料の拡張」、効果料理は「他ロールを支援するバフ料理の解放」を担当する。

# 7. 料理の詳細方針

本章では、料理分岐について現時点で確定している方針と、未確定の検討事項を整理する。

## 7.1 品質調理

料理の品質は、新しいレシピを解放することで上昇させるのではなく、完成時の品質判定によって決定する。

```text
使用食材の最低品質を基準品質とする
→ 品質調理スキルの確率テーブルを参照する
→ 成功時に完成品質を1段階上昇させる
→ 使用した主要食材の最高品質を上限とする
```

品質調理I～Vでは、品質上昇の成功率のみを改善する。品質段階ごとに以下を追加する必要はない。

- 個別の料理レシピ
- 品質別の完成アイテム
- 品質別の中間素材レシピ

具体的な品質上昇率は9.13の確率テーブルを使用する。

## 7.2 加工技術

加工技術I～IIIでは、追加加工の利用範囲を広げるとともに、加工時間の短縮と、1回の加工で得られる中間素材の量を増加させる。

### 初期推奨値

| ランク | 加工時間 | 中間素材の出力量 | 主な解放 |
|---|---:|---:|---|
| I | 10%短縮 | 基礎出力量 | 切断、粉砕、混合、基本加熱 |
| II | 20%短縮 | 基礎出力量＋1 | 圧搾、乾燥、燻製 |
| III | 30%短縮 | 基礎出力量＋2 | 発酵、高度加熱、高度な品質維持 |

出力量増加は、レシピ側で増産対象に指定した中間素材だけへ適用する。

以下には原則として適用しない。

- 容器や道具などの返却アイテム
- 完成料理
- 保存食
- 希少素材
- 各ロール固有の特殊素材

基礎出力量が1個の中間素材へ増産を適用する場合は、レシピごとに明示的に許可する。

対象となる中間素材の例は以下とする。

- 小麦粉
- 油
- 砂糖
- 切り分けた肉
- 挽肉
- 調味素材
- 乾燥食材
- 発酵食材

一般的な自動調理設備にはプレイヤーのFarmerスキルを継承しないため、自動処理には加工時間短縮および生産量増加を適用しない。

本節の数値は初期プレイテスト用の推奨値とする。

## 7.3 レシピ系統

追加レシピは、保存食と支援対象ロールごとに系統を分け、それぞれレベル1から5まで段階的に解放する。

| レシピ系統 | 段階 | 主な用途 |
|---|---:|---|
| 保存食 | 1～5 | 備蓄、携帯、長期活動 |
| Blacksmith向け料理 | 1～5 | 採掘、精錬、鍛冶作業 |
| Explorer向け料理 | 1～5 | 移動、探索、環境対応 |
| Adventurer向け料理 | 1～5 | 戦闘、回復、遠征 |
| Alchemist向け料理 | 1～5 | 採取、醸造、錬金作業 |
| Architect向け料理 | 1～5 | 跳躍、落下制御、高所建築、短時間の浮遊 |

| II | 屋根職人のスープ | ジャガイモ、ニンジン、牛乳 | 野3・蛋1 | 低速落下・15分 |
| III | 高所作業シチュー | 肉、ジャガイモ、ニンジン、パン | 穀2・野3・蛋3 | 跳躍力上昇II・10分、低速落下・20分 |
| IV | 空中作業食 | 卵、牛乳、パン、ベリー | 穀2・果1・蛋3 | 浮遊I・5秒、低速落下・20分 |
| V | 建築長の宴 | 肉、卵、牛乳、野菜、パン、希少食材 | 穀2・野3・蛋4 | 建築浮遊・30秒、跳躍力上昇II・20分、低速落下・30分 |

バニラの浮遊効果は上昇を止めにくいため、最高段階では上昇と下降を操作できる独自効果「建築浮遊」を推奨する。

最小実装では、短時間の浮遊と低速落下の組み合わせへ置き換えてもよい。

本節の料理名、材料、栄養値および効果値は初期プレイテスト用の推奨案とする。

## 7.4 レシピ研究と効果料理の関係

役割を以下のように分ける。

| 要素 | 役割 |
|---|---|
| レシピ研究 | 対応段階の中間素材、一般料理および保存食を作成可能にする |
| 効果料理 | 対応段階の各ロール向けバフ料理を作成可能にする |

効果料理のランクNは、同じランクのレシピ研究を前提とする。

レシピ研究だけを伸ばしたFarmerは、食料の加工、栄養供給および保存を得意とする。

効果料理まで伸ばしたFarmerは、他ロールの作業を支援する専門料理を供給できる。

料理の効果強度は、原則として料理レベル、レシピ内容および完成品質によって決定する。

## 7.5 現時点の未確定事項

料理分野では、以下を別途定義する。

- Diet MODとの具体的な連携方法
- 暫定栄養ポイントをDiet側の実値へ変換する方法
- 各レシピの最終的な必要数と完成数
- 「鍛冶集中」「錬金集中」「建築浮遊」の具体的な処理
- 希少食材と調味素材の具体的な入手経路
- プレイテスト後のバランス調整

以下は本章で決定済みとする。

- 中間素材は1回の加工で得られる量を増加させる
- レシピ研究と効果料理の役割分担
- Architect向け料理を独立系統として追加する
- バフの重複と上書き規則

加工時間、出力量、レシピ、栄養値および効果値は初期推奨案として定義し、プレイテスト後に確定する。

# 8. システム上の判定と時間経過

## 8.1 スキル参照の基本原則

各処理では、その行為を実行したプレイヤー、Entityまたはブロックを処理主体として扱う。

処理主体がプレイヤーである場合は、そのプレイヤーのFarmerスキルを参照する。

処理主体がプレイヤー以外である場合は、原則としてFarmerスキルを持たない状態として処理する。

対象例は以下とする。

|処理|スキル参照対象|
|---|---|
|プレイヤーによる植え付け|植え付けたプレイヤー|
|村人による植え付け|スキルなし|
|ディスペンサーなどによる植え付け|スキルなし|
|プレイヤーによる収穫|収穫したプレイヤー|
|水流、ピストン、村人などによる収穫|スキルなし|
|プレイヤーによる繁殖|繁殖を成立させたプレイヤー|
|プレイヤーによる屠畜|最終攻撃者|
|自動処理設備による屠畜|スキルなし|
|プレイヤーによる料理|調理を実行したプレイヤー|
|自動調理設備による料理|スキルなし|

スキルなしの処理では、Farmerスキルを取得していないプレイヤーと同じ基礎値を使用する。

## 8.2 自動処理

自動化そのものは原則として禁止しない。

ただし、一般的な自動装置にはプレイヤーのFarmerスキルを継承しない。

### 自動植え付け

自動植え付けでは、以下を適用する。

- 最も長い基礎成長時間を使用する
    
- 植え付け時のFarmer成長補正を適用しない
    
- 必要な肥沃度は通常どおり消費する
    
- Farmer経験値を付与しない
    

### 自動収穫

水流、ピストン、村人、その他の自動装置による収穫では、以下を適用する。

- Farmerの追加収穫判定を行わない
    
- スキルなし用の品質確率テーブルを使用する
    
- Farmer経験値を付与しない
    

### 自動屠畜

最終攻撃者がプレイヤーとして特定できない場合、Farmerの追加食料抽選を行わない。

プレイヤーが放った矢など、攻撃元のプレイヤーを特定できる攻撃は、そのプレイヤーによる処理として扱う。

### 自動調理

自動調理設備を追加する場合は、以下を適用する。

- Farmerの品質上昇判定を行わない
- MOD追加レシピのスキル条件を満たさない
- 加工技術による加工時間短縮を適用しない
- 加工技術による中間素材の出力量増加を適用しない
- Farmer経験値を付与しない
- 使用食材の最低品質を、そのまま完成品質として使用する

## 8.3 Farmer専用ブロック

牧畜ブロックや専用保管庫など、Farmerスキルと関連する専用ブロックには所有者を設定しない.

牧畜ブロックが保持する主な性能値は以下とする。

- 餌消費効率
    
- 管理可能数
    
- 繁殖に関する補正
    

一般的なホッパー、ディスペンサー、ピストンなどには、この仕組みを適用しない。

## 8.4 ブロックの所有と共有

ブロック共有機能は設けない。

所有者以外のプレイヤーには、原則として以下の操作を許可しない。

- 専用UIを開く
    
- 設定を変更する
    
- 管理対象を変更する
    
- 内部在庫を直接操作する
    

ブロックの破壊や持ち去りについては、専用の保護機能を設けない。

敵対関係や拠点への侵入による略奪は、ワールド内の通常の行動として許容する。

## 8.5 繁殖時のプレイヤー判定

家畜の繁殖は、プレイヤーが対応する餌を直接与えることで行う。

複数のプレイヤーが同じ繁殖処理に関与した場合は、繁殖を成立させる最後の餌を与えたプレイヤーのスキルを参照する。

```text
1人目が最初の成体へ餌を与える
→ 2人目がもう一方の成体へ餌を与える
→ 繁殖成立
→ 2人目の繁殖管理スキルを参照
```

この方式により、繁殖成立時の処理主体を一人に確定する。

プレイヤー以外の物体が繁殖を成立させた場合は、スキルなしとして扱い、追加個体抽選を行わない。

## 8.6 時間経過

作物成長、品質低下、家畜成長、餌消費および繁殖クールダウンは、対象が存在するチャンクが読み込まれている間のみ進行する。

### チャンクが読み込まれている場合

以下の時間を通常どおり進行させる。

- 作物の成長時間
    
- 食材と料理の品質低下時間
    
- 家畜の成長時間
    
- 牧畜ブロックの給餌間隔
    
- 繁殖クールダウン
    
- 調理や加工の進行時間
    

### チャンクが読み込まれていない場合

対象の時間処理を停止する。

チャンクを再読み込みした際に、未読み込み期間をまとめて加算する処理は行わない。

### サーバー停止中

すべての時間処理を停止する。

サーバー再起動時に、停止していた実時間を加算しない。

### プレイヤーのインベントリ

プレイヤーがオンラインである間は、インベントリ内の食材と料理の品質時間を進行させる。

プレイヤーがオフラインである間は進行させない。

## 8.7 アイテムEntity

地面に落ちているアイテムEntityには、品質低下処理を適用しない。

地面に存在する間は、品質と品質低下までの残り時間を維持する。

ただし、バニラのアイテム消滅処理は通常どおり適用する。

## 8.8 保存場所の変更

食材や料理を別の保存場所へ移動した場合は、移動前までに経過した時間を反映した後、新しい保存場所の倍率を適用する。

```text
通常チェストで経過した時間を反映
→ 現在の品質と残り時間を確定
→ 専用保存容器へ移動
→ 専用保存容器の保存倍率を適用
```

保存場所を移動することで、既に経過した時間を取り消すことはできない。

品質を持つアイテムを、用途に応じて以下の3種類へ分類する。

|分類|主な役割|栄養|バフ|保存期間|
|---|---|---|---|---|
|材料|保存食と料理の材料|原則なし|なし|長い|

## 9.11 品質維持時間

品質ごとの基礎維持時間は以下とする。

各時間を経過するごとに、品質が1段階低下する。

|分類|高品質から標準品質|標準品質から低品質|低品質から腐敗|高品質から腐敗まで|
|---|--:|--:|--:|--:|
|料理|20分|20分|20分|60分|
|材料|120分|120分|120分|6時間|
|保存食|240分|240分|240分|12時間|

これらの時間は、対象が読み込まれている間のみ進行する。

料理の品質維持時間は短いが、料理によるバフは比較的長時間持続する。

## 9.12 保存設備

保存設備の倍率は以下を初期値とする。

| 保存場所 | 品質維持時間倍率 |
|---|---:|
| プレイヤーのインベントリ | 1.0倍 |
| 通常のチェスト・樽 | 1.0倍 |
| Architect製の専用保管庫 | 2.0倍 |
| Architect製の保存容器 | 3.0倍 |

通常チェストと樽は品質管理に関するバフ効果を持たない。

保存設備は品質を回復させず、保存開始時点の残り時間に倍率を適用する。

### 専用保管庫の初期推奨容量

| 項目 | 初期推奨値 |
|---|---:|
| 登録可能なアイテム種類 | 27種類 |
| 1種類あたりの最大保管数 | 品質合計256個 |
| 最大理論保管数 | 6,912個 |
| 初期取り出し順 | 品質低下までの残り時間が短い順 |

1種類あたりの256個は、高品質、標準品質、低品質および腐敗の合計とする。

### ホッパー連携の初期推奨仕様

- 上面と側面から搬入できる
- 下面から搬出できる
- 搬出時は品質低下までの残り時間が短い食料を優先する
- 腐敗物も通常どおり搬出できる
- 異なる品質や効果情報を誤って統合しない
- 初期実装ではGUIによる自動搬出フィルターを設けない
- 保存容器は手動利用を基本とし、初期実装ではホッパー連携を行わない

### 通常チェスト・樽の品質処理

通常チェストと樽には保存倍率を与えないが、内部の品質時間は進行させる。

初期実装では以下を推奨する。

- 搬入、搬出、分割、統合およびUI表示時に品質を遅延計算する
- 品質を持つ食料が入っている読み込み済みコンテナだけを処理対象として登録する
- 登録済みコンテナは200tick、約10秒ごとに品質を更新する
- 全チェストを定期的に検索しない
- 1サーバーtickで最大32コンテナを処理し、超過分は次tickへ繰り越す
- 1コンテナ内では最大54スロットを処理対象とする

処理周期と性能上限は負荷試験後に調整する。

## 9.13 料理品質

料理の基準品質は、使用食材の最低品質とする。

品質調理スキルは、完成時に品質を1段階上昇させる抽選を行う。

|スキル|品質上昇率|
|---|--:|
|スキルなし|0%|
|品質調理I|10%|
|品質調理II|20%|
|品質調理III|30%|
|品質調理IV|40%|
|品質調理V|50%|

完成品質は、使用した主要食材の最高品質を超えない。

## 9.14 料理のバフ時間と重複規則

料理の具体的な効果は7.3の初期案を基準とし、完成品質によって持続時間を補正する。

| 完成品質 | 基礎バフ時間の倍率 |
|---|---:|
| 高品質 | 1.5倍 |
| 標準品質 | 1.0倍 |
| 低品質 | 0.67倍 |
| 腐敗 | 使用不可 |

標準品質の一般的な作業支援料理は、基礎バフ時間30分を目安とする。

再生、耐性、攻撃力上昇および浮遊など影響が大きい効果は、料理全体の基準時間より短く個別設定する。

### バフの重複と上書き

- 現在発動中の効果と同じ効果IDを持つ料理を食べた場合、新しい料理の効果レベルと効果時間で置き換える
- 同じ効果の時間を加算しない
- 異なる効果IDは同時に発動できる
- 新規追加の独自バフも、異なる効果IDであれば既存効果と併存する
- 1つの料理が複数効果を持つ場合は、それぞれを独立して処理する
- 品質による時間倍率は、上書きに使用する新しい効果時間へ適用する

## 9.15 Farmer経験値

Farmerは共通経験値を使用する。

初期テストでは、作業ごとの基礎経験値を以下とする。

|作業|Farmer経験値|
|---|--:|
|成熟作物を1株収穫|1|
|農業用肥料を1回使用|2|
|堆肥を1個完成|1|
|家畜へ繁殖用の餌を与えて繁殖成立|5|
|子どもの家畜が成体になる|3|
|担当動物を屠畜する|2|
|中間素材を1回加工|1|
|保存食を1個完成|2|
|料理を1個完成|3|
|バフ料理を1個完成|5|

自動処理によって発生した作業には、経験値を付与しない。

同一操作の短時間反復による経験値取得については、必要に応じてクールダウンまたは上限を設定する。

# 10. UI

UIは、プレイヤーが現在の状態と次に必要な行動を確認できることを目的とする。

色だけに依存せず、名称、数値、アイコンおよびゲージを組み合わせて表示する。

## 10.1 食材と料理のツールチップ

品質を持つアイテムには、以下を表示する。

```text
分類：料理
品質：高品質
品質低下まで：18分32秒
腐敗まで：約58分
```

料理には追加で以下を表示する。

```text
栄養：穀物・野菜・たんぱく質
効果：採掘速度上昇
持続時間：45分
```

材料には、直接使用しても栄養やバフを得られないことを表示する。

```text
分類：材料
直接使用効果：なし
用途：料理・保存食の材料
```

## 10.2 品質表示

品質は以下の名称で統一する。

- 高品質
    
- 標準品質
    
- 低品質
    
- 腐敗
    

品質名の横にアイコンまたは段階表示を追加する。

例：

```text
高品質　◆◆◆
標準品質　◆◆
低品質　◆
腐敗　×
```

## 10.3 耕地UI

農地診断スキルを持つプレイヤーが耕地または作物を確認した場合、以下を表示する。

```text
肥沃度：64 / 100
植え付け可能：はい
作物：小麦
成長状態：第4段階
成熟まで：約22分
植え付け時の成長補正：24%
```

表示方法は、画面中央の簡易情報、ブロックツールチップまたは専用オーバーレイとする。

常時表示ではなく、農具を持っている場合や特定キーを押している場合だけ表示する。

## 10.4 専用保管庫UI

専用保管庫では、アイテムを種類ごとにまとめ、品質別に内部管理する。

表示項目は以下とする。

- アイテム名
    
- 合計数
    
- 品質別の個数
    
- 最も早い品質低下までの時間
    
- 保存倍率
    
- 最大容量
    

表示例：

```text
小麦　合計128
高品質　32
標準品質　64
低品質　32
腐敗　0

最短品質低下：12分
保存倍率：2.0倍
```

### 操作

- 品質を指定して取り出す
    
- 古いものから取り出す
    
- 新しいものから取り出す
    
- 腐敗したものだけ取り出す
    
- アイテム名で検索する
    
- 分類で絞り込む
    
- 品質で絞り込む
    

初期設定では、品質低下までの時間が短いものから優先して取り出す。

## 10.5 牧畜ブロックUI

牧畜ブロックには以下を表示する。

```text
対象動物：ウシ
餌：小麦
餌の残量：48 / 64
管理数：7 / 12
成体：5
子ども：2
繁殖可能：2
次の給餌判定：約4分
```

### 警告表示

以下の場合は警告を表示する。

- 餌が少ない
    
- 餌がない
    
- 管理可能数に達している
    
- 管理可能数を超えている
    
- 子どもの成長が停止している
    
- 繁殖可能な空きがない
    
- 対応していない動物が範囲内にいる
    
## 10.6 繁殖時の表示

繁殖を成立させる餌を与えた際に、以下を短時間表示する。

```text
繁殖成立
追加個体率：30%
管理可能数：9 / 12
```

追加個体が生成された場合は、その結果を表示する。

```text
繁殖管理が発動しました
子どもが1体追加されました
```

管理可能数が不足している場合は、餌を消費せず、理由を表示する。

```text
繁殖できません
牧畜ブロックの管理可能数が不足しています
```

## 10.7 調理UI

調理UIには以下を表示する。

- レシピ名
    
- 必要な食材
    
- 使用する食材の品質
    
- 基準完成品質
    
- 品質上昇率
    
- 予想される栄養
    
- 予想されるバフ
    
- バフ時間
    
- 品質低下までの時間
    
- 調理時間
    

表示例：

```text
料理：野菜と肉の煮込み

最低食材品質：標準品質
完成基準品質：標準品質
品質上昇率：30%

栄養：野菜・たんぱく質
効果：最大体力上昇
標準持続時間：30分
品質維持時間：20分
```

腐敗した食材が含まれている場合は、調理開始ボタンを無効化し、対象食材を表示する。

## 10.8 FarmerスキルツリーUI

Farmerツリーは、中央から3方向へ伸びる構造とする。

```text
                 農耕
                  ↑
                  │
畜産・酪農 ← Farmer基点 → 料理
```

画面上部または中央には以下を表示する。

- Farmerレベル
    
- 現在経験値
    
- 次のレベルまでの経験値
    
- 使用可能なスキルポイント
    
- Farmerツリー全体への投資ポイント
    

各ノードには以下を表示する。

- スキル名
    
- 現在ランク
    
- 最大ランク
    
- 必要ポイント
    
- 前提ノード
    
- 現在の効果
    
- 次ランクの効果
    

例：

```text
生育管理III

現在効果：作物の成長時間を24%短縮
次ランク：32%短縮
必要ポイント：1
前提：生育管理III取得済み
```

## 10.9 経験値表示

Farmer経験値を取得した際は、取得理由を簡潔に表示できるようにする。

```text
Farmer経験値 +3
料理を完成しました
```

経験値表示は設定で非表示にできるものとする。

自動処理によって経験値が発生しない場合は、通常はメッセージを表示しない。

## 10.10 UIの優先順位

初期実装では、以下の順序でUIを作成する。

1. 食材と料理の品質ツールチップ
    
2. 専用保管庫UI
    
3. 牧畜ブロックUI
    
4. FarmerスキルツリーUI
    
5. 耕地と作物の診断表示
    
6. 調理UI
    
7. 経験値取得表示
    

料理レシピとバフが未確定であるため、調理UIの最終設計は料理仕様の確定後に行う。

# 11. 実装条件と設定方針

## 11.1 開発環境

| 項目 | 内容 |
|---|---|
| Minecraft | 1.20.1 |
| Modローダー | Minecraft Forge |
| Java | 64ビット版JDK 17 |
| マッピング | Mojang公式マッピング（official） |
| Diet MOD | Minecraft 1.20.1対応版 |
| Diet連携 | 詳細を別章で定義する |

Minecraft 1.20.1のForge開発では、プロジェクトのビルド、実行およびCIをJava 17へ固定する。

「最新版Java」ではなくJDK 17を使用する。

## 11.2 マッピング

マッピングは、配布版Minecraftの読みづらいクラス名、メソッド名およびフィールド名を、開発時に読みやすい名前へ対応づける仕組みである。

```text
配布版の読みづらい名前
→ マッピングを適用
→ Block、ItemStack、Playerなどの名前で開発
→ ビルド時に配布環境向けへ変換
```

初期構成ではMojang公式マッピングを採用する。

```gradle
minecraft {
    mappings channel: 'official', version: '1.20.1'
}
```

Parchmentは公式マッピングへ引数名や説明を補う選択肢であるが、初期実装では導入しない。

## 11.3 Diet MODとの連携

対象はMinecraft 1.20.1対応版Diet MODとする。

具体的なAPI、データパック、タグまたは設定ファイルによる連携方法は、料理と栄養の連携仕様で別途定義する。

連携方法を確定するまでは、7.3.1の暫定栄養ポイントを使用する。

## 11.4 設定変更

最小構成では、Forge Config、外部TOML設定および設定画面を追加しない。

- レシピ、栄養ポイントおよび効果定義はMOD内のJSONへ記述する
- 成長時間、確率、容量および処理周期はJava定数または内部データファイルへ記述する
- 値を変更した場合は、必要に応じてMODを再ビルドする
- 実装が安定した後に、サーバー管理者向けコンフィグの追加を再検討する

## 11.5 確定事項と初期推奨案

### 確定事項

- Minecraft 1.20.1を対象とする
- ModローダーはMinecraft Forgeとする
- JDK 17を使用する
- Diet MODはMinecraft 1.20.1対応版を対象とする
- Diet連携の詳細は別章で定義する
- 中間素材の増産は、1回の加工で得られる個数を増やす
- Architect向け料理に、跳躍、低速落下および浮遊系の効果を設定する
- 同じバフは新しい効果時間とレベルで上書きする
- 異なるバフは同時に発動できる
- 通常チェストと樽は品質維持へのバフを持たない
- 最小構成では外部コンフィグを追加しない

### 初期プレイテスト用の推奨案

- Mojang公式マッピングを使用する
- 加工時間を10%、20%、30%の順に短縮する
- 中間素材の出力量を基礎、＋1、＋2の順に増やす
- 7.3のレシピ、栄養値およびバフ値を使用する
- 専用保管庫を27種類、1種類あたり256個とする
- 専用保管庫をホッパー搬入・搬出へ対応させる
- 通常コンテナの品質更新を約10秒周期で分散処理する

推奨案はゲーム内テストとサーバー負荷試験によって変更できる。
