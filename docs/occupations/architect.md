# 建築家（Architect）仕様

## 1. 文書情報

| 項目 | 内容 |
|---|---|
| 対象環境 | Minecraft Forge 1.20.1 |
| スキル管理 | Pufferfish's Skills 0.18.1 |
| 文書状態 | MVP実装仕様 |
| 対象 | サーバー・クライアント双方で動作するMOD |

本書は、建築家スキルツリーのゲーム仕様と実装上の契約を定義する。数値は初期調整値であり、プレイテストで変更できるよう、処理へ直接埋め込まず一か所で管理する。

---

## 2. 役割

建築家は、他のプレイヤーから建築や改修、解体を請け負い、対価を得る生活職である。

建築物の自動生成や設計そのものを代行する職業ではなく、次の作業を効率化する。

- 足場を使った現場内の移動
- 遠い位置へのブロック設置
- プレイヤーが設置したブロックの解体
- 高所作業中の落下事故への耐性
- エリトラを使った空中施工の継続

採掘職が自然地形や鉱石の採掘を得意とするのに対し、建築家はプレイヤーが作った構造物の施工・改修・解体を得意とする。

## 3. 設計原則

- すべての効果を常時判定型のパッシブスキルとし、専用キー操作を要求するアクティブアビリティは追加しない。
- スキル未取得者も、通常の建築、解体、エリトラ飛行を行える。
- WorldEditのような一括設置、自動建築、設計図、ゴースト表示はMVPに含めない。
- スキルはブロックや花火などの通常コストを原則として維持し、明記された確率効果だけが消費を軽減する。
- 土地保護、スポーン保護、イベントのキャンセル、アドベンチャーモードなどによる既存の操作制限を無視しない。
- ゲーム結果を決める判定、乱数、永続データの更新は論理サーバーを正とする。
- 他MODとの組み合わせで効果が重複した場合は、特記がない限り乗算する。

---

## 4. スキル構成

MVPでは5系統、各5ランクの合計25ランクを実装する。プレイヤーが細かな進捗を継続的に感じられるよう、1ランクをPufferfish's Skills上の1ノードとして表現する。

表内の数値は、そのランク取得時の差分ではなく累計効果である。ランク0は未取得を表す。

| ID | 表示名 | 主な効果 | ランク数 |
|---|---|---|---:|
| `scaffolding_mobility` | 足場移動 | 足場上の移動速度を上げる | 5 |
| `placement_reach` | 設置距離 | ブロック設置だけの到達距離を伸ばす | 5 |
| `demolition` | 解体作業 | プレイヤー設置ブロックの破壊速度を上げる | 5 |
| `fall_protection` | 落下耐性 | 落下ダメージを軽減する | 5 |
| `firework_conservation` | 飛行技術 | エリトラ飛行用花火を確率で消費しない | 5 |

### 4.1 ツリーの前提関係

MVPでは次の前提関係を採用する。

```text
足場移動 I ──→ 足場移動 II～V
     └──────→ 落下耐性 I～V

設置距離 I ──→ 設置距離 II～V
     └──────→ 解体作業 I～V

落下耐性 III ──→ 飛行技術 I～V
```

飛行技術は、花火節約だけを目的とした低コスト取得を避けるため、落下耐性IIIを前提とする。他の系統内では、一つ前のランクを次ランクの前提とする。

前提関係と取得コストはバランス項目であり、効果処理のコードから分離してPufferfish's Skills側の定義で管理する。

## 5. 足場移動

### 5.1 効果値

| ランク | 移動速度倍率 |
|---:|---:|
| 0 | 1.00 |
| 1 | 1.10 |
| 2 | 1.20 |
| 3 | 1.30 |
| 4 | 1.40 |
| 5 | 1.50 |

### 5.2 発動条件

次の条件をすべて満たす間だけ発動する。

- プレイヤーがサバイバルまたはアドベンチャーモードである。
- プレイヤーの足元、脚部、または直下にある移動を支えるブロックが `minecraft:scaffolding` である。
- プレイヤーがエリトラ飛行中、騎乗中、泳ぎ中ではない。

### 5.3 効果範囲

- 足場上の水平方向の移動に倍率を適用する。
- 足場内でジャンプにより上昇するとき、およびスニークにより下降するときの垂直移動にも同じ倍率を適用する。
- ノックバック、落下速度、外部から与えられた速度には適用しない。
- 速度上限はバニラの足場操作を維持できる値へクランプし、1 tickの補正だけで目的の高さを大きく通り過ぎないようにする。

### 5.4 実装上の注意

単純な移動速度Attributeだけでは足場内の昇降へ同じように作用しない可能性がある。そのため、水平移動と足場固有の垂直移動を分けて扱ってよい。クライアント表示とサーバー位置が継続的にずれないことを必須とする。

## 6. 設置距離

### 6.1 効果値

| ランク | 追加距離（ブロック） |
|---:|---:|
| 0 | 0.00 |
| 1 | 0.25 |
| 2 | 0.50 |
| 3 | 0.75 |
| 4 | 1.00 |
| 5 | 1.50 |

### 6.2 対象操作

追加距離は、`BlockItem`等を使用してブロックを設置する操作だけに適用する。

次の操作には適用しない。

- ブロックの破壊距離
- Mobや他プレイヤーへの攻撃距離
- エンティティとのインタラクション距離
- チェスト、ドア、レバー、作業台等の既設ブロックの使用距離
- 液体の取得・設置など、ブロック設置以外のアイテム使用

### 6.3 判定

- クライアントは、通常距離にランク別追加距離を加えた範囲で、設置対象面を選択できる。
- サーバーは受信した設置要求について、プレイヤーの目の位置から対象までの距離、視線、チャンクのロード状態、通常の設置可否を再検証する。
- サーバーが認識するスキルランク以上の距離は許可しない。
- 遠距離設置であっても、アイテム消費、衝突、置換可否、土地保護等は通常の設置と同じとする。

### 6.4 実装方針

Forgeの一般的なブロック到達距離を恒常的に増加させるだけの実装は、破壊や既設ブロックの使用距離まで広げる可能性があるため採用しない。設置操作だけを拡張できるクライアント側の照準処理と、サーバー側の検証を組み合わせる。

設置だけへの限定が技術的に安全に実現できない場合は、MVPから本スキルを一時的に外す。破壊距離や攻撃距離も同時に伸ばすフォールバックは採用しない。

## 7. 解体作業

### 7.1 効果値

| ランク | 破壊速度倍率 |
|---:|---:|
| 0 | 1.00 |
| 1 | 1.15 |
| 2 | 1.30 |
| 3 | 1.50 |
| 4 | 1.75 |
| 5 | 2.00 |

### 7.2 発動条件

次の条件をすべて満たす場合、通常計算後の破壊速度へランク別倍率を乗算する。

- 対象座標が「プレイヤー設置ブロック」として記録されている。
- 破壊者が解体作業を1ランク以上取得している。
- 対象が `craftbound:architect_demolition_blacklist` ブロックタグに含まれない。
- 対象ブロックが破壊不能ではない。
- メインハンドの道具が対象に対して通常より有効で、必要な採掘レベルを満たしている。
- プレイヤーが通常のルール上、そのブロックを破壊できる。

「道具が有効」の実装判定では、少なくとも対象BlockStateに対する道具の破壊速度が素手相当より大きいことと、正しい道具がドロップ条件となるブロックではその条件を満たすことを確認する。

### 7.3 効果外の項目

解体作業は次の値を変更しない。

- アイテムドロップと経験値
- Fortune、Silk Touch等のエンチャント
- 道具の耐久消費
- 爆発耐性
- 破壊権限
- 自然生成ブロックの採掘速度

### 7.4 プレイヤー設置ブロックの定義

プレイヤー本人が通常の設置操作を行い、設置イベントが成立した座標をプレイヤー設置ブロックとする。設置者のUUIDは保存しない。誰が置いたブロックであっても、建築家の解体作業の対象となる。

次はMVPではプレイヤー設置として扱わない。

- ワールド生成時に生成されたブロック
- 構造物、村、ダンジョンを構成するブロック
- コマンド、ストラクチャーブロック、WorldEdit等が直接設置したブロック
- Create等の機械やFakePlayerが設置したブロック
- Mobが設置または移動したブロック
- ピストンで移動した後のブロック

### 7.5 永続データ

チャンクごとにプレイヤー設置座標の集合を保持する。通常ブロックをBlock Entity化したり、各ブロックへNBTを付与したりしない。

初期実装の論理モデルは次のとおりとする。

```java
interface PlayerPlacedBlockData {
    boolean contains(BlockPos pos);
    void add(BlockPos pos);
    void remove(BlockPos pos);
}
```

保存先には `LevelChunk` へ付与したForge Capabilityを使用する。実装内の集合はプリミティブ型のlong集合を使用し、MVPでは `BlockPos#asLong()` 相当の値を保存してよい。データ量が問題になった場合は、チャンク内座標へ圧縮したint集合へ移行する。

Capabilityの状態を変更したときは、対象チャンクを必ずdirtyとしてマークする。NBTにはデータ形式のバージョンを持たせ、将来の圧縮形式への移行を可能にする。

概念上の保存形式：

```text
{
  Version: 1,
  Positions: [L; ...]
}
```

### 7.6 データ更新

| 契機 | 処理 |
|---|---|
| プレイヤーによる単一ブロック設置 | 設置成立後に対象座標を追加 |
| ドア、ベッド等の複数ブロック設置 | 成立した全座標を追加 |
| プレイヤーによる破壊 | 破壊がキャンセルされなかった場合に座標を削除 |
| 爆発 | 実際に破壊対象となった座標を削除 |
| 照会時に対象が空気 | 不整合データとして座標を削除し、効果を適用しない |

Forge 1.20.1では、設置候補として `BlockEvent.EntityPlaceEvent` と `BlockEvent.EntityMultiPlaceEvent`、破壊速度補正として `PlayerEvent.BreakSpeed`、通常破壊の削除として `BlockEvent.BreakEvent` を使用する。複数設置イベントは全ての置換スナップショットを処理し、集合への追加は冪等にする。

### 7.7 MVPで保証しない整合性

火災、流体更新、植物の成長、エンダーマン、ピストン、他MODの独自一括操作など、Forgeの共通イベントだけで完全に追跡できない変更については完全な整合性を保証しない。

- ブロックがピストンで移動した場合、移動先へプレイヤー設置状態を引き継がない。
- 不整合を検出した座標は遅延削除してよい。
- このデータは土地所有権や荒らし対策には使用しない。
- 運営中に不整合率や保存件数を計測し、必要な変更原因だけを追加対応する。

## 8. 落下耐性

### 8.1 効果値

| ランク | 落下ダメージ軽減率 |
|---:|---:|
| 0 | 0% |
| 1 | 10% |
| 2 | 20% |
| 3 | 30% |
| 4 | 40% |
| 5 | 50% |

### 8.2 判定

- 原因が通常の落下ダメージである場合だけ適用する。
- 軽減率を、通常の落下ダメージ計算に対する乗算補正として適用する。
- Feather Falling、Resistance、装備、他MODの軽減がある場合、それらを無効化せず共存させる。
- 最大ランクでも落下ダメージを完全には無効化しない。
- クリエイティブおよびスペクテイターモードでは追加処理を行わない。

### 8.3 将来拡張

MVPには含めないが、足場の近くで作業している場合だけ追加軽減を与えるスキルを追加候補とする。

候補仕様：落下開始地点または着地点から一定距離内に足場が存在する場合、通常の落下耐性に追加の軽減率を乗算する。常時効果へ置き換えるか、別の上位ノードとするかは未決定とする。

## 9. 飛行技術（エリトラ花火節約）

### 9.1 効果値

| ランク | 非消費確率 |
|---:|---:|
| 0 | 0% |
| 1 | 5% |
| 2 | 10% |
| 3 | 15% |
| 4 | 20% |
| 5 | 25% |

### 9.2 発動条件

次の条件をすべて満たす花火使用だけを対象とする。

- プレイヤーが実際にエリトラ飛行中である。
- 使用アイテムがバニラの `minecraft:firework_rocket` である。
- 花火がエリトラ加速用として正常に生成される。
- プレイヤーがサバイバルまたはアドベンチャーモードである。
- 飛行技術を1ランク以上取得している。

クロスボウから発射した花火、地面やブロックに対して使用した花火、ディスペンサーが発射した花火には適用しない。

### 9.3 消費処理

- 条件を満たした使用1回につき、論理サーバーで1回だけ乱数判定する。
- 成功した場合、その使用で消費される花火1個だけを消費しない。
- 花火の飛行時間、加速、速度、軌道、ダメージ、NBTは変更しない。
- 使用自体がキャンセルされた場合や、花火Entityの生成に失敗した場合は非消費判定を成立させない。
- クリエイティブモードでは元から消費されないため、スキル判定や払い戻しを行わない。
- 非消費を払い戻しとして実装する場合、元のItemStackと同じNBTを持つ花火を同じ手へ戻す。手が別アイテムで埋まった場合はインベントリへ戻し、複製や消失が起きないようにする。

乱数判定の結果は永続化しない。演出の追加はMVPでは不要とする。

## 10. スキル連携

### 10.1 ランク取得

各プレイヤーのランクはPufferfish's Skillsを正とする。効果実装側はPufferfish's Skillsの内部データを各所から直接参照せず、次のようなMOD内サービスを介して取得する。

```java
interface ArchitectSkillService {
    int scaffoldingMobilityRank(Player player);
    int placementReachRank(Player player);
    int demolitionRank(Player player);
    int fallProtectionRank(Player player);
    int fireworkConservationRank(Player player);
}
```

- 戻り値は0から5へクランプする。
- スキル定義が欠落している場合はランク0として安全に処理し、ログへ警告を出す。
- クライアント側の照準処理に必要な設置距離ランクだけは同期する。クライアントから申告されたランクをゲーム結果の根拠にしない。
- スキルID、前提ノード、取得コスト、表示テキストはデータ定義へ置き、Javaコードへ重複させない。

### 10.2 数値設定

効果値はランクを添字とする配列または同等の構造で一元管理する。

```text
scaffolding_multipliers = [1.00, 1.10, 1.20, 1.30, 1.40, 1.50]
placement_reach_bonus   = [0.00, 0.25, 0.50, 0.75, 1.00, 1.50]
demolition_multipliers  = [1.00, 1.15, 1.30, 1.50, 1.75, 2.00]
fall_damage_reduction   = [0.00, 0.08, 0.16, 0.25, 0.35, 0.50]
firework_save_chance    = [0.00, 0.05, 0.10, 0.15, 0.20, 0.25]
```

設定値の検証に失敗した場合は起動時に明確なエラーを出す。配列長不足を実行中の例外やランク5の無効果として放置しない。

## 11. 互換性と権限

### 11.1 土地保護

建築家スキルは、破壊・設置イベントのキャンセルを解除しない。土地保護MODが最終的な破壊を拒否した場合、解体速度が上がっていてもブロックは破壊されないことを必須とする。

土地保護MODによっては破壊途中のひび表示が通常より速く見える可能性がある。この表示差はMVPでは許容するが、実際の破壊やドロップが発生してはならない。

### 11.2 他MODのブロック

解体作業は他MODのブロックも原則対象とする。ただし、機械、壊すことで状態を失う設備、特殊な破壊処理を持つブロックは、データパックから `craftbound:architect_demolition_blacklist` へ追加できるようにする。

初期ブラックリストには、少なくとも次を含めるか導入MODごとに検討する。

- 管理用・保護用ブロック
- 破壊不能ブロック
- 通常の採掘速度変更を前提としない特殊ブロック

### 11.3 専用サーバー

全機能を専用サーバーでテストする。クライアント専用クラスを共通コードから参照せず、設置距離の照準処理だけをクライアント専用の実装へ分離する。

## 12. 受け入れ基準

### 12.1 共通

- ランク0ではバニラと同じ結果になる。
- ランク1から5まで、表示された累計値と実際の効果が一致する。
- 死亡、再ログイン、ディメンション移動、サーバー再起動後もスキル効果が正しく復元される。
- クライアントが改変されたランクや距離を送信しても、サーバー側上限を超えた効果を得られない。

### 12.2 足場移動

- 足場上だけで水平・上昇・下降速度がランクに応じて上がる。
- 足場から離れたtickで補正が残らない。
- 落下、ノックバック、エリトラ飛行へ倍率が流用されない。
- 高遅延環境でも継続的な位置巻き戻りが起きない。

### 12.3 設置距離

- 最大ランクで通常距離外かつ追加1.5ブロック以内の位置へ設置できる。
- 同じ位置にある既設ブロックを通常距離外から使用・破壊できない。
- サーバー上のランクを偽装して追加距離を超えられない。
- アイテム消費、衝突判定、土地保護が通常設置と同じように機能する。

### 12.4 解体作業

- プレイヤーが設置した対象ブロックだけに速度倍率が適用される。
- 別プレイヤーが設置したブロックも対象になる。
- 同種の自然生成ブロックには適用されない。
- 不適正な道具、素手、ブラックリスト対象には適用されない。
- ドアやベッドの全構成座標が記録される。
- 通常破壊と爆発後に記録が削除される。
- チャンクのアンロード、ワールド保存、サーバー再起動後も記録が維持される。
- 保護されたブロックを破壊できない。

### 12.5 落下耐性

- 落下ダメージだけが指定率で減少する。
- 奈落、炎、窒息、Mob攻撃等のダメージは減少しない。
- Feather Falling等と併用でき、最大ランクでも通常条件下で落下ダメージが完全無効にならない。

### 12.6 飛行技術

- エリトラ飛行中の手持ち花火だけが判定対象になる。
- 成功時にも花火Entityと加速は通常どおり発生する。
- 1回の成功で2個以上増えない。
- クロスボウ、ディスペンサー、地上使用では節約されない。
- 大量試行時の非消費率が設定値へ統計的に収束する。

## 13. 計測とログ

バランス調整と保存方式の判断に使用するため、開発環境または任意で有効化できるデバッグ計測として次を用意する。

- チャンクごとのプレイヤー設置座標数
- ワールド全体の記録座標数
- 解体作業の発動回数
- 花火の使用回数と非消費回数
- 不整合な設置座標を遅延削除した回数

通常運用時にブロック単位でログを出力してはならない。集計値を管理コマンドまたはデバッグログから確認できればよい。

## 14. MVP対象外

- 建築依頼書、報酬のエスクロー、納期、進捗率等の契約システム
- 建築物の機械的な品質判定
- 設計図、距離測定、円・対称ガイド、ゴーストプレビュー
- 一括設置、一括置換、一括解体
- 資材バッグやインベントリからの自動補充
- 建築専用のアクティブアビリティ
- 設置者UUIDの保存
- WorldEditや全機械MODとの完全な設置履歴連携
- ピストン移動時の設置履歴追従
- 足場付近での条件付き追加落下耐性

## 15. 確定事項と調整方針

MVP実装では次を確定事項とする。

- 5系統のスキルを各5ランク、合計25ノードで構成する。
- 本書に記載した各ランクの効果値を初期値として使用する。
- 飛行技術Iの取得には落下耐性IIIを必要とする。
- Pufferfish's Skills 0.18.1と連携する。
- 足場移動は水平、上昇、下降へ同じ倍率を使用する。
- FakePlayerや機械による設置をプレイヤー設置として記録しない。
- 非プレイヤー原因による履歴削除は、MVPでは爆発と照会時の空気検出を保証範囲とする。

各ノードの取得コストは、3か月の運営期間で2～3個のスキルツリーを極められるという全職業共通の進行設計に合わせ、Pufferfish's Skills側で調整する。導入MOD固有の解体ブラックリストは、導入MOD構成が確定した時点でデータパックへ追加する。
