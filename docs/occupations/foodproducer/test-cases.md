# 食料生産者（FoodProducer）テスト・受け入れ基準

## 1. この文書の役割

この文書は、FoodProducerの機能別受け入れ基準、手動テスト状況、MVP統合テストおよび回帰テストを管理する。ゲーム上の期待結果は[ゲーム仕様](foodproducer.md)を正本とし、テスト結果から仕様を無断で変更しない。

## 2. 状態表記

| 状態 | 意味 |
|---|---|
| 合格 | 期待結果をゲーム内で確認済み |
| 部分合格 | 主要結果は確認したが長時間・数値・再起動などが未確認 |
| 未実施 | 実装済みだがゲーム内確認前 |
| 延期 | MVP後または他職業統合時に確認 |
| 不合格 | 再現可能な不具合があり修正が必要 |

## 4. 現在の最小テスト

### 牧畜MVP再検証（M系列、5段階）

既存のM系列は破棄せず、第2段階で発見した距離順再選択の問題を記録したうえで、確定した安定登録仕様へ改訂して継続する。

| 段階 | 確認内容 | 状態 |
|---|---|---|
| M-01 | 対象設定、餌制限、初回給餌、基本UI | 改訂後の回帰確認に合格 |
| M-02 | 基礎容量8体の安定登録、移動による入れ替わり禁止、オーバーフロー無給餌 | 改訂後の手動確認に合格 |
| M-03 | 範囲外で即時停止、29秒以内の復帰、30秒経過後の解除・補充、戻った旧個体のオーバーフロー化 | 手動確認に合格。600 tick境界は自動テストでも確認 |
| M-04 | 登録個体とオーバーフロー個体の子ども成長、手動繁殖、容量判定、経験値 | 手動確認に合格 |
| M-05 | セーブ・再起動、死亡、対象変更、ブロック破壊、容量更新、重複範囲での単一登録 | 手動確認に合格 |

M-02の旧実測は「餌16個を投入すると8個を即時消費し、約3秒後に9体目も給餌されて7個となった」である。原因は、毎回の距離順再選択により管理対象が入れ替わったことだった。これは改訂前実装の記録として残し、改訂後は登録済み8体が範囲内を移動しても9体目を登録・給餌しないことを合格条件とする。

改訂後のM系列では、M-02から確定した安定登録仕様をM-03以降へ引き継いだ。M-05完了後にM-01も回帰確認し、飼料管理0%かつ給餌期限へ到達した登録個体8体に対して、小麦16個が8個、次の同時給餌で0個になることを確認した。これにより、個体ごとの次回給餌時刻を保持して重複消費を防ぎながら、期限到達時には管理個体数に応じて消費することを確認済みとする。

手動確認では、牧畜UIの「飼料管理」「飼育容量」を実効果の「餌を消費しない確率」「登録できる最大数」へ変更し、範囲表示と餌表示の重なりを解消した後、表示崩れがないことも確認した。

### 地域食材MVP再検証（AD系列、5段階）

| 段階 | 確認内容 | 状態 |
|---|---|---|
| AD-01 | 11種類の登録、データ定義、対象バイオームおよびTier対応 | 手動確認に合格 |
| AD-02 | 新規チャンクの対象バイオームにおける地表自然生成 | 自然生成に合格。生成密度は暫定値 |
| AD-03 | 実プレイヤーの右クリック収穫、2～4個、標準品質および二重収穫防止 | 手動確認に合格 |
| AD-04 | 48,000 tick再生、チャンク再読込およびセーブ再起動 | 短縮予約の保存修正後、手動確認に合格 |
| AD-05 | 通常破壊、ドロップ・移植・骨粉・自動収穫禁止および料理Tier利用 | 手動確認に合格 |

群内の配置は全種類共通で最大6回試行する。生成確率は初期実装値をMVP確定値とせず、5章の統合テストで複数シードの実測結果を記録してから調整する。

洞窟内部に採集源が存在しないことを手動探索で網羅的に証明することはAD-02の合格条件に含めない。洞窟または地下で自然生成を発見した場合だけ不合格として記録し、地表限定のデータ定義は自動テストで検証する。

初期実装の生成密度である対象バイオーム4チャンクに約1群では、平原とタイガで10秒の探索につき4群、湿地で6群、桜の林で3群、樹氷で7群を確認し、供給量が多すぎると判断した。統合テスト候補を全Tier共通で16チャンクに約1群へ変更し、同じ測定方法と複数シードで再評価する。群内配置は最大6回のまま変更しない。

AD-05では、通常破壊、シルクタッチ、移植および骨粉禁止に加え、Tier II食材ではTier I料理を開始できず、自然採集したTier I食材では調理前素材セットと料理が完成することを確認した。Createのデプロイヤーでは成熟状態と所持数が変化せず、その後に実プレイヤーが同じ採集源を2～4個収穫できることを確認し、自動収穫禁止を合格とした。

### DI-01 Diet値

1. Diet導入環境で材料から保存食を作る。
2. 食べる前後の穀物、野菜、果物、タンパク質、糖類を確認する。
3. 材料由来カテゴリだけが設定倍率と上限内で増えることを確認する。

### DI-02 職業料理の排他

1. 固有効果を持つ職業料理を食べる。
2. 同じ料理を再度食べ、効果時間が更新されることを確認する。
3. 効果中に別の職業料理を使用し、消費されず拒否されることを確認する。
4. 牛乳で解除した後、別の職業料理を食べられることを確認する。

### DI-03 Dietなし起動

1. Dietを外した構成でゲームを起動する。
2. ワールドを読み込み、保存食と職業料理を使用する。
3. Diet関連クラッシュがなく、品質、満腹度、隠し満腹度、効果が機能することを確認する。

### 2026-08-16 実施記録

- DI-01は、手動加工とCreate開始経路の材料由来値、保存食1.25倍、職業料理0.85倍、同一カテゴリ上限25%、品質非依存を確認して合格。
- DI-02は、同一料理の効果時間更新、別料理の消費拒否、拒否表示、牛乳解除および固有効果未実装料理が排他対象外であることを確認して合格。拒否時に食事動作が先行する表示問題は修正後に再確認済み。
- DI-03は、Dietなしでの起動、ワールド読込、保存食と職業料理の使用、Dietコマンドが登録されないこと、Dietあり構成への復帰を確認して合格。
- Diet連携のサーバー設定を無効化した場合、料理は機能したままDiet値が増加しないことを確認済み。
- 自動テス66件、Dietあり・なしのjar生成、言語JSONおよびDietの任意依存定義を確認済み。

## 5. MVP統合テスト

テスト用コマンドやクリエイティブ取得を使わず、新規ワールドの通常サバイバルで次を一連の流れとして確認する。

1. FoodProducerスキルを取得し、簡易料理包丁、調理台、手回しミル、乾燥器、調理鍋を揃える。
2. 耕地を作り、施肥、植え付け、成長、収穫、品質確認を行う。
3. 牧畜ブロックを作り、動物設定、給餌、繁殖、子どもの成長を行う。
4. 収穫物と畜産物を加工し、保存食と職業料理を完成させる。
5. 保存設備I・IIへ移し、品質時計、搬入出、再起動後の在庫を確認する。
6. 手動加工とCreate自動加工を比較し、生産量・品質・必要設備の役割差を確認する。
7. 地域食材を探索して料理へ使用し、発見距離、収穫量、再生時間を記録する。自然生成については複数シードで、対象バイオームの確認チャンク数、発見した群数、1群の実株数、採集源が生成されなかった対象バイオーム、および最初の群までの移動距離を記録する。群内配置は最大6回の共通値を維持し、生成確率はTier別に変えず、この実測結果から全Tier共通値として調整の要否を判断する。
8. Diet導入時と未導入時の両方で食事を確認する。

### 5.1 スキル進行の測定

最大レベル50、全50ノードの必要ポイント1、経験値曲線`10 + 現在レベル × 5`、累計必要経験値6,625をマルチ統合テストの初期値とする。測定ではテスト用コマンドおよびクリエイティブ取得を使用しない。

想定条件は参加者約10人、各プレイヤー1日1時間・週7時間、約3か月、職業の担当制なしとする。経験値は該当行為を行った本人が取得し、FoodProducer以外の職業も同じプレイヤーが進行できる前提とする。

各プレイ記録では次を残す。

- プレイヤー、測定開始・終了時刻、全プレイ時間、およびFoodProducer行為へ実際に費やした時間
- 開始時と終了時のFoodProducer経験値、レベル、使用済み・未使用スキルポイント
- 農耕、畜産、加工・料理に分けた対象行為の回数、獲得経験値および経験値毎時
- 最初の分岐、2つ目の分岐、全50ノードを取得した時点、または各時点までの推定時間
- 実測した総経験値毎時から算出した、累計6,625へ到達する推定FoodProducer行為時間

FoodProducer行為をしていない移動、建築、他職業作業および離席時間は、FoodProducer行為時間へ含めない。全取得の比較基準はFoodProducerへ集中して行動した実時間30～45時間とするが、単独の厳密な合否条件にはせず、他職業の実測結果と併せて判断する。大量の成熟作物収穫だけで進行全体が極端に短縮されないこと、および畜産や加工・料理を中心に遊ぶプレイヤーも有用な速度で進行できることを重点的に確認する。

少なくとも次のコストを記録する。

- 設備一式を揃えるまでのゲーム内日数、鉄、木材、糸、燃料などの総量
- スキル取得に要した時間とポイント
- 牧畜ブロックを利用開始するまでの素材負担
- 保存設備Iの3倍保存を得る時期と、保存設備IIの5倍保存へ更新する負担
- 肥料など継続消費品の供給量
- 農耕、畜産、加工、保存、料理を並行した場合の移動・待ち時間・総資源量

コストの高低だけでは不合格にしない。進行不能、需要消失、無限増殖または極端な負担がある場合だけMVP前の調整対象とする。

## 6. 回帰テスト

- 新規ワールドと既存ワールドの両方を読み込める。
- セーブ・終了・再起動・再ログインで品質、肥沃度、牧畜、設備在庫、処理途中データが維持される。
- シングルプレイと専用サーバーで同じサーバー側結果になる。
- FoodProducerのItemをスタック、分割、チェスト移動しても消失・複製しない。
- Dietの導入・未導入、Create連携の許可・拒否操作、Pufferfish's Skillsによる取得・リセットでクラッシュしない。
- 他職業のAttribute、スキル、設備およびデータへFoodProducerが意図しない変更を加えない。

## 7. MVP完了条件

1. DI系列が合格する。
2. 5章の統合テストで進行不能、データ消失、無限増殖および致命的な負担がない。
3. 6章の回帰テストが合格する。
4. 初期値の調整結果をゲーム仕様または判断台帳へ反映する。
5. 未合格項目をMVP後へ送る場合、判断台帳へ理由と代替動作を記録する。
