# 食料生産者（FoodProducer）判断台帳

## 1. この文書の役割

この文書は、確定ゲーム仕様へ混ぜない初期値、未決定事項、外部職業待ちおよびMVP後の候補を管理する。ゲーム内で現在採用する挙動と数値は[ゲーム仕様](foodproducer.md)、アセット固有の契約は[アセット仕様](assets.md)、検証状況は[テスト・受け入れ基準](test-cases.md)を参照する。

## 2. 状態区分

| 区分 | 意味 | 扱い |
|---|---|---|
| 確定 | 方向性とゲーム上の結果を採用済み | ゲーム仕様またはアセット仕様を変更しない限り維持 |
| 初期値 | 現在の実装で使用するプレイテスト用数値 | 統合テスト後に同じ方向性の範囲で調整可能 |
| 要決定 | 複数案で結果または実装範囲が変わる | 決定者と期限を明記 |
| 外部待ち | 他職業側の定義が正本となる | FoodProducer単体MVPを止めない |
| MVP後 | 初期プレイに不要な拡張 | MVP受け入れ基準へ含めない |

## 3. 確定済みの設計判断

- FoodProducer文書は専用フォルダで管理し、ゲーム仕様、アセット、判断事項、テストを分離する。
- FoodProducerだけを整理対象とし、他職業の仕様書は変更しない。
- 設備7種類を立方体または専用立体モデルのどちらで表現するかはアセット実装者へ委任する。新しいゲーム状態は追加しない。
- 職業料理は対象職業ごとに外見を分け、同じ職業のランクI～Vは共通外見とする。
- 保存食I～Vは保存食用の共通外見とする。
- 地域食材11種類の採集源は、成熟・収穫済みとも平面の`cross`モデルとする。
- Craftbound専用GUI背景画像はMVPへ含めない。実装済みの機能GUIを使用し、専用背景画像の制作はMVP後に扱う。
- 専用スキルアイコンはMVPへ含めない。MVPでは現在のItemアイコンを使用し、専用アイコンの制作はMVP後に扱う。
- テスト結果と一時的な作業状況はゲーム仕様へ記載しない。

## 4. 現在の初期値

次は仕様欠落ではなく、ゲーム仕様に現在値を持つ調整対象である。

| 領域 | 初期値として扱う内容 | 正式化の判断材料 |
|---|---|---|
| スキル・成長 | 最大レベル50、全50ノードの必要ポイント1、1レベルごとに1ポイント、経験値曲線`10 + 現在レベル × 5`、レベル50までの累計6,625、行動経験値 | 約10人・1人週7時間・約3か月のマルチプレイで、FoodProducerを実際に行う時間、分岐別経験値効率、全取得までの推定時間を測定 |
| 農耕 | 品質抽選、成長時間、収量、肥沃度回復量 | 序盤の食料供給と肥料維持費 |
| 畜産 | 管理範囲、容量、範囲外の登録保持30秒、給餌間隔、繁殖率、成長時間 | 長時間運用、個体の入れ替えやすさとサーバー負荷 |
| 品質・保存 | 品質維持時間、食事補正、保存倍率 | 備蓄量と腐敗頻度 |
| 設備・消耗品 | 設備、包丁、肥料、牧畜ブロック、保存設備のレシピコスト | MVP統合テストの総コスト |
| 包丁 | 簡易料理包丁の耐久64、鍛冶師製料理包丁の耐久512、MVPで修理不可 | 加工回数と交換頻度 |
| 料理 | 中間素材、保存食5種類、職業料理25種類の材料数と完成数 | FoodProducerへの需要と供給負担 |
| 食事性能 | 満腹度、隠し満腹度、Diet補正、職業料理の効果値と時間 | 実戦・遠征・日常食での使用率 |
| Create | 保存食Iまでの自動化範囲と低品質固定 | 手動生産との役割差 |
| 地域食材 | Tier、バイオーム、密度、収穫量、再生時間、品質時計 | 複数シードでの探索距離と供給量 |
| UI | 情報密度、失敗理由の位置、設備別レイアウト | 文字の重なりと操作理解 |

スキル・成長の初期値は、単に機能テストを短縮するための値ではなく、マルチ統合テストへ持ち込む仮決定とする。参加者は約10人、各プレイヤーの平均プレイ時間は1日1時間・週7時間、運用期間は約3か月を想定する。担当制は設けず、各プレイヤーが自分で行った農耕、畜産、加工・料理によってFoodProducer経験値を得て、他職業を含むすべてのスキルを取得可能とする。

3か月で各プレイヤーが2～3職業を最大まで進められる全体目標から、FoodProducerへ集中して行動した実時間30～45時間を全取得時間の比較基準とする。この範囲は統合テスト前の厳密な合否値ではなく、実測した農耕、畜産、加工・料理それぞれの経験値毎時、スキル取得時期および他職業との規模差から調整要否を判断するための基準である。

## 5. 要決定事項

FoodProducer単体MVPを開始する前に決定が必要な項目は、現時点ではない。外部職業側の確定を待つ内容は6章、MVP後に検討する内容は7章で管理する。

完成料理には、製造時点の満腹度、隠し満腹度、効果、Diet値などをNBTへ保存する。そのため、後からデータパックのレシピ定義を変更しても、変更前に製造済みの料理は製造時の性能を維持し、変更後に製造した料理から新性能になる。この挙動をMVPの確定仕様とし、開発中に性能を変更した場合は旧テスト料理を作り直す。既存料理を新性能へ移行する仕組みが必要になった場合だけ、MVP後のデータ移行として別途検討する。

Diet連携と職業料理1種類制限は現在方式を採用する前提でゲーム内テストを行う。テスト失敗は未決定事項ではなく不具合または初期値調整として扱う。

Alchemist Vの仮レシピは3材料制限に合わせて砂糖を一時的に省いている。Alchemist側との正式レシピ相談時に材料構成を決定する。

## 6. 外部職業待ち

- Blacksmith向け職業料理は、Blacksmith側の正式Attribute定義後にバニラ効果と強めのAttribute補正を設定する。
- Alchemist向け職業料理は、Alchemist側の効果体系確定後に同じ方針で設定する。
- 鍛冶師製料理包丁の素材とクラフトレシピはBlacksmith側が決定する。FoodProducer側は使用回数と加工時の扱いを担当する。
- 状態効果を持つバニラ食品と怪しげなシチューはAlchemistの担当とし、FoodProducerの品質補正対象にしない。

## 7. MVP後の候補

- 料理ミニゲーム
- 保存設備の整理、検索、品質フィルター、腐敗品抽出
- Create自動化の保存食II以降への段階的拡張

- Craftbound専用GUI背景画像

## 8. 料理ミニゲームの将来候補

### 8.1 基本方針

本節の詳細設計はMVP後に再検討する将来候補であり、現在の実装要件ではない。MVPでは手動・自動を問わず料理操作評価を`成功`に固定し、ミニゲーム入力、採点、専用UIおよび操作評価による品質補正を行わない。以下は将来導入する場合の参考設計として保持する。

- ミニゲームは任意参加とし、開始時にスキップできる。
- スキップした場合は`成功`評価として扱う。
- 失敗しても材料を失わず、処理自体は通常どおり完了する。
- ミニゲームの失敗だけを理由に完成品の基準品質を低下させない。
- ホッパー、Createまたは処理主体不明の自動開始ではミニゲームを行わず、操作評価を`成功`として出力へ記録する。
- 自動開始された最終加熱は、操作評価にかかわらず品質上昇抽選と経験値の対象外とする。
- サーバー側を判定の正とし、クライアントからは操作時刻または操作内容だけを送信する。

ミニゲームの素点は0～100とし、次の4段階へ変換する。

| 素点 | 操作評価 | 内部値 |
|---:|---|---:|
| 0～39 | 失敗 | 0 |
| 40～69 | 成功 | 1 |
| 70～89 | 上出来 | 2 |
| 90～100 | 完璧 | 3 |

`加工技術 I～III`を持つプレイヤーが切断、粉砕、保存加工または混合のミニゲームを行った場合、判定前の素点へランクごとに5点を加算する。

| 加工技術 | 素点補正 |
|---|---:|
| スキルなし | 0 |
| I | +5 |
| II | +10 |
| III | +15 |

100を超える分は切り捨てる。最終加熱ではこの素点補正を適用せず、`品質調理`の基礎品質上昇確率によって成長効果を表現する。

### 8.2 工程別ミニゲーム

| 工程 | ミニゲーム | 初期操作 | 採点基準 |
|---|---|---|---|
| 切断 | 連続タイミング | 左右に動く指標を指定位置で3回決定する | 3回の停止位置と目標中央との差を平均する |
| 粉砕 | 力の維持 | 操作ボタンの長押しと解放で5秒間ゲージを適正範囲へ保つ | 適正範囲内にいた時間割合を使用する |
| 保存加工 | 取り出しタイミング | 状態が`乾燥不足→適正→乾燥しすぎ`と進む中で取り出す | 適正範囲の中央に近いほど高得点とする |
| 混合 | 順番入力 | 画面に示された3入力を順番に行う | 正しい入力数と完了までの時間を使用する |
| 加熱 | 温度管理 | 火力を上げる・下げる操作で8秒間適温を維持する | 適温範囲内にいた時間割合を使用する |

入力はマウスまたはキーボードの双方へ割り当てられるようにし、キー設定から変更可能とする。

保存加工でプレイヤーが操作せず適正範囲を通過した場合は、適正範囲終了時に自動的に処理を完了し、`成功`評価とする。乾燥しすぎによって材料消失や腐敗を発生させない。

### 8.3 操作評価の継承

ミニゲーム評価は品質そのものではなく、`料理操作評価`として加工後の中間素材へ保持する。

- 未加工の材料は料理操作評価を持たず、継承計算では無視する。
- 加工済み入力が料理操作評価を持たない場合は`成功`として扱う。
- 複数の加工済み入力を使用する場合は、それらの内部値の平均を入力評価とする。
- 出力評価は、入力評価と今回の工程評価の平均を四捨五入して0～3へ収める。
- 評価を持つ加工済み入力が存在しない場合は、今回の工程評価をそのまま出力評価とする。
- 調理前素材セットは完成予定レシピID、基準品質、品質上限、Diet値に加えて料理操作評価を保持する。
- 同一アイテムでも料理操作評価が異なる場合は通常スタックへ統合しない。

```text
入力評価が存在する場合：
出力評価
=
round（（入力評価の平均＋今回評価）÷2）

入力評価が存在しない場合：
出力評価
=
今回評価
```

### 8.4 品質上昇確率への補正

将来ミニゲームを導入する場合、最終加熱工程では加熱ミニゲームを含めて算出した出力評価を品質上昇確率へ反映する。MVPでは`成功`固定のため補正は0ポイントである。

| 最終料理操作評価 | 品質上昇確率補正 |
|---|---:|
| 失敗 | -20ポイント |
| 成功 | 0ポイント |
| 上出来 | +20ポイント |
| 完璧 | +40ポイント |

例として、`品質調理 III`の基礎確率30%では次となる。

| 操作評価 | 最終確率 |
|---|---:|
| 失敗 | 10% |
| 成功 | 30% |
| 上出来 | 50% |
| 完璧 | 70% |

料理操作評価は品質上昇確率だけへ影響し、品質上昇に失敗した場合も基準完成品質で完成する。
